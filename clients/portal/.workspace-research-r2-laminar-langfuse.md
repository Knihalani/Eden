## Verdict

Steal **two complementary org grammars**, not one clone:

| Peer | Container model | Settings surface | What Eden should take |
|------|-----------------|------------------|------------------------|
| **Laminar** | Workspace ⊃ Project; settings **unified** under project shell | One `/settings?tab=` — **project tabs first**, then workspace (team / usage / billing) | Collapse dual rails; daily vs Advanced; keys + seats as unblock paths; personal→team seat jump |
| **Langfuse** | **Org → Project**; settings **by level + topic** | Org settings (members, SCIM, org API keys) vs Project settings (scores, LLM connections, project API keys) | Explicit level split in mental model; invite-by-email + pending; role-gated config; region/compliance at entry |

Eden already names the container **Workspace** (not “org” in chrome). Map Laminar’s “workspace” ≈ Eden Workspace; map Langfuse’s “organization” ≈ Eden Workspace; map both peers’ **project** ≈ Eden’s data/product scope (agents / env) — do **not** invent a third nested admin shell.

**DESIGN.md lock-in:** Settings ≤8 visible tabs default; **no double sidebar**; 28–32px controls; one primary CTA; kit `Button` / DangerZone only (`DESIGN.md` §3, §4, §10 P2).

## 1. Container hierarchy

### Laminar — Workspace ⊃ Project (settings merged)

From R2 + [PR #1918](https://github.com/lmnr-ai/lmnr/pull/1918):

- **Single settings URL:** `/project/{id}/settings?tab=…` inside the project layout.  
- **Sidebar order:** project settings **first**, then workspace sections (usage, team, billing…).  
- Standalone `/workspace/{id}` and separate workspace settings shell **deleted** → redirect shims only.  
- Settings is **item 11 in the main project nav** (not footer-only). Footer = account / logout / upgrade.  
- Cannot delete the **last project** in a workspace (UI + server guard).  
- Creating a workspace requires an **initial project name**; land in traces (product), not an empty admin page.  
- Project picker: swipe panes for workspaces/projects + create dialogs + account menu.

**Eden steal:** One Settings hub under Workspace IA; **no** nested 240px settings rail (matches checklist **M12** / DESIGN.md P2). Prefer overview landing that answers “who / plan / keys / members” then `?tab=` leaves (**M11**).

### Langfuse — Organization → Project (settings by level)

From R3 + [Organizations changelog](https://langfuse.com/changelog/2024-08-13-organizations) + [RBAC](https://langfuse.com/docs/administration/rbac):

```
User ──role──► Organization ──1:n──► Projects ──n:1──► API Keys (project)
                     │
                     └── Org API keys / SCIM (admin plane)
```

- Start page: **all orgs + projects**.  
- **Project selector** to jump without leaving product context.  
- Settings **organized by level** (org vs project) **and topic**.  
- Project transfer into another org = centralize membership; **API keys stay on the project**.  
- Roles: Owner / Admin / Member / Viewer / None (None = org shell without default project access).  
- Viewer: most **configuration hidden** — not shown as disabled spam.

**Eden steal:** Keep a **single Workspace** container in chrome, but mentally split tabs into:

| Level | Eden daily leaves | Peer analogue |
|-------|-------------------|---------------|
| Workspace (team) | overview, members, security, billing, SCIM (Advanced/team-only) | Langfuse Org Settings; Laminar workspace tabs |
| Workspace (me) | account | Laminar account menu / footer |
| Data / integrations | api-keys; Advanced: gateway, PII, retention, exports, DLQ | Laminar project API keys; Langfuse Project Settings + data plane |

Personal orgs: hide invites / SCIM / ownership chrome (**M5**, **M13**) — Laminar Free’s **1 seat / 1 project** (`lmnr-pricing-scroll0.png`) is the right empty-state story: upgrade unlocks team, don’t fake team UI.

## 2. Settings IA patterns to steal

### A. Unified page + `?tab=` (Laminar) — beat Eden’s double rail

| Pattern | Laminar | Eden today (R1/R6) | Steal |
|---------|---------|-------------------|-------|
| Surface | One settings page; project sidebar stays | Portal sidebar **+** ~240px settings rail + ~21 tabs | **Kill second rail**; hub + category pills + Advanced (**M2**, **M12**) |
| Order | Project → Workspace | Flat mega-list (Org…Advanced) | Daily first (≤6): overview, account, api-keys, members, security, billing; rest Advanced |
| Deep links | `?tab=` + redirect shims for legacy workspace URLs | Dual FS stubs + `?tab=` | Preserve `?tab=`; stubs = redirects only (**M9**, checklist S14) |
| Ghosts | Feature-flag / omit unfinished | Soft-hidden `roles` / `sso` still in union | Soft-hide + quiet deep-link (**M6**) — Langfuse Viewer “hide config” energy |

### B. Level + topic (Langfuse) — beat service-boundary tabs

Langfuse docs Platform bucket (visible in `langfuse-demo-scroll0.png` / `scroll1.png`):

- **Administration** — org/project membership, access  
- **API & Data Platform** — keys, ingestion, data plane  
- **Security & Guardrails** — compliance / safety  
- Product areas (Observability / Prompts / Evaluation) stay **out** of Settings

**Eden steal:** Organize by **user intent**, not internal services (Wave 0 R5 settings MUST). Map:

| Intent | Eden tab(s) | Do not bury under |
|--------|-------------|-------------------|
| “Who is in this workspace?” | members (+ invite) | SCIM-first |
| “Unblock SDK / ingest” | api-keys | gateway / MCP soup |
| “Pay / limits” | billing | finops as peer daily tab |
| “Account security” | security / account | org identity fields |
| “Compliance trail” | `/audit-trail` only | Settings `audit-log` twin (**M3**) |
| “Data plane knobs” | Advanced: retention, PII, exports, gateway, DLQ | Daily rail |

Score / annotation schemas live in Langfuse **Project Settings** (R3) — Eden equivalent is **product** Settings (evals/guardrails), not Workspace daily chrome. Don’t overload Workspace with rubric editors.

### C. Progressive disclosure density (both + DESIGN.md)

- Laminar DESIGN (R2 / Eden `DESIGN.md`): dark tonal steps, **28–32px** controls, **14px** body, inputs `bg-secondary`, one accent CTA.  
- Settings leaves = **form sections + DangerZone**, not KPI card strips (`DESIGN.md` §6–7).  
- Density toggle is a **product preference**, not overview chrome (`DESIGN.md` §9; checklist S18).

Visual continuity: product mock density in `lmnr-home-scroll1.png` / `langfuse-home-scroll1.png` / `langfuse-public-trace-scroll0.png` — Workspace should feel like the same tool, not a separate “admin marketing” site.

## 3. Auth, region, and first workspace entry

### Laminar — SSO-first, dark, projects callback

**Cite:** `lmnr-app-scroll0.png`, `lmnr-app-full.png`

- Centered “Welcome Back”; **Google / GitHub / Microsoft** only (no email field on this capture).  
- Callback targets `/projects` → login wall.  
- Brand mark top-left; legal footer Privacy + Terms.  
- Continuity with dark docs (`lmnr-docs-scroll0.png`) and dark product mocks.

**Eden steal:** Auth stays outside Workspace chrome; invite accept (`/invite/[token]`) must land coherently into Members / overview (**M16**, S9). Prefer SSO-capable paths for team workspaces without inventing SSO settings UI until Ghosts A lifts (**M6**).

### Langfuse — region before identity

**Cite:** `langfuse-cloud-scroll0.png`, `langfuse-cloud-full.png`, `langfuse-public-project-scroll0.png`, `langfuse-public-project-scroll1.png`

- Troubleshooting callout (force refresh / cache) above the form — reduce auth support load.  
- **Data Region** dropdown (EU flag) **above** email Continue — residency chosen before credentials.  
- Providers: Google, GitHub, **Azure AD**, plus ClickHouse Cloud.  
- Legal stack names infra partner + Cloud Addendum + Privacy.

**Eden steal:** If multi-region ever ships, put residency on **entry or overview**, not a buried Advanced tab. For now: overview plan/region chip if applicable; keep troubleshooting patterns for invite/auth friction. Azure AD scent = Enterprise/SCIM path belongs under **team Advanced**, not personal (**M5**).

### Langfuse public vs project walls

- Live **public trace** works without login (`langfuse-public-trace-*.png`) — share is a **project action**, not a Settings page.  
- **Public project** home still hits sign-in (`langfuse-public-project-*.png`) — sharing granularity is resource-level.

**Eden steal:** Share / public links stay on Observe/Improve resources; Workspace Settings owns **membership & keys**, not every share toggle.

## 4. Members, invites, RBAC

| Pattern | Laminar (docs/PR) | Langfuse (docs) | Eden steal |
|---------|-------------------|-----------------|------------|
| Invite | Email-gated accept; idempotent; reject existing members; admins revoke-only API | Add by email; pending until signup; email notification | Members leaf: invite → pending → active; align `/invite/[token]` (**S9**) |
| Roles | Workspace admin gates | Org + project roles; assign ≤ own role; Viewer hides config | Ship Members + clear permissions; **don’t** advertise Roles/SSO ghosts (**M6**) |
| Personal vs team | Free: **1 seat** (`lmnr-pricing-scroll0.png`) | Org with projects for teams | Personal: 0 invite/SCIM/transfer chrome; CTA to upgrade (**M5**, S6) |
| Last-resource guard | Block delete last project | Project transfer keeps keys on project | DangerZone: block last-workspace / last-owner footguns |

Langfuse **None** role (org without default project) ≈ Eden “invited to workspace but no product scope yet” — teach via empty Members/overview, not a second IA.

## 5. API keys — the unblock path

| Peer | Key scope | UX notes |
|------|-----------|----------|
| **Laminar** | **Project** API key | CLI `lmnr-cli setup` mints key → `.env`; visible/revocable under **Settings → Project API Keys**; keys never in `.lmnr/project.json` |
| **Langfuse** | **Project** keys for data; **Org** keys for Admin/SCIM | Org keys in Organization Settings (Owner/Admin); project keys stay with project on transfer |

**Cite (indirect):** product chrome assumes keys already work — env chip `Env: default` on `langfuse-public-trace-scroll0.png`; Laminar pricing/usage assumes ingest (`lmnr-pricing-scroll0.png`).

**Eden steal (checklist M10 / S11):**

1. Overview → **≤2 clicks** to API keys.  
2. Reveal-once secret UX; revoke primary destructive pattern.  
3. Do **not** force gateway/MCP before first key.  
4. If Eden ever adds workspace-scoped admin keys, separate them visually from ingest keys (Langfuse org vs project), still under Advanced or a clear subheading — not a 7th daily peer tab if daily is already full.
