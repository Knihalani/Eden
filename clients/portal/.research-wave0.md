## 8–12 transferable best practices for Eden

1. **Transcript-first, tree secondary** — default the view that answers “what did the agent do?”; keep hierarchy for instrumentation debug.
2. **Collapse multi-agent fan-out into cards** — scan N subagents, expand one in place; preserve outer scroll.
3. **Elide non-semantic spans** — wrappers/framework internals stay out of the reading flow.
4. **Inline one-line previews on every row** — skim long runs without expanding payloads.
5. **Surface root/subagent Input automatically** — don’t make users dig `messages[]` for “what was asked?”
6. **Synced timeline as overview, not the primary reader** — parallelism/latency/errors at a glance; content stays transcript.
7. **Master–detail drawer + URL state** — list stays mounted; deep-link `traceId`/`spanId`; Esc closes; don’t full-page-navigate for every open.
8. **Saved table views with drift UX** — filters/search/sort/columns as named presets; amber “unsaved” + save/discard; **scope views per table**.
9. **Dense toolbar defaults (≈28px / 14px)** — observability UI should feel like a tool, not a marketing dashboard.
10. **Reserve semantic colors for span kinds** — don’t reuse tool/LLM/subagent hues as generic accents.
11. **Empty states = onboarding path** — coding-agent prompt + copy box **or** manual SDK steps + integrations grid + live “listening” when realtime connects ([PR #1887](https://github.com/lmnr-ai/lmnr/pull/1887)).
12. **Opt-in intelligence panels with grounded citations** — chat/SQL/metadata off by default; answers jump to spans via chips.
13. **(Bonus) Sessions as conversation cards** — numbered turns with I/O previews before span drill-down.

## Anti-patterns Laminar avoids

| Avoid | Instead |
|-------|---------|
| Default equal-weight span trees for agents | Transcript of the LLM↔tool loop |
| Making useful reading depend on extra “prompt” attributes | Auto-parse chat completions for Input |
| Expanding all subtrees / equal indent walls | Collapsed subagent cards |
| Always-on Metadata + Chat + Timeline + span panel | Progressive disclosure; span panel default closed in drawer |
| Shared saved views across Traces/Spans/Sessions | Per-table view namespaces |
| Silent filter drift | Amber unsaved indicator |
| Spacious consumer UI / light-mode “product” chrome in app | Dark, dense, 28px controls |
| Decorative brand color / span colors as decoration | Primary = one CTA; span colors = type labels only |
| Empty tables with a sad “no data” only | Actionable setup (agent prompt / manual / docs / Discord) |
| Chat that dumps ungrounded prose | Span-cited chips that navigate |

# Wave 0 / R4 — Helicone + Braintrust portal UX

**Verdict:** Scannable logs come from **dense truncated tables + filters/properties + a detail panel**; comparable experiments come from **immutable baselines + green/red deltas + inline diff + aggregate grades**—not denser columns.

## 1. Logs / request table UX

### Helicone
- **Multi-view IA, not one mega-table:** Requests / Sessions / Users / Models / Properties each answer a different question ([Observability overview](https://helicone-helicone.mintlify.app/observability/overview)).
- **Row scan columns:** timestamp, model, latency (incl. TTFT), cost/tokens, status, truncated I/O; properties appear as optional columns you can hide via **Columns** ([Segmentation cookbook](https://docs.helicone.ai/guides/cookbooks/segmentation)).
- **Custom properties as first-class facets:** `Helicone-Property-*` tags drive filter, cost grouping, Properties page metrics, and alert targeting ([Custom properties](https://docs.helicone.ai/features/advanced-usage/custom-properties)).
- **Sessions > flat requests for agents:** Session-Id + Path hierarchy + Session-Name for workflow grouping/filtering ([Sessions](https://docs.helicone.ai/features/sessions)).
- **Dashboard above the log:** big totals (requests, cost, latency, errors) + time series; live feed + time-range filter ([Metrics](https://helicone-helicone-7.mintlify.app/observability/metrics), product mockups).
- **Alerts reuse request filters:** same filter system as Requests; min-request floor; group by user/model/provider/property ([Alerts](https://docs.helicone.ai/features/alerts)).

### Braintrust
- **Default = traces, not spans:** one row = root trace; switch to Spans for op-level timing ([View logs](https://www.braintrust.dev/docs/observe/view-logs)).
- **Compact scan columns:** Created, Name, Input, Output—long text truncated; selection opens right detail ([marketing Observe UI](https://www.braintrust.dev/)).
- **Toolbar triad:** View dropdown · Filter · Display · Search · time range + **LIVE** tail ([Filter](https://www.braintrust.dev/docs/observe/filter)).
- **Filter chips:** Basic (point-and-click) + SQL; applied filters as editable chips; built-in views (Errors, Non-errors, Unreviewed, Assigned to me).
- **Custom columns via SQL expression** (e.g. `metadata.user_id`) so the table surfaces what matters without dumping full payloads.
- **Detail panel modes:** Trace / Timeline / Thread / Views; Thread = chat-style system/user/assistant; tool calls as distinct badges ([Observe](https://www.braintrust.dev/docs/observe)).
- **Log → improve:** select rows → **Iterate in playground**; assign/tag for review.

**What makes logs scannable without clutter**
1. Truncate I/O in the grid; full text only in the panel.  
2. Toggle columns + compact density.  
3. Properties/metadata as filters/columns, not always-on cells.  
4. Separate “list” from “aggregate” (Helicone Properties/Users; Braintrust Summary layouts).  
5. Live flash for new rows only while the tab is focused.

## 2. Experiment compare UX (Braintrust; Helicone is weaker here)

Helicone’s strength is **observability + playground/prompts**, not Braintrust-grade experiment compare. Braintrust’s model:

| Pattern | Behavior | Source |
|--------|----------|--------|
| **Playground vs experiment** | Playground = mutable overwrite; Experiment = immutable snapshot you can revisit/compare | [Playgrounds](https://www.braintrust.dev/docs/evaluate/playgrounds), [Evaluate](https://www.braintrust.dev/docs/evaluate) |
| **Enter compare** | Multi-select experiments → **Compare**, or Comparisons selector in sidebar | [Compare experiments](https://www.braintrust.dev/docs/evaluate/compare-experiments) |
| **Baseline** | Persistent baseline (experiment or project default); else latest same-branch | same |

# === RESEARCH FRESH: R8-linear (94247f56-bfe2-47d8-88c8-736a5cd3221f) ===

# Wave 0 / R8 — Dense B2B portal chrome (12 principles)

Gold standards studied: **Linear**, **Vercel Dashboard**, **Stripe Dashboard**, **Datadog**, **Grafana** — authenticated app chrome only.

---

### Sidebar vs command palette

**1. Sidebar = places; palette = verbs + deep find**  
Keep the left nav for durable destinations (Inbox, Projects, Deployments, Logs). Put “do X / go to entity Y” in Cmd/Ctrl+K so the chrome stays thin. Linear’s palette is the reference: navigate + act in one surface, with shortcuts shown beside results.  
→ [Gunpowder Labs on Linear](https://gunpowderlabs.com/2024/12/22/linear-delightful-patterns) · [DesignSystems.one / Linear](https://www.designsystems.one/design-systems/linear)

**2. Progressive customization: default nav + user-pinned places**  
Ship a sane default sidebar; let power users pin saved views, favorites, and recent pages into Shortcuts—don’t dump every product surface into always-visible nav. Stripe’s Shortcuts (pinned + recently visited) and Linear’s pin/save-to-sidebar are the pattern.  
→ [Stripe Dashboard basics](https://docs.stripe.com/dashboard/basics) · [Gunpowder Labs](https://gunpowderlabs.com/2024/12/22/linear-delightful-patterns)

**3. Collapsible / resizable chrome; hide when reading data**  
Primary nav should be hideable and resizable so dense tables and graphs reclaim width. Vercel moved tabs into a resizable, hideable sidebar ordered by common workflows; Grafana docks/undocks side panes and can auto-hide.  
→ [Vercel nav redesign](https://vercel.com/changelog/dashboard-navigation-redesign-rollout) · [Grafana create dashboards](https://grafana.com/docs/grafana/latest/visualizations/dashboards/build-dashboards/create-dashboard/)

---

### Table density without overwhelm

**4. Density is a user setting (compact / comfortable / spacious), not one hard-coded height**  
Analysts want more rows; occasional users want breathing room. Persist density per user. Treat density as a product feature like Stripe-class financial tables.  
→ [Setproduct data table guide](https://www.setproduct.com/blog/data-table-ui-design) · [Stripe Design System](https://www.designsystems.one/design-systems/stripe-design)

**5. Toolbar + sticky identity columns + filter chips that show the active query**  
Above every dense table: search, filters, column picker, primary action. Freeze the leading identity/status columns; show active filters as chips so the view is always legible. Stripe Dashboard is the cited reference for sticky financial tables + async filters/presets/export.  
→ [Stripe Design System](https://www.designsystems.one/design-systems/stripe-design) · [Setproduct](https://www.setproduct.com/blog/data-table-ui-design)

**6. Progressive disclosure: KPIs/sparklines first, full charts and row detail on demand**  
Don’t put every column and every chart on the list surface. Stripe-style hierarchy: key metrics + contextual sparklines, then click-through for full charts/detail; calibrate density to role (ops/finance vs casual).  
→ [Illustration.app on Stripe dashboard IA](https://www.illustration.app/blog/stripe-payment-ux-gold-standard) · [Masterly fintech dashboards](https://www.themasterly.com/blog/fintech-dashboard-design-guide)

---

### Split panes / master-detail

**7. Two detail depths: Peek (ephemeral) vs Split (persistent)**  
**Peek** (Space / Quick Look): skim adjacent rows without leaving the list or losing scroll/filters. **Split**: keep list + detail side-by-side for multi-step work. Linear documents both; don’t force full-page navigation for every row.  
→ [Linear Peek docs](https://linear.app/docs/peek) · [Linear UI redesign](https://www.linear.app/now/how-we-redesigned-the-linear-ui)

**8. Docked vs overlay panes; persist size and dock state**  
Detail/inspector panes should dock (resize main content) or float (overlay). Persist dock + width. Grafana’s sidebar/toolbar epic and docs make this explicit; Stripe Apps `ContextView` is the same idea—app drawer beside Dashboard content.  
→ [Grafana create dashboards](https://grafana.com/docs/grafana/latest/visualizations/dashboards/build-dashboards/create-dashboard/) · [Grafana epic #113993](https://github.com/grafana/grafana/issues/113993) · [Stripe Apps design](https://docs.stripe.com/stripe-apps/design)

**9. Compare mode: duplicate the workspace side-by-side with linked time/scope**  
For investigation UIs, one click splits the workspace so users compare envs, queries, or time ranges with synced pickers. Grafana Explore’s Split is the canonical pattern.  
→ [Grafana Explore](https://grafana.com/docs/grafana-cloud/visualizations/explore/get-started-with-explore/)

---

### Settings IA

**10. Triple-partition settings: Personal · Account/Team · Product**  
Never dump all config into one alphabetized list. Stripe’s documented IA: **Personal** (me), **Account** (business/team/security), **Product** (Billing, Radar, Payments…). Vercel mirrors scope with Team Settings vs Project Settings in the sidebar.  
→ [Stripe Dashboard basics](https://docs.stripe.com/dashboard/basics) · [Vercel project settings](https://vercel.com/docs/project-configuration/project-settings)

**11. Same nav shape across scopes; scope is a filter, not a different app**  
Team vs project (or org vs workspace) should share the same sidebar labels; switching scope filters the same pages. Vercel’s “Projects as filters” + consistent team/project tabs is the lesson.  
→ [Vercel nav redesign](https://vercel.com/changelog/dashboard-navigation-redesign-rollout)

---

### Status/health home vs data workspaces

**12. Home answers “what needs attention?”; workspaces answer “let me dig”**  
**Home**: status, health, notifications, owned entities, next actions (customize with widgets). Stripe Home = analytics + unresolved disputes/identity; Datadog IDP Homepage = PRs/tickets + service health/on-call; Vercel project home = production + previews status.  
**Workspaces**: Explore / Log Workspaces / Sigma / transaction lists—query, filter, join, export. Keep these separate so Home never becomes a second Explore.  
→ [Stripe Home](https://docs.stripe.com/dashboard/basics) · [Datadog IDP Homepage](https://www.datadoghq.com/blog/datadog-idp-homepage/) · [Vercel dashboard redesign](https://vercel.com/blog/dashboard-redesign) · [Grafana Explore](https://grafana.com/docs/grafana-cloud/visualizations/explore/get-started-with-explore/) · [Datadog Log Workspaces](https://www.datadoghq.com/blog/log-workspaces/)

---

### Bonus density pattern (ops dashboards)

Datadog’s **high-density mode** (wide monitors → side-by-side groups on a 12-col grid, toggleable) is worth copying for status walls: design for 1280px *and* 2560px, put streams at the bottom so they don’t trap scroll.  
→ [Datadog dashboards blog](https://www.datadoghq.com/blog/datadog-dashboards/) · [Datadog integration dashboard guidelines](https://docs.datadoghq.com/extend/integrations/create-an-integration-dashboard/)

## 3. Visual rules Eden should adopt

1. **Master–detail as default for traces** — Keep list/tree and inspector on one screen (Langfuse / Braintrust / Phoenix). Prefer split ≥1280; drawer on smaller. Avoid forcing full-page navigation for every span.
2. **Latency, tokens, cost on every row/node** — Right-aligned or inline secondary type (Langfuse pink metrics; Laminar green tokens). First-class, not buried in hover.
3. **Metadata as a pill strip** — Timestamp, latency, env, $, token summary as compact chips above I/O (Langfuse).
4. **I/O visual split** — Structured input (Path/Value or JSON) vs washed/toned **output** block; Formatted ↔ JSON toggle.
5. **Narrow app rail (~200–240px / ~15–20%)** — Helicone/Laminar docs pattern: icon+label groups; don’t steal canvas from tables.
6. **One functional accent** — Eden already dark-terminal: pick **one** accent (not purple-default); use semantic colors only for status (fail/success/tokens). Laminar orange / Helicone blue / Langfuse yellow-highlight are good precedents.
7. **Chat-with-trace as overlay/rail, not a separate product** — Laminar floating panel; Phoenix Ask bar; keep dense data visible underneath.
8. **Toolbar grammar for lists** — View · Filter · Display · Search · time range · LIVE (Braintrust). Match Eden’s filter-bar / density prefs.
9. **Thin 1px borders + size hierarchy over card spam** — Dense surfaces use hairline rules and type weight; reserve cards for **metric dashboards** (Helicone), not every trace row.
10. **Monospace for IDs, span names, JSON; sans for chrome** — Universal across all five.
11. **Keyboard affordances** — Shortcut chips on primary actions (Langfuse `L` / `⌘K`) fit Eden’s command palette culture.
12. **Signals/issues callout above transcript** — Laminar’s failure banner pattern maps cleanly to Eden Issues/Alerts.

**Explicit non-goals from this corpus:** Don’t copy Helicone’s light marketing aesthetic for the authenticated portal; don’t use Phoenix marketing purple glow; don’t make the first viewport a card collage.

### Design principles distilled

- **Density over decoration** — 28px controls, 14px body; borrow from Linear/Vercel, not consumer SaaS.
- **One primary action** — brand orange only for the single most important CTA.
- **Narrow palette** — hierarchy via background steps; don’t invent new accents.
- **Read like a conversation** — default to human-readable transcripts; keep trees as power tools.
- **Collapse by default** — subagents/cards, optional timeline/chat/metadata.
- **Master–detail everywhere** — list ↔ right pane; one click from score → span.
- **Save the user’s filters** — named table views beat re-configuring columns every visit.
- **Empty states teach the next step** — integrations, sources, listening status—not blank voids.
- **Semantic color = product meaning** — tool/llm/subagent only in span UI.
- **Editable ≠ card** — inputs use secondary fill so they read as fields.
- **Two font weights max** per screen.
- **Progressive power** — SQL/MCP/CLI for depth; UI stays skimmable.

## Inconsistency report

### 1. Overlapping / duplicate primitives

| Issue | Detail |
|-------|--------|
| **Badge vs StatusBadge family** | Generic CVA `Badge` (status + pipeline + outcome colors) **and** icon badges in `status-badge.tsx` (`StatusBadge`, `SeverityBadge`, `TraceOutcomeBadge`, …). Same semantic space, different APIs/shapes (`rounded-full` vs `rounded-md`). |
| **Tag vs Badge** | Removable chip vs colored pill — close visually; easy to mix. |
| **Alert vs Banner** | Both convey tone; Alert = bordered message block; Banner = mono pill with pulse dot. Overlap on error/success/info. |
| **Card / Panel / Section / StatCard / ChartCard / LinkCard** | Six surface containers; comments distinguish Card vs Panel, but Section ≈ Panel+header; LinkCard unused from barrel. |
| **Table vs DataTable** | Both exist; DataTable wraps Table (intentional), but many pages still hand-build tables. |
| **EmptyState / ErrorState / QueryState / NoOrgState** | Related empty/error patterns; QueryState composes them — good — but call sites still pick inconsistently. |

### 2. Button style inconsistencies

| Issue | Detail |
|-------|--------|
| **`default` ≈ `secondary`** | Both map to the same blue (`--accent` and `--primary` are both `#5B9EFF`) → two names, one look. |
| **`destructive` vs `danger`** | Solid red vs outlined/dim red — two “delete” grammars. |
| **`emerald` vs success tokens** | Uses `--accent-2` (terminal green); overlaps “success” language. |
| **Hand-rolled buttons** | Settings dialogs (`delete-org-dialog`, `transfer-ownership-*`, `pii-policy-tab`, `security-tab`), `not-found`, `global-error`, `users` page, ScoresTab, etc. still use raw `<button className="px-… rounded-lg bg-[var(--accent)]…">` instead of `Button`. |
| **Direct Radix Dialog** | `delete-org-dialog.tsx`, `transfer-ownership-dialog.tsx`, `security-tab.tsx` import `@radix-ui/react-dialog` **bypassing** `ui/dialog`. |

### 3. Barrel / export gaps

Present on disk but **missing from** `index.ts`: `filter-bar`, `wizard`, `link-card`, `error-boundary`, `table-sticky`.  
`status-badge` barrel only exports `StatusBadge`, `IssuePriorityBadge`, `IssueWorkflowBadge` — not `SeverityBadge`, `OutcomeBadge`, `TraceOutcomeBadge`, etc. (imported by path).

### 4. Radix / deps drift

- Checkbox & Switch: shadcn-style API, **not** Radix (despite next.config listing Radix checkbox/switch).  
- Popover / ScrollArea: optimized in next.config, **no** ui components, **not** in package.json.  
- Label package installed; no `ui/label.tsx`.  
- No official shadcn `components.json`.

### 5. Tabs / Sidebar

- Shared `ui/tabs` exists with `underline` hub grammar, but `settings/page.tsx` still has hand-rolled `role="tablist"` rail (spec notes ~20 settings tabs).  
- No Sidebar primitive; sidebar is AppShell + portal-chrome composition.

### 6. Token aliases / legacy

- `--accent-2`, `--accent-light`, `--primary*` documented as legacy/compat.  
- `--info` and Banner `info` both use accent blue (same as primary CTA), while `--status-running` is a separate sky — intentional but easy to misuse.  
- Badge `success` vs `emerald` both green-tinted.

- Unequal visual weight: content > chrome.
