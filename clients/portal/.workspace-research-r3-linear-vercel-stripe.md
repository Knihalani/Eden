## 1. Thesis

Linear, Vercel, and Stripe share one **team-settings grammar**:

| Pillar | Shared rule |
|--------|-------------|
| **Overview** | One composition: identity + plan pulse + short admin jobs — not a widget dashboard |
| **Members** | First-class rail item; invite is the primary CTA |
| **Billing plan card** | Calm “what plan / seats / status / change” hero; invoices below the fold |
| **Search** | Local settings find once option count is high; does **not** excuse a long default rail |
| **Danger zones** | Bottom of General/Overview; typed confirm; owner-gated |
| **Progressive disclosure** | Daily ≤ ~6 mental tabs; Advanced / Product / Project absorbs the long tail |

**Eden translation (Ambition A):** Workspace overview as Settings landing; **≤6 daily-visible tabs** (+ Advanced collapsed); explicit **personal vs team** mode gates; Stripe-calm billing; no second 240px settings sidebar.

## 2. Overview patterns

### Shared composition (steal this layout)

The first settings surface for a team/workspace reads as **one composed page**, not a portal-of-everything:

| Band | Job | Linear | Vercel | Stripe |
|------|-----|--------|--------|--------|
| **Identity** | Name, slug/URL, avatar | Workspace name + URL (Administration) | Team Settings → General (name, slug, avatar, Team ID) | Account details / public info |
| **Plan pulse** | Tier + seats/usage at a glance | Admin → Billing summary | Billing + spend cues on Pro/Enterprise | Account health + entitlements |
| **Primary admin jobs** | Short destinations, strong scent | Members, Security, Billing, Integrations | Members, Billing, Security & Privacy, Domains… | Team & security, Business details |
| **Rare / irreversible** | Bottom or gated | Delete workspace (48h cool-down) | Leave team / Delete team | Close account / sensitive security |

**Overview rules**

1. **One job:** “Is this the right workspace, who owns it, are we on the right plan, what do I do next?”
2. **No card soup:** identity fields + **one** plan card + a short list of admin links beats StatCard grids.
3. **Same product chrome:** open from workspace/team switcher or Settings in sidebar; do not invent a nested settings app (Linear: workspace menu → Settings; Vercel: Team → Settings; Stripe: Dashboard settings).
4. **Role-gated bands:** Members see Personal/Account; only Admins/Owners see Administration, billing write, delete. Linear is explicit: members see settings for their own work; admins/owners also see workspace administration.
5. **Fail → act ≤2 clicks:** from overview, reach Members, Access/keys, or Billing without hunting (feeds R10 **M10**).

### Scope split (critical — R8 principle 10)

| Product | Scope A — me | Scope B — us | Scope C — surface |
|---------|--------------|--------------|-------------------|
| **Stripe** | **Personal** (password, sessions, notifications) | **Account** (business, team & security) | **Product** (Billing product, Radar, Payments…) |
| **Vercel** | User / account prefs | **Team Settings** | **Project Settings** (env, domains, git, protection) |
| **Linear** | Account | **Workspace → Administration** | **Team settings** (workflow, labels, access) per product team |

Never flatten Personal + Team + Product into one alphabetized mega-list. Scope is a **filter**, not a different app (R8 principle 11 / Vercel “projects as filters”).

## 3. Members as first-class

### Why first-class

In B2B ops products, **who can see data and spend seats** is as frequent as renaming the workspace. All three put **Members** on the primary settings rail — not under Advanced → Security → Users.

### Pattern matrix

| Pattern | Linear | Vercel | Stripe |
|---------|--------|--------|--------|
| Dedicated Members page | Settings → Administration → Members | Team Settings → Members | Team / Team & security |
| Invite = primary CTA | Emails + role + optional teams | Emails + role (+ project roles for Contributor) | Add member → emails + roles |
| Role on the row | Owner / Admin / Member / Guest + filters | Owner / Member / Developer / Billing / Viewer / … | Multiple assignable roles |
| Pending visible | Filter: Pending invites | Pending Invitations section | Pending until accept |
| Soft-remove vs hard-delete | **Suspend** (history kept; seat drops next cycle) | Remove / role change | Remove / role edit |
| Seat ↔ billing | Suspended off next bill; Billing shows seats | Seat pricing + Billing role | Org/account team mgmt |

### Steal-for-Eden (Members)

1. **Daily tab** beside Overview — never buried under Security or Advanced.
2. **Table-first:** name/email · role · status · last activity (if available) · overflow (edit role / remove / suspend).
3. **Invite sheet:** multi-email, role, one primary Send.
4. **Pending (+ Suspended if modeled)** filters so the list stays operational.
5. **Billing scent:** “Suspended members lose access and stop counting toward seats” (Linear) — map to Eden plan limits.
6. **Permission scent:** if viewer cannot invite, hide Invite or explain the role gate (Vercel Owner-default).
7. **Personal mode:** when workspace is personal/Hobby-class, **hide invite chrome**; explain upgrade path instead of empty invite spam (Vercel: upgrade Hobby → Pro to add members). Feeds R10 **M5**.

## 4. Billing as a clear plan card

### Anti-pattern

Landing Billing on a raw invoice table, usage heatmap, or FinOps explorer. That is **investigation**, not **plan literacy**.

### Gold pattern (Stripe calm + Linear/Vercel plan management)

**Plan card (above the fold):**

```
┌─────────────────────────────────────────────────────────┐
│  Plan: Pro                          [Change plan]       │
│  $X / seat · monthly · renews Apr 1                     │
│  Seats: 12 used / 15 included     [Manage members]      │
│  Status: Active · Payment OK                            │
└─────────────────────────────────────────────────────────┘
```

Then progressive sections:

1. **Usage / limits** — meters that affect the plan (requests, retention, seats); soft bars; upgrade when near cap.
2. **Payment method + billing email** — edit in place or modal.
3. **Invoice history** — table below the fold (Stripe Dashboard density).
4. **Spend controls** (Vercel Pro+) — threshold → notify / pause; typed team name for destructive pause.
5. **Cancel / downgrade** — delayed confirm; Linear: takes effect end of period; consequences stated plainly (e.g. free-plan limits).

### Steal-for-Eden

- One **Billing** daily tab whose hero is the plan card.
- Park FinOps / cost explorer under **Advanced** or a Cost product hub — not a twin first-class settings peer.
- One primary CTA: **Upgrade / Change plan**; secondary: Manage payment, View invoices, Manage members (seat overflow).
- Cross-link plan limits → Members and retention (information scent).
- Matches plan Wave 9.4 / R10 **S11**: “Billing / plan limits — Stripe-like calm.”

## 5. Search + danger zones

### Settings search

- Add **local settings search** once option count exceeds ~15–20 (Threshline / R5; R10 **N4**).
- Search **finds Advanced items**; it must not justify 19 always-visible tabs.
- Results jump to **category + tab + section anchor**, not a second nested hub.
- ⌘K stays **global** navigate + verbs (Vercel Geist / Linear). Settings search is **local to the settings surface**. Do not bind ⌘K solely as a settings filter.

### Danger zones

Industry grammar (Linear / Vercel / GitHub-class admin UIs):

| Rule | Detail |
|------|--------|
| **Placement** | Bottom of Overview / General — never top of page, never a default tab labeled “Delete” |
| **Visual** | Muted or `--error` outline; titled **Danger zone** / **Delete workspace** / **Leave team** |
| **Actions** | Transfer ownership, leave workspace, delete workspace, revoke all sessions, wipe retention |
| **Confirmation** | Type workspace/team name or slug; checkbox for irreversible data loss |
| **Role gate** | Owners only for delete/transfer; Admins may suspend members but not delete workspace |
| **Copy** | State what survives (e.g. invoices) vs what dies (traces, keys, members) |
| **Cool-down (Linear)** | Delete scheduled (e.g. 48h) with admin cancel window — optional polish |

Vercel: **Leave Team** and **Delete Team** are separate bottom sections; spend-management pause uses typed team name — same confirmation grammar.

## 6. Progressive disclosure

### NN/g mapped to settings

[NN/g Progressive Disclosure](https://www.nngroup.com/articles/progressive-disclosure/): show frequent options first; defer rare/advanced on request; **≤2 disclosure levels** in the rail (third level → users get lost). Strong information scent on the control that reveals more.

| Level | What shows | Peer examples |
|-------|------------|---------------|
| **L0 Daily** | ≤6 mental tabs | Linear Admin subset; Vercel Team core; Stripe Personal + Account daily jobs |
| **L1 On demand** | Advanced accordion / More / Product or Project scope | SSO/SCIM, audit, webhooks, retention, PII, gateway |
| **L2 Staged** | Fields appear when parent enabled | Enable SSO → IdP fields; Spend management → threshold + pause |
| **L3 Command** | ⌘K / search for rare destinations | Export, DLQ, finops, soft-launch features |

### Constraints from Eden docs

- R10 **M2**: daily-visible tabs **≤6** among overview · account · api-keys · members · security · billing; Advanced collapsed.
- `DESIGN.md`: no double settings sidebar; recede chrome.
- R4 **M1 / S1 / S12**: progressive disclosure; ≤2 rail levels; flat nav ≤12 core with Advanced buried.
- R5: organize by **user intent**, not internal service boundaries.

### Anti-patterns to reject

- 19–21 tab IDs always visible in a second full-height rail.
- Soft-launch ghosts (`roles` / `sso`) in the tab union or ⌘K promo (R10 **M6** / Ghosts A).
- Embedding an entire Profile page as a tab instead of an inline Account panel.
- Alphabetical mega-list mixing Personal + Team + Product knobs.
- Multiple Advanced entry points with weak scent (“More”, “Explore”).

## 7. Steal-for-Eden (actionable)

### 7.1 Overview composition (Wave 2 feed)

**Recommended `/settings` default (`?tab=overview` or bare `/settings`):**

1. Workspace identity (name, slug, logo) — save inline.
2. Plan card (tier, seats/usage, status, Change plan).
3. Health snapshots with act links: members count → Members; key health → API keys; audit snapshot → `/audit-trail`.
4. Personal→team CTA when `Organization.is_personal` (unlock Members / SCIM without inventing Roles/SSO).
5. Danger zone at bottom (owner-only; hidden or reduced in personal mode).

No KPI StatCard wall. No second portal sidebar (**M12**). Overview is **not** a second product Home (**M11**).

### 7.2 ≤6 daily tabs

Target **default visible** set (hard gate R10 **M2**):

| # | Tab | Intent | Scope |
|---|-----|--------|-------|
| 1 | **Overview** | Identity + plan pulse + act links + danger | Team |
| 2 | **Account** | Me: profile, sessions, notifications, density | Personal |
| 3 | **API keys** | Access credentials / reveal-once secrets | Team |
| 4 | **Members** | Invite, roles, suspend | Team (gated in personal) |
| 5 | **Security** | 2FA / sessions policy; SSO entry when shipped | Team |
| 6 | **Billing** | Plan card + invoices | Team (admin write) |

**Advanced** (collapsed; searchable): Retention, PII, Gateway, Exports, Webhooks/DLQ, FinOps, Analytics prefs, Sidebar prefs, Status, SCIM (team-only), Autonomous, References. Roles / SSO: soft-hidden until backend ships (Ghosts A).

Optional category pills (≤6 labels) may group scent without adding weekly tabs: Workspace · People · Access · Plan · Personal · Advanced.

Preserve `?tab=` deep links; `audit-log` → `/audit-trail` redirect (**M3**, **M9**).

### 7.3 Personal vs team

Vercel’s **Hobby vs Team/Pro** and Linear’s **member vs admin Administration** are the clearest peer models for Eden `Organization.is_personal`.

| Mode | Chrome | Members | Billing | Danger / SCIM |
|------|--------|---------|---------|---------------|
| **Personal** (Hobby-class) | “Workspace” copy; no invite spam | Explain upgrade; 0 invite / transfer / ownership chrome leaks | Plan card still visible (limits + upgrade) | Hide team-only SCIM / transfer / delete-org patterns that don’t apply |
| **Team** | Full admin bands for owners/admins | Invite + roles + pending | Plan card + seat links | Owner danger zone; SCIM in Advanced |

| Bucket | Contents | Who sees |
|--------|----------|----------|
| **Personal** | Profile, Clerk account, notification prefs, density, my sessions | Every member |
| **Team / Workspace** | Overview, Members, Billing, org Security, API keys, retention, exports | Admins write; members read subset |
| **Project / Product** (if kept) | Per-project keys / ingest — mirror Vercel Project Settings | Project admins |

**IA rule:** org/workspace switch in chrome **filters the same settings shape**; do not invent a different settings app per scope.

**Copy rule:** prefer “workspace” over “org” in user-facing chrome (R10 **S5**, **S21**).

### 7.4 Mapping Eden debt → gold grammar

| Current debt (Wave 0 clutter / Ambition A) | Gold move |
|--------------------------------------------|-----------|
| ~19–21 visible tabs + second rail | ≤6 daily + Advanced; no nested 240px rail |
| Account = full `/profile` import | Inline Account panel (Personal scope) |
| Billing + FinOps both first-class | Billing = plan card; FinOps → Advanced |
| Members crowded among org tabs | Promote next to Overview |
| SettingsSearch + long rail | Keep search; shorten rail so search finds Advanced |
| Ghost `roles` / `sso` | Soft-hide; quiet deep-link notice only |
| Danger mixed with normal forms | Danger zone + typed confirm |
| Personal org shows team invite chrome | Mode helpers; upgrade CTA on overview (**M5**, **M13**) |
| Dual audit surfaces | Canonical `/audit-trail` only (**M3**) |

### 7.5 Craft notes (Linear / Vercel / Stripe)

Apply inside settings too (Mantlr craft synthesis + R4 + `DESIGN.md`):

- Monochrome + one accent; no purple/glow settings chrome.
- Cards only for **interaction units** (plan card, invite form) — not every fieldset.
- One primary CTA per leaf; destructive = danger grammar once.
- Complete microstates on Members rows.
- Recede settings chrome so content (member rows, plan card) carries weight — Linear: not every element equal visual weight.
- Kit Dialog / SettingsCard / DangerZone only — no hand-rolled accent CTAs (**M7**).
