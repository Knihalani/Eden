## 1. Thesis

Eden today ships **two live “audit” UIs with different backends and overlapping names**. Peers (Linear, Vercel, Stripe) ship **one admin-facing compliance reader** (sometimes with Enterprise export/stream depth), not a top-level product page *and* a Settings tab that both claim the same job.

**Wave 6 target (R10):** one URL — **`/audit-trail`** — that folds org privileged events + chain ledger + compliance tools as **segments**, with Settings `?tab=audit-log` becoming a **bookmark-safe redirect** (M3, M9, M15). Sidebar Audit trail stays the sole IA entry.

### 2.3 Same noun, different jobs

```
User hears “audit”
        │
        ├─ Sidebar “Audit trail” ──► agent chain ledger + SOC2 packs
        │                              (product / agent compliance)
        │
        └─ Settings “Audit Log” ──► org privileged admin actions
                                     (members, settings, billing, …)
```

| | Settings audit-log | `/audit-trail` |
|--|--------------------|----------------|
| **Question answered** | Who changed the workspace? | Did agents leave a tamper-evident trail? |
| **Actor model** | Human users (`user_id` / name) | Agent + actor_type + hash chain |
| **Compliance artifact** | Event list for admins | Verify + framework export pack |
| **Typical peer home** | Settings → Administration / Security | *(peers rarely top-level this)* |

**Overlap is IA/naming, not identical APIs.** Unifying Wave 6 is a **single reader with two data segments**, not merging backends into one table blindly.

### 2.4 Concrete dual-surface smells (today)

1. **Two IA entries** to “audit”: sidebar + Settings Compliance + ⌘K Settings command.  
2. **Cross-link both ways conceptually:** trail → Settings audit (shipped); Settings does not deep-teach trail as the pack home (R9 wanted that; still incomplete).  
3. **Copy collision:** “audit trail” appears in ⌘K description for Settings audit-log *and* in sidebar description for `/audit-trail`.  
4. **R9 vs R10 tension:** R9 allowed secondary Settings body; **R10 M3 hard-bans competing Settings compliance body** — Wave 6 resolves by redirect + fold.

## 3. Peer single-compliance patterns

### 3.1 Linear — one Audit Log under Administration

- **Where:** Workspace Settings → Administration → **Audit Log** (owners; Enterprise).  
- **What:** Workspace events (access, subscriptions, settings) + IP/country; 90-day UI; filter by type; API/webhook for power.  
- **Not:** A second top-level “Audit” product beside Settings.  
- **Steal:** Single destination; owner-gated; list-first; stream/export as depth on the **same** surface.

Sources: [Linear Audit log](https://linear.app/docs/audit-log).

### 3.2 Vercel — Activity vs Audit (clear hierarchy, one settings home)

- **Activity Log:** team chronology for members (product + team events).  
- **Audit Log:** Enterprise owners under Team Settings → Security & Privacy → Audit Log (CSV + drains/SIEM).  
- **Grammar:** deeper compliance is an **upgrade of the same Settings security home**, not a parallel Workspace nav item that fights Settings.  
- **Steal:** Name tiers honestly (activity vs audit); keep both under Team Settings; export/stream live on the audit surface.

Sources: [Vercel Activity Log](https://vercel.com/docs/activity-log) · [Vercel Audit Logs](https://vercel.com/docs/audit-log).

### 3.3 Stripe — one Security history

- **Where:** Settings → Team and security → **Security history**.  
- **What:** Filterable admin/security actions; CSV export; Activity Logs API for SIEM.  
- **Steal:** One settings-adjacent reader; export is a control on that page, not a second product.

Sources: [Stripe Team / security history](https://docs.stripe.com/get-started/account/orgs/team) · [Activity logs](https://docs.stripe.com/activity-logs).

### 3.4 Peer → Eden mapping

| Peer rule | Eden today | Wave 6 target |
|-----------|------------|---------------|
| One compliance URL in IA | Two (`/audit-trail` + Settings tab) | **`/audit-trail` only** (M3) |
| Audit lives near admin / security | Split: Workspace nav + Compliance tab | Sidebar Audit trail = reader; Settings Security may **link**, not host a second body |
| Export/verify on the same surface | Only on `/audit-trail` | Keep tools on canonical page (collapsed details / segment) |
| Deep links / bookmarks survive | `?tab=audit-log` is a live UI | Redirect preserve (M9) |
| Progressive disclosure | Compliance not daily ≤6 (good) | After redirect, Compliance category **drops** live tab body; overview may keep snapshot → trail (N9) |

**R3 already placed audit as L1 on-demand** (Advanced / Security link), not a daily tab — aligns with removing Settings body while keeping scent via overview / Security link / ⌘K → `/audit-trail`.

### 3.5 What peers do *not* do (anti-patterns Eden currently approximates)

1. Top-level **Audit trail** *plus* Settings **Audit Log** both fully interactive.  
2. Cross-linking “the other audit” as if they were interchangeable product homes.  
3. Using the same label family (“audit trail”) for human org events and hashed agent ledgers without segment labels.

## 4. Wave 6 redirect strategy

### 4.1 Success metrics (from R10)

| ID | Wave 6 ownership | Acceptance |
|----|------------------|------------|
| **M3** | Unify | Dual compliance surfaces = **0**. Canonical **`/audit-trail`**. Settings `?tab=audit-log` **redirects**. No competing Settings body. Sidebar sole IA entry. |
| **M9** | Redirect + deep links | `?tab=audit-log` → `/audit-trail` safely; other `?tab=` untouched. **Hard ban** on broken bookmarks. |
| **M15** | Productize | `/audit-trail` folds former audit-log capabilities as **segments** (e.g. Events \| Chain packs); toolbar ≤5; EmptyState teaches. |
| **S12** | Polish | Toolbar ≤5; EmptyState teaches; peer scannability. |
| **N3 / N9** | Nice | Segment URL scent; overview snapshot → trail with filter scent. |

Wave **1** may land the **redirect contract** early; Wave **6** owns the **fold + UI rewrite**. Wave **12** freezes redirects + single URL.

### 4.2 Recommended redirect mechanics

Prefer **client replace in Settings hub** (matches ghosts + Wave 6 Analytics soft-deletes), not a blind `next.config` path redirect (query-tab is not a filesystem path).

| Step | Behavior |
|------|----------|
| 1 | User hits `/settings?tab=audit-log` (bookmark, ⌘K, old docs, trail More menu). |
| 2 | Settings `useEffect` (or early branch): `router.replace("/audit-trail")` — optionally `?segment=events` so org-admin intent is preserved. |
| 3 | Do **not** mount `AuditLogTab`. Remove / stop dynamic-import of audit-log body from Settings paint path. |
| 4 | Drop `audit-log` from visible TABS / Compliance category **or** keep id only as a redirect alias (no rail label). Prefer **no rail entry** (M3). |
| 5 | Update ⌘K: single command → `/audit-trail` (label **Audit trail**); retire “Settings · Audit Log” or alias it to the same href. |
| 6 | Remove audit-trail More → “Settings audit” link (or retarget to `#` segment on same page). |
| 7 | Tests: assert replace target; assert Settings does not render privileged-events table for that tab; freeze matrix includes redirect (M17). |

**Optional query map (nice, N3):**

| Incoming | Outgoing |
|----------|----------|
| `?tab=audit-log` | `/audit-trail?segment=events` |
| bare `/audit-trail` | default segment = `chain` *(or last-used; default chain preserves today’s primary job)* |
| `?agent=` | preserved across redirect |

Permission: `audit:view` still gates **Events** segment; chain tools may keep existing org access — document in Wave 6 critic if gates differ.

### 4.4 Unified `/audit-trail` composition (M15 sketch — research only)

One page, **segments** (not two routes):

```
/audit-trail
├── Header: “Audit trail” · one More menu (Agents / Fleet / Ledger — no Settings audit)
├── Segment control (≤2–3):  Events  |  Chain
├── Toolbar ≤5 controls (S12)
│     Events: action filter · date · load more
│     Chain:  agent filter · (count) · load more
└── details “Compliance tools” (verify · export pack) — Chain segment or always collapsed
```

| Segment | Former home | API |
|---------|-------------|-----|
| **Events** | Settings `AuditLogTab` | `getAuditLog` |
| **Chain** | Current trail table | `complianceApi.ledger` |
| **Tools** | Current `<details>` | verify + exportPack |

EmptyStates must **teach which segment** (org admin actions vs agent chain) — do not reuse one generic “no audit events” for both.

## 5. Decision record

| Decision | Choice | Why |
|----------|--------|-----|
| Canonical URL | `/audit-trail` | Already Workspace IA; holds unique chain/export value peers don’t put in Settings |
| Settings tab body | **Remove** (redirect) | R10 M3; peers don’t dual-host |
| Org privileged events | **Fold into trail as Events segment** | Preserves product capability; one reader |
| R9 “secondary Settings audit” | **Superseded** | Keep R9 naming (“Audit trail” in nav) + collapsed tools rule; drop dual body |

| Ledger (`/ledger`) | **Out of Wave 6 unify** | Separate agent config ledger product; keep cross-link only |
