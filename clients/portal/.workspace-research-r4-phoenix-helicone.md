# Wave 0 / R4 — Phoenix + Helicone keys / retention / org vs project / empty states

**Scope:** Research only. No Eden product code changes.  
**Focus:** API keys, data retention, org/space vs project boundaries, empty / first-run states — patterns to steal for Eden **Settings → Advanced** (gateway · PII · retention · exports · DLQ · provider keys).  
**Date:** 2026-07-21  
**Inputs:** `.cursor/visual-research/ai-portals/phoenix-*`, `helicone-*` PNGs; `OBSERVATIONS.md` / `OBSERVATIONS-R10.md`; public Phoenix + Helicone docs; Eden Workspace R9/R10 Advanced contract (`≤6` daily + Advanced collapsed).

## Verdict (one screen)

| Product | Model | Steal for Eden Advanced |
|---------|--------|-------------------------|
| **Phoenix** | **Project** = data container; **Space** (Cloud) / instance = collab boundary; **System vs User** API keys; **named retention policies** assigned per project | Policy objects (not a lone days slider); dual key classes with scope labels; Project Settings = data plane (description, colors, annotation cleanup, retention bind) |
| **Helicone** | **Organization** = billing/seats/collab unit (1 → 5 → ∞); **Helicone keys** (`sk-`/`pk-`, `eu-`) vs **Vault provider keys**; retention **plan-gated** (7d / 1mo / 3mo / Forever) + **storage GB** meter | Plan → retention scent on Advanced; separate “platform key” vs “provider/BYOK” surfaces; org switcher in chrome; gateway/rate-limits as Monitor-class Advanced |

Eden already has daily `api-keys` + Advanced `retention` / `gateway` / `pii` / `exports`. R4 recommendation: keep **keys on daily** (unblock ingest), put **retention policy + gateway/BYOK + storage limits** under Advanced — and never mix Phoenix-style *data plane* with Helicone-style *org seats* in one unlabeled list.

## 1. Arize Phoenix — projects, keys, retention

### Org / Space vs Project

Phoenix’s primary working unit is the **Project** (trace / experiment container), not an “org settings” dump.

| Layer | Role | Notes |
|-------|------|-------|
| **Project** | Segregate traces by env / app / experiment; own Project Settings | Description + gradient colors for visual ID; annotation summary + admin **bulk-delete annotations by name** (optional time range); destructive, admin-only when auth on |
| **Phoenix Cloud Space** | Hosted instance + collaborators | Create Space → launch instance; Settings → Add User (Admin / Member); Members manage own user keys only |
| **Arize AX Workspaces** | Dept / multi-party isolation above Phoenix projects | Docs point here when org-level governance exceeds Phoenix OSS/Cloud |
| **⌘K palette** | Jump projects / datasets / experiments / prompts | Context switch without re-walking nav |

**Docs:** [Projects](https://arize.com/docs/phoenix/tracing/llm-traces/projects), [Phoenix Cloud getting started](https://arize.com/docs/phoenix/phoenix-cloud).

**Steal:** Advanced data settings should always show **which project (or Eden workspace scope)** they affect. Project Settings = data identity + retention bind + destructive cleanup — **not** members/SSO.

### API keys

Phoenix exposes **three credential classes** (Settings → API Keys):

| Kind | Who creates | Lifetime / binding | Typical use |
|------|-------------|--------------------|-------------|
| **System API key** | Admin only | Not tied to creating admin; survives admin delete | OTEL / client / unattended REST (`PHOENIX_API_KEY`, `Authorization: Bearer …`) |
| **User API key** | Any user (own keys) | Bound to user; deleted with user | Notebooks, personal experiments |
| **Admin Secret** | Deploy env (`PHOENIX_ADMIN_SECRET`) | Bootstrap only | Sidecar / provisioning; docs recommend remove after first system key |

Also: optional **key expiration**; auth-on deployments **stop ingest until a key exists** (empty-state pressure). Env: `PHOENIX_API_KEY`, `PHOENIX_PROJECT` / `PHOENIX_PROJECT_NAME` (default `"default"`).

**Docs:** [API Keys](https://arize.com/docs/phoenix/settings/api-keys), [Authentication (self-host)](https://arize.com/docs/phoenix/self-hosting/features/authentication).

**Steal for Eden:**

- Label key rows **System / service** vs **User / personal** (or project-scoped vs workspace-admin) — never one anonymous list.
- First-run empty on keys: **one primary CTA** “Create system/service key” + copyable env snippet (`PHOENIX_API_KEY` pattern → Eden equivalent).
- Expiration as optional Advanced field on create, not a separate tab.

### Retention

Phoenix models retention as **reusable policies**, then **binds** them to projects:

| Concept | Behavior |
|---------|----------|
| **Default policy** | Named `Default`; **0 days = indefinite**; every project inherits unless overridden |
| **Policy shape** | Name + rule (max **days** and/or max **trace count**) + **CRON schedule** (cleanup window) |
| **UI** | **Data Retention** tab → create policy → Project config → associate (admin) |
| **Deploy default** | `PHOENIX_DEFAULT_RETENTION_POLICY_DAYS` (0 / 7 / 30…) for self-host |
| **Side effect** | Empty sessions auto-cleaned after last traces purge |
| **Manual** | Project action **remove data** by time / selection |
| **Storage honesty** | Settings usage may lag deletes (Postgres vacuum) — surface “reclaim may take time” |

**Docs:** [Data Retention](https://arize.com/docs/phoenix/settings/data-retention).

**Steal for Eden Advanced `retention`:**

1. Prefer **named policies** (or at least named presets: Indefinite / 7d / 30d / 90d) over a naked number field.
2. Bind policy at **project / env** scope; show current bind + “used by N projects.”
3. Admin-gate destructive bind / purge; confirm copy before save.
4. Cross-link storage / plan limits (Helicone lesson below) when entitlement caps days.

## 2. Helicone — orgs, keys, retention / storage

### Org vs project

Helicone is **organization-centric** in pricing and chrome; captures do **not** show a Langfuse-style Project Settings split.

| Signal | Evidence | Implication |
|--------|----------|-------------|
| **Org switcher** | `helicone-home-scroll0.png` — sidebar top **“Xpedia AI”** chevron | Scope lives in **chrome**, not buried in Advanced |
| **Seats / orgs by plan** | `helicone-dashboard-marketing-scroll0.png` | Hobby: **1 seat, 1 org**; Pro: unlimited seats; Team: **5 organizations**; Enterprise: unlimited + on-prem |
| **IA groups** | Product mock sidebar | Dashboard · Requests · Segments (Sessions / Users) · Improve · **Monitor** (Rate Limits, Alerts) — ops knobs clustered, not mixed with Prompts |
| **Time window** | Dashboard **Custom / 24H / 7D / 1M / 3M** | Retention ceiling should **match** available ranges (don’t offer 3M picker on 7-day Hobby) |

**Docs / pricing:** [Helicone Pricing](https://www.helicone.ai/pricing) (Retention row: 7 days / 1 month / 3 months / Forever; Configurable retention on Enterprise).

**Steal:** Eden Workspace overview already owns org identity; Advanced should **not** re-implement an org switcher. Do surface **plan org/seat/retention caps** next to Advanced retention/gateway so scent matches billing.

### API keys (two planes)

| Plane | What | Where users learn it |
|-------|------|----------------------|
| **Helicone platform key** | `HELICONE_API_KEY`; Quickstart “Generate your Helicone API key at API Keys”; `sk-` read / `pk-` write; `eu-` regional prefix | `helicone-docs-scroll0.png`; [Helicone Auth](https://docs.helicone.ai/helicone-headers/helicone-auth) |
| **Provider / Vault keys** | BYOK OpenAI/Anthropic/… in Vault; proxy keys for distribution; gateway credits = Helicone manages provider keys | Platform overview “Bring your own provider keys (Advanced)” |
| **Integration pattern** | OpenAI SDK + `baseURL: https://ai-gateway.helicone.ai` + env key | `helicone-home-product-scroll1.png`, `helicone-home-scroll2.png`, docs code tabs TS / Python / cURL |

**Steal for Eden Advanced:**

- **Daily:** Eden ingest/API keys (unblock “first event”).
- **Advanced:** Gateway / provider-key vault / rate-limit — Helicone’s “BYOK is Advanced” framing.
- Prefix / region / permission badges on key rows (`sk`/`pk`/`eu` equivalent).
- Empty keys: numbered Quickstart (**1** Generate key → **2** Send request → see Requests) — `helicone-docs-scroll0.png` / `scroll1.png`.

### Retention & storage

Helicone couples **time retention** to **plan** and meters **storage GB** separately:

| Plan (from pricing capture + matrix) | Retention | Storage note |
|--------------------------------------|-----------|--------------|
| Hobby | **7 days** | **1 GB** included |
| Pro | **1 month** | 1 GB free + usage |
| Team | **3 months** | same |
| Enterprise | **Forever** + **configurable retention** | bulk discounts / on-prem |

Calculator UI (`helicone-dashboard-marketing-scroll1.png`): slider **Requests/mo** + **Tokens/request** → line items **Storage (GB $)** and **Requests ($)** — retention cost is visible as **storage**, not only “days.”

**Steal for Eden Advanced `retention`:**

1. Show **entitlement chip** (“Plan: 30 days”) beside the control; upgrade path when user asks for more.
2. Pair **days** with **storage / volume** if Eden bills or soft-caps either.
3. Don’t invent Phoenix-style freeform CRON policies on day one unless backend supports them — but **named presets aligned to plan** is fair steal from both.

## 4. Steal-for-Eden Advanced checklist

Maps to Workspace R10 **S13** (Advanced data plane: gateway / PII / retention / exports / DLQ) and R9 **daily ≤6 + Advanced**.

### Copy aggressively

- [ ] **Retention = Advanced**, with **scope label** (project/env) and **plan entitlement** chip (Helicone) + optional **named policy / preset** (Phoenix).
- [ ] **Dual key semantics:** service/system vs user (Phoenix) *or* platform vs provider-vault (Helicone) — scope badge on every row.
- [ ] **Gateway / BYOK / rate limits** under Advanced (Helicone “provider keys = Advanced”), not competing with daily API keys.
- [ ] **Org switcher stays in chrome**; Advanced only explains caps (seats / orgs / retention days).
- [ ] **Empty states distinguish:** no keys · waiting first event · filtered empty · error — never blank (`phoenix-home-error` anti-pattern).
- [ ] **First-run:** numbered steps or Quick Start cards → Create key → paste snippet → open Traces/Requests (docs grammar from both).
- [ ] **Time-range UI ≤ retention entitlement** (Helicone 7D vs 3M).
- [ ] **Destructive retention / bulk delete:** admin-only + confirm (Phoenix annotation bulk delete / remove data).
- [ ] **Monitor-class cluster** in Advanced: retention · exports · gateway · rate/alerts config — Helicone Improve vs Monitor split.

### Avoid

| Anti-pattern | Source | Eden risk |
|--------------|--------|-----------|
| Mixing members/SSO with retention/keys in one flat Advanced list | Neither peer | Breaks ownership scent (R2 Langfuse lesson) |
| Light Helicone marketing chrome / blue card soup in dark portal | `helicone-home-*` | Violates `DESIGN.md` |
| Phoenix marketing purple glow | Arize marketing (non-`phoenix-*` clean shots) | Same |
| Treating login walls as Settings proof | `phoenix-demo-*` | Docs-only for key/retention UI details |
| Unlimited freeform retention CRON without backend | Phoenix self-host | Overbuild; ship presets + entitlement first |
| Burying **create API key** only under Advanced | Helicone Quickstart puts Keys step 1 | Blocks first event; keep keys daily (R10 M2/M10) |

### Suggested Eden ownership (research only)

| Concern | Daily vs Advanced | Peer cue |
|---------|-------------------|----------|
| Eden ingest / SDK API keys | **Daily** `api-keys` | Both: keys unblock product |
| Key expiration / rotate / revoke-all | Daily leaf detail or Advanced sub | Phoenix expiration |
| Provider / gateway BYOK vault | **Advanced** `gateway` | Helicone Vault / BYOK |
| Retention days / policies / purge | **Advanced** `retention` | Phoenix policies + Helicone plan matrix |
| Storage / export of raw logs | **Advanced** `exports` (+ billing link) | Helicone storage $ |
| PII redaction / omit-logs | **Advanced** `pii` | Helicone omit-logs (docs; not in PNG) |
| Org seats / multi-org | Overview + **Billing** (not Advanced) | Helicone pricing cards |
| Project description / visual ID | Overview or project leaf | Phoenix Project Settings colors |
