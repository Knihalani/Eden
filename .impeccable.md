# Design Context — Eden

> Persistent design guidelines for the Eden monorepo. Loaded on every session to keep product, marketing, and docs visually and tonally consistent.

## Project at a glance

Eden is the **observability + improvement platform for AI agents and LLM apps**, delivered as two pillars that close a loop:

1. **Observability** — drop-in SDKs (Python, TypeScript) + OpenAI-compatible HTTP gateway that proxies every request to any upstream model.
2. **Web platform** — multi-tenant org workspace, trace/eval visualisations, data export, and a persistent AI assistant sidebar cited to real data.

Stack: Next.js 16 (App Router) · React 19 · Tailwind v4 · Radix UI · Clerk · Recharts · Framer Motion · next-intl (de / en) · Playwright + axe-core.

The PRD explicitly states the theme: *"Next.js (App Router) + dark-terminal theme, reused in marketing, portal, docs."*

---

## Users

### Primary: AI / ML engineers and platform owners

- **Context**: lives in a terminal and an IDE. Already runs OpenAI / Anthropic / Bedrock in production. Probably on call.
- **Job to be done**: drop in one proxy line, get every LLM call captured, then close the loop (find failures → propose a fix → ship a PR) without leaving the tool.
- **Sophistication**: high. Reads diffs, reads eval scores, expects instrumentation to be honest about units and timestamps.
- **Pain**: vendor dashboards that hide cost behind a sales call; agents that silently drift; telemetry that doesn't survive a re-org.

### Secondary: engineering managers, platform leads

- Same surface, different lens — cost, eval regression rate, org-wide eval coverage, audit log.
- Needs to trust the numbers in a board update without re-running the math.

## Brand Personality

**Three words: precise, technical, calm.**

- **Voice**: dry, declarative, infrastructure-grade. Never breathless. Never "revolutionary". Reads closer to a Stripe changelog than a SaaS landing page.
- **Tone**: confident with quiet edges. The product earns trust by being right, not loud.
- **Emotional goal**: *I trust this with my production traces.* The interface should feel like a well-built instrument panel — dense, legible, never decorative.
- **Anti-personality**: no playful illustrations, no exclamation marks in CTAs, no "AI-y" gradients behind every headline, no anthropomorphised mascots.

## Aesthetic Direction

### Visual identity: **Signal Black (flat)** — live product / marketing / auth

- **Surfaces**: pure black only (`--bg` / `--eden-black` `#000000`). No graphite grey panels; elevation is gold wash (`--accent-muted`), not grey fill.
- **Accent (action)**: Signal Gold `#E8B84A` (`--eden-gold-400`) — primary buttons, focus, links. Hover `#F0C65C`. Never purple / cyan glow.
- **Live / running / success**: Verdant `#4ECF96` (`--eden-live-400`) — **status only**, never decorative.
- **Fail**: true red `#EF4444` — not dusty rose.
- **Text**: white → zinc ladder (`--eden-snow` → `--eden-dusk`). Borders: hairline white alpha (`--line`).
- **Type**:
  - Sans: **Geist Sans** (UI body, headings)
  - Mono: **Geist Mono** (micro-labels, code, status pills, terminal mock content)
  - Marketing micro-label: `font-mono uppercase tracking-[0.18em] text-[var(--text-faint)]` for `OBSERVE` / `EVALUATE` / `IMPROVE`
- **Shadows**: none on static marketing sections; auth card uses hairline border only.
- **Motion**:
  - Default 150–300ms with `--ease-out`
  - Auth brand panel ambient drift on a ~24s loop (sub-attentional)
  - `prefers-reduced-motion` disables ambient drift and hero entrance motion

### Mood references (intent, not pixel-matching)

- **Linear** — restraint, dense data tables, keyboard-first
- **Vercel dashboard** — black, sharp borders, monospace micro-labels
- **Raycast store** — focused ambient motion, no ambient decoration behind work
- **Stripe Sigma / Atlas** — instrument-panel precision
- **Terminal.app + VS Code dark+** — the colour anchors

### Anti-references (explicit non-goals)

- ❌ Gradient hero blobs behind headlines
- ❌ Pastel SaaS palettes
- ❌ Illustrations of cartoon robots / sparkles / smiling agents
- ❌ Drop-shadowed "neumorphic" cards
- ❌ Pillow-y rounded everything (`rounded-3xl` shapes, oversized blur)
- ❌ Phosphor green used decoratively (it means *active / running*)
- ❌ Borders below WCAG 3:1 (bumped in 2026-06 audit; do not regress)
- ❌ Arbitrary `z-9999` overlays (use the documented `--z-*` ladder)

## Design Principles

These five principles resolve every UI trade-off in this codebase. When two principles pull in opposite directions, resolve in this order: **legibility → precision → restraint → motion → coherence**.

### 1. Legibility beats decoration

Density is a feature, but only when every line can be read at speed.

- Borders must pass WCAG AA non-text contrast on every surface they touch.
- Body text must pass AA Normal contrast on its background.
- Micro-labels are a *recipe* (mono + uppercase + tracking-wide + muted colour), not just a smaller font — never reach for `text-[8px]` outside a terminal mock.

### 2. Token discipline: primitive → semantic → component

Consume tokens in order; never reference raw hex from a component.

1. **Primitive** — raw values (`--bg-base`, `--accent`, `--terminal`). Hex/size/duration definitions.
2. **Semantic** — intent (`--success`, `--border-default`, `--text-muted`). Components consume these. Re-theming swaps here.
3. **Component** — scoped recipes (`--auth-card`, `--node-agent`, `--code-surface`). Pre-resolved, self-contained.

shadcn-style legacy aliases exist (`--surface`, `--background`, `--foreground`, `--border`) and resolve correctly — leave them alone.

### 3. Active state is green, action is gold

Verdant green is non-negotiably "running / live / success". Signal gold is the action colour. Mixing these is a brand violation.

| Use | Token |
| --- | --- |
| Primary button, link, focus ring | `--accent` (gold) |
| Status: running, success, active | `--terminal` / `--success` (verdant) |
| Status: error / failed / warn | `--error` |
| Info callouts | `--info` (gold) |

### 4. Motion has a job

A transition should answer *"did something change?"* or *"where should I look?"* — never *"look how clever we are."*

- Default 150–200ms for state changes, 300ms for layout changes.
- Ambient motion (mesh drift, ticker sweeps, chart shimmer) is OK if it's slow, sub-attentional, and disables on `prefers-reduced-motion`.
- Never animate shadows into existence on mount.

### 5. Reused across surfaces

Marketing, portal, and docs share the same design tokens, type, and accent colours. A user moving from the landing page into the dashboard should feel the same product — not a marketing site pasted onto an app.

## Operating checklist for new UI

Before merging any front-end change, run this checklist. Items are written so an LLM can verify mechanically:

- [ ] Every colour comes from a token (search the diff for `#`-prefixed hex outside `globals.css` — none should appear).
- [ ] Every interactive element has a visible focus ring (use `--border-glow` or `--accent`).
- [ ] Borders on text/inputs are ≥ 3:1 contrast on their background.
- [ ] Body text is ≥ 4.5:1 on its background.
- [ ] No new `z-index` value outside the documented ladder (`z-base | z-sticky | z-dropdown | z-topbar | z-modal | z-overlay`). The grain overlay at z-9999 is a documented exception (pointer-events: none, aria-hidden).
- [ ] Phosphor green is reserved for active / running / success — never decorative.
- [ ] Micro-labels use the mono + uppercase + tracking-wide pattern; not raw `text-[Npx]` everywhere.
- [ ] Animation respects `prefers-reduced-motion` (mesh drift, shimmer, ticker sweeps).
- [ ] All copy is internationalised via `next-intl` (`useTranslations`); English + German keys present.
- [ ] New components added to `src/components/ui/index.ts`.
- [ ] No new shadow usage on static cards — `--shadow-lg/xl` reserved for floating surfaces.
