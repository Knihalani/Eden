# Eden Memory

Passive memory for Claude Code. Durable facts persist without `remember()`. Matching notes inject later. Broken Eden never blocks the agent: the hook exits 0 and prints nothing. `EDEN_MEMORY=0|readonly|on` (default on; `0`/`off` identity inject, no encode; `readonly` recall existing, no persist; any other value is off). Sleep: `EDEN_SLEEP_EVERY` unset → 32 turns (`0`/`off` disables; `"8"` turns; `"64k"` bytes). `EDEN_SLEEP_IDLE` unset → 5 min / 300000 ms (`0`/`off` disables). `EDEN_SLEEP_HEAVY` unset → 30 min / 1800000 ms of quiet before the idle sleeper mines the repo's files (`0`/`off`: only SessionStart's detached `eden sleep --heavy` mines). `EDEN_SLEEP_IDLE` `0`/`off` starts no detached sleeper at all, SessionStart's included, so only a manual `eden sleep` mines. `EDEN_SLEEP_BUDGET` unset → 25ms incremental budget. Unrelated math does not get sqlite `[fact]`. Store is JSONL under `EDEN_MEMORY_DIR` or `$EDEN_HOME/memory` (default `~/.eden/memory`), one store per repo: `<dir>/repos/<key>/`, keyed by the repo's common git dir, so every session, worktree and subagent of a repo shares it and two repos never do (outside git, by the folder a session starts in). The hook keys it by the event's `cwd`, the wrap (`processMemory()`) by the folder it runs in; a session's rows carry its episode `ep`. Each context window (`session_id`, or `session_id--agent_id` in a subagent) keeps its ledger in `<dir>/windows/<win>/`. Stores written before per-repo memory (one per session) move with `eden memory migrate` (`--dry-run` first). Retrieve k is `EDEN_MEMORY_CAP` (default 6), not store size; store cap (default 2000; `EDEN_MEMORY_STORE_CAP`). `EDEN_MEMORY_SESSION` or `EDEN_MEMORY_PARENT` names the session file; `EDEN_MEMORY_CHILD` opens the child file. `EDEN_MEMORY_LOG=1` prints note ids and ages to stderr (default off; the plugin's hook commands discard stderr, so use it with `eden hook` or in-process). `EDEN_MEMORY_INJECT_LOG` is an optional metric path (unset writes nothing). Dir `0700`, file `0600`. Silent inject only — no memory UI, no Letta tools in the default loop. Do not enable the plugin **and** `eden setup` — both attach UserPromptSubmit.

`/plugin marketplace add .` then `/plugin install eden-memory`. Needs Bun, and `bun install` in the checkout. `eden setup` installs the same hooks on Claude, Gemini, Codex, and OpenCode when present. Wrap injects the same store (`messages` or Gemini `contents[]`). Cursor-style and kebab OpenCode events work via hookd.

The hook loads Eden's memory hook from an Eden checkout into its own process. Claude Code runs an installed plugin from a copy in its plugin cache, so the hook looks for the checkout in this order: the checkout the plugin directory sits in (`--plugin-dir`), `EDEN_ROOT`, then the directory marketplace it was installed from. There is no slower fallback: no `eden hook` spawn, no hookd call. When Eden cannot load (no checkout found, or no `bun install`), the hook exits 0, prints nothing and logs the cause once to `$EDEN_HOME/plugin-fallback.jsonl`. `eden doctor --memory` shows whether the installed copy is current and loads Eden within the 150 ms Submit budget. After pulling a new plugin version, run `claude plugin marketplace update`, then `claude plugin update eden-memory@eden`.

hookd answers only callers that send its key, a new one it writes to `$EDEN_HOME/hookd.key` (mode
0600) each time it starts. The hooks `eden setup` writes read it there; the plugin never calls hookd.
Hooks written by an older `eden setup` do not send it and get `{}` from hookd: run `eden setup` again.

UserPromptSubmit / PreCompact inject then store. SessionStart briefs up to 3 pins for the likely scope and `Updated:` items on a startup or `/clear`, and the latest session gists (no pins) after a compaction, then stores — not last-k retrieve, not how-to; after `resume` or `fork` it brings nothing, as the session already holds its packets. Empty cue skips inject. PostToolBatch / Stop / SessionEnd / SubagentStop store only. What the window's instruction files already state is never injected: the files InstructionsLoaded reports (an async handler that only records their paths in `<dir>/windows/<win>/shadow.log`; files loaded lazily leave at a compaction or `/clear`), AGENTS.md where the project has no CLAUDE.md, and the auto-memory `MEMORY.md` beside the transcript. A compaction or `/clear` re-arms what the window was given, except what PostCompact's summary still names; a forked session copies its parent's ledger after its first turn, once its transcript names the parent. Each window reads its transcript once, line by line, from a mark in `<dir>/windows/<win>/hwm.json`; a rewind takes back what the abandoned turns said. Stop has two handlers: a sync `stop-fast` that keeps the agent's last message for the next prompt, and an async `stop-sleep` that stores the turn and rewrites the session gist. The full sleep runs in a detached `eden sleep --idle`, which Stop and SessionEnd start once the repo has no sleeper: it waits for `EDEN_SLEEP_IDLE` without hook activity in the repo (`0`/`off`: no idle sleeper). `EDEN_SLEEP_EVERY` and `EDEN_SLEEP_BUDGET` steer the wrap's in-process sleep; the hook never sleeps in-process. Repo facts (the package manager, node version, framework, test runner, auth SDK, database, CI, …) are mined from the repo's own files, each cited by the files that state it ("from pnpm-lock.yaml"); a later typed statement overrides one. SessionStart returns the cited files as `watchPaths`, and FileChanged re-reads them when one changes: a value the files no longer state is dropped.

**Delivery flags, observability and kill switches** (EXECUTION §5). Each delivery point has a flag, `off`, `shadow` or `on`, read on every event: `deliver.submit` (UserPromptSubmit) and `deliver.session_start` (SessionStart) default to `on`. Set them in `~/.eden/flags.json` (`$EDEN_HOME/flags.json`), override them per repo in `<repo>/.eden/flags.json`, or in the environment (`EDEN_FLAG_DELIVER_SUBMIT`, …). `off` delivers nothing and writes no ledger; `shadow` runs the whole pipeline, prints nothing, and records what it would have delivered in the window's `delivery.shadow.log`. An unknown value is `off` (`shadow` for `deliver.submit`). Every invocation appends one wide event (ids, hashes, counts, times; no text) to `hook.log.d/<date>.jsonl` under the memory root. An unhandled exception at an `on` point forces it to `shadow` for 24 h (`$EDEN_HOME/flags.auto.json`), and the next SessionStart says so once. The kill switches, narrowest first: a point's flag (next event), `EDEN_MEMORY=off` (next session), disabling the plugin or `disableAllHooks`. `eden doctor --memory` lists the flags, the breaker and the kill switches. A hook command ends in `2>/dev/null || true`, so even with no `bun` on PATH it exits 0 and prints nothing.
