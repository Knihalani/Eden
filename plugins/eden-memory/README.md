# Eden Memory

Passive memory for Claude Code. Durable facts persist without `remember()`. Matching notes inject later. Broken Eden never blocks the agent: the hook exits 0 and prints nothing. `EDEN_MEMORY=0|readonly|on` (default on; `0`/`off` identity inject, no encode; `readonly` recall existing, no persist). Sleep: `EDEN_SLEEP_EVERY` unset → 32 turns (`0`/`off` disables; `"8"` turns; `"64k"` bytes). `EDEN_SLEEP_IDLE` unset → 5 min / 300000 ms (`0`/`off` disables). `EDEN_SLEEP_BUDGET` unset → 25ms incremental budget. Unrelated math does not get sqlite `[fact]`. Store is JSONL under `EDEN_MEMORY_DIR` or `$EDEN_HOME/memory` (default `~/.eden/memory`). Wrap (`processMemory()`) uses `memories.jsonl` at that root. The Claude hook scopes a `session_id` to `<dir>/<session>/memories.jsonl` so episode `ep` survives spawn. Retrieve k is `EDEN_MEMORY_CAP` (default 6), not store size; store cap (default 2000; `EDEN_MEMORY_STORE_CAP`). `EDEN_MEMORY_SESSION` or `EDEN_MEMORY_PARENT` names the session file; `EDEN_MEMORY_CHILD` opens the child file. `EDEN_MEMORY_LOG=1` prints note ids and ages (default off). `EDEN_MEMORY_INJECT_LOG` is an optional metric path (unset writes nothing). Dir `0700`, file `0600`. Silent inject only — no memory UI, no Letta tools in the default loop. Do not enable the plugin **and** `eden setup` — both attach UserPromptSubmit.

`/plugin marketplace add .` then `/plugin install eden-memory`. Needs Bun, and `bun install` in the checkout. `eden setup` installs the same hooks on Claude, Gemini, Codex, and OpenCode when present. Wrap injects the same store (`messages` or Gemini `contents[]`). Cursor-style and kebab OpenCode events work via hookd.

The hook loads Eden's memory hook from an Eden checkout into its own process. Claude Code runs an installed plugin from a copy in its plugin cache, so the hook looks for the checkout in this order: the checkout the plugin directory sits in (`--plugin-dir`), `EDEN_ROOT`, then the directory marketplace it was installed from. There is no slower fallback: no `eden hook` spawn, no hookd call. When Eden cannot load (no checkout found, or no `bun install`), the hook exits 0, prints nothing and logs the cause once to `$EDEN_HOME/plugin-fallback.jsonl`. `eden doctor --memory` shows whether the installed copy is current and loads Eden within the 150 ms Submit budget. After pulling a new plugin version, run `claude plugin marketplace update`, then `claude plugin update eden-memory@eden`.

hookd answers only callers that send its key, a new one it writes to `$EDEN_HOME/hookd.key` (mode
0600) each time it starts. The hooks `eden setup` writes read it there; the plugin never calls hookd.
Hooks written by an older `eden setup` do not send it and get `{}` from hookd: run `eden setup` again.

UserPromptSubmit / PreCompact inject then store. SessionStart briefs pins and gists then stores — not last-k retrieve, not how-to. Empty cue skips inject. PostToolUse / Stop / SessionEnd / SubagentStop store only.
