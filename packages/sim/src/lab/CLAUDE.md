# packages/sim/src/lab — the benchmarks

Every number Eden is judged by comes from here: the hidden-context suites, the no-model funnel, the live agent A/Bs
on Pi and Hermes, the connector lab, and their reports. The runbook with copy-paste recipes and costs is
[docs/LAB.md](../../../../docs/LAB.md); this file is the map and the rules.

**Another session may be editing** `hidden-funnel, pi-ab, hermes-ab, hermes-host, hermes-proxy, hermes-worker,
cards-enrich, presets, suites, free, spend` (`.ts`): check `git log origin/main` before changing them.

## Rules

- **Never tune on held-out suites.** `heldout*` are measurement only; tune on `train` (the broad set) or
  `dev6a`/`dev6b`. Held-out 5–9 are contaminated (D80); 10 and 11 were run several times in the funnel (Haiku
  campaign); 12 was first read by a strong model in D98. A new blind round needs a new suite.
- **UNRUN_BLIND** keeps held-out suites out of `all` so a tuning command cannot spend them. Held-out 9–13 have all
  been read (D72, D80, D85, D98; held-out 13 backed D112 and the final live run), so none of them is blind: a blind
  round needs a new suite. funnel.ts says so when a run names one.
- **`--reader live` and `--judge live` keep the funnel to one process.** A live reader appends its top-up to one
  reader cache file and spends through one ledger stream; a parallel live top-up (per-process cache parts merged
  after, headroom split across processes) is not built. `--record` and `--timeline` keep one too (one ledger entry
  per suite; per-process CPU and RSS would be contended). Diagnostic output files shard (funnel.ts).
- **Free models (D91):** `<id>:free` needs `--allow-logging` (prompts are logged; sim data only); every request goes
  through one `Pacer` (default 18/min with a free model; the account allows about 20/min and 1,000/day, retries
  count); `--max-requests` caps a run, and a capped run is PARTIAL and not recorded.
- **Anthropic (D97):** a `claude-*` model needs `HAIKU_API_KEY` (or `ANTHROPIC_API_KEY`) and `--spend-ledger FILE
--spend-cap USD`, else the run stops before any call; parallel processes share one ledger, each keeping
  `--spend-headroom` clear. `--run-label` names a run's lines.
- **Live eval on Anthropic (`eval-live.ts`).** The shipped wiring (no judge, the servers' reader role from
  `modelRolesFromEnv`, `DEFAULT_CONFIG`) with only the transport swapped: Anthropic's Messages API direct instead of
  OpenRouter (D12's ZDR route, D95's throughput sort). Output says `provider: "anthropic-direct (lab, D97)"`; quote
  it as the same model family on another transport, never as production. The env handed to `modelRolesFromEnv`
  carries a placeholder OpenRouter key (its gate), never the real one, and `make` refuses any other. `--thinking off`
  (default) is the shipped request: since D144 `ModelReaderMaker` sends no reasoning, and thinking is disabled as in
  every lab reader run. `adaptive` is the effort-low arm D144 timed and rejected: the driver adds `reasoning: "low"`
  to each request (`effortLow`), because `AnthropicModel` sends `output_config.effort` only from it and would
  otherwise think at the model's default effort. It is slower: at the eval's default `--wait 2000` it lost 2 of 6
  calls to the wait (counted as reader failures, none logged; 0 at `--wait 10000`, 2026-11-05). Runs on 2026-11-05,
  ledger labels as named: `close-eval-live` (off) precision 0.8276, recall 0.48, falseFireRate 0, 6 reader calls,
  $0.00103. At `--wait 10000`, 6 calls each, 0 failures, the same three metrics in every arm: off
  (`close-eval-live-off-wt`) 1,191 output tokens, $0.00103; adaptive at effort low (`close-eval-live-adaptive-wt`)
  2,466 tokens, $0.00166; adaptive before this fix, default effort (`close-eval-live-adaptive-before-wt`) 3,640
  tokens, $0.00214.
- **`--cards-calls N`** (F2, D482; hidden-funnel after `--`, pi-ab): each user's card model answers its first N calls
  and leaves the rest uncovered (no call, no spend), standing in for a new user whose requests arrive before the
  backfill is read. Without it both harnesses wait for the enrichment to finish before the first request, so they
  cannot see what order the cards were made in. `--cards-rest cards` (N4, funnel only)
  answers the calls past N with their cards and no requests (a card-only model for the rest, the replayed cards
  standing in for it).
- **A stronger agent (N4, D520):** `--model claude-sonnet-5-5` or `claude-opus-5-5` changes only the Pi agent
  (`../../lab/n4/run.sh`). Opus 5.5 cannot run with thinking off: it runs `adaptive` at effort `low`
  (`anthropicThinkingOff`); say so beside its numbers. Budget about $0.009 (Sonnet) and $0.015 (Opus) a task run.
- **A killed paid run is resumed, not re-run (R4, D813).** pi-ab writes each finished unit (a task; a whole day under
  `--day`/`--days`) to `<out>.partial.jsonl` as it lands; the same command with `--resume` skips them at $0 (no model
  call, no ledger line) and merges them in; `spent`/`--budget` start from the journal's last spend note. A unit is
  reusable only under the same key (flags less outputs and caps, named files' contents, model env, tasks, harness and
  prompts hash, the `packages/` code with untracked files): anything else is refused, as is an existing journal
  without `--resume`, unknown code, or a journal another live process holds (`.lock`). A finished run deletes its
  journal. Reused units never reached Eden: under `--day`/`--days` an Eden arm needs `--resume-biased` and is marked
  BIASED in the results and reports. days-calls does the same per user beside
  `--json`; `lab_fanout.py --resume` re-launches only the shards that have not returned (docs/LAB.md 4 and 7).
  A harness that gains a unit of work journals it the same way, and a new input that decides a unit joins the key.
- **No OpenRouter from the lab (D818).** Every script under packages/sim/ refuses to start while `OPENROUTER_API_KEY`
  is set (bunfig.toml's preload, `scripts/lab-guard.ts`), unless `EDEN_ALLOW_OPENROUTER=1` for a run the owner
  approved: run the lab with `env -u OPENROUTER_API_KEY` or after `unset OPENROUTER_API_KEY`.
- **Keys** are read by `keyFor`, never printed or put in results.
- **Budgets:** every live run passes `--budget` (a hard cap per process on everything it spends).
- **Strict CLIs (audit 2026-11-03b).** funnel.ts, hidden-funnel.ts and quality-cli.ts parse through `flags()`; a new
  flag is added to the CLI's `known` list or it exits 2. Engine settings (`--config`, `--set`, the preset merged with
  them) go through `labConfig`/`checkEngineConfig`: unknown keys, wrong types, out-of-range numbers and a child flag
  whose parent flag the merged configuration has off (`PARENTS`, e.g. `syncPollBehind` without `sync`) exit 2.
  gate-traffic.ts, the A/B harnesses and eval's cli.ts do not use it yet; eval-live.ts does.
- **Record honestly:** funnel and `bench.ts` record to `bench/ledger.jsonl` unless `--no-record` (`bun run funnel`
  does not record unless `--record`); a run on a dirty tree is marked `dirty`.

## Pitfalls seen in this repo

- **One seed per `pi-ab.ts` process.** One process for four seeds over nine suites was killed for memory (14 GB;
  docs/research/pi-full-benchmark.md); the Haiku campaign ran three processes at once, RSS up to 3.35 GB each. With
  `--noise-sources 995` (D357) run one process at a time: two at once were killed on 15 GiB (A21).
- The default needs `--cards`, `--intent` (requests replayed) and a reader for its model parts; without them they are
  inert (the funnel screens with `--reader stub` when none is named). `bun run funnel` passes the checked-in cards
  and, since D158, the checked-in intent requests (train seeds 41–44, held-out 10–11 seeds 41–42, held-out 13 seeds
  41–44; INTENT_COVERS in cards-disk.ts) itself; a run outside that coverage, or with `--intent none`, is intent
  inert and every TOTAL line says so. **pi-ab and hermes-ab do the same since 2026-11-06** (with `--cards` and intent
  on, the covering file is replayed by default; the header prints `intent: replayed n of m items` or
  `[intent inert: no replay]`). Before that they replayed no requests unless `--intent` was given, so every held-out
  13 Pi/Hermes figure up to then (the final live run, the D159 pair) had requests only for items carded live: intent
  inert for about two thirds of items (estimate, docs/research/edge-intent.md). `--cards-out` now keeps a live call's
  requests (`{h, c, r}`) and replays them, only when a requests file is replayed: `--intent none` and an uncovered
  run skip those `r` lines (`cardRequests: false`), so they replay nothing and the inert label (0 found) is true.
  Numbers recorded before D158 (214/211 stub, 247/127 replayed, D112–D153) are intent-inert ones: compare like with
  like. Read settings through `effective()`: a preset is an
  override, and `default` is `{}`. The harnesses wait 3,000 ms on the first observe (`@w<ms>` changes it; 1 s lost
  7.6–18.1 points, D98).
- Pi's `both` arm gets no `ask_context` (only `eden` does); `both+ask` (fix-s3b) adds it, the shape integrators ship;
  Hermes gets both. `--day K` runs K requests per agent session (`pi-day.ts`), with a recap turn that is never
  graded. After the change notices before the recap it waits up to 10 s for `revisionsSettled` (D205's background
  poll), standing in for the two hours between change and recap; `DaySummary.updatePackets` counts "updated:" packets.
  The change lands just before the recap, so a lever that re-sends an update at the recap repeats the packet the agent
  has just read (D341); `staleHanded`/`staleUpdated` say whether a stale recap's item was handed and updated that day.
- **`--days` intervals** (N3, D519): a day's requests share one transcript, so pair with whole days resampled
  (`../../lab/n3/day-cluster.py`); an arm that changed nothing differed from its twin over two users (asks +0.06 a
  task, $ +0.015/1k, intervals excluding zero). `--late` on train costs about $0.48 a shard: a lower cap cuts every
  stream's later days (`../../lab/n3/late.py` counts whole days only). `../../lab/n3/stems.sh RUN` turns a Modal
  fan-out's shards into the `STEM.json`/`STEM.tl` pairs the Python reports read.
- **Position in the day** (A17): `../../lab/a17/days.py` reads `--days` runs per position bucket and pairs arms task by
  task (it needs `--timeline`). One request a session (the funnel, short pi-ab) cannot see D340's re-show: screen it on
  `--days` only.
- **pi-ab and hermes-ab default to `--time-scale 1`** (since 2026-11-03): sources take their profiles' assumed
  latency, so the "Eden on the critical path" column includes the on-demand sync poll. Earlier results (every
  haiku-phase3 row) ran at 0, connectors instant; compare like with like. Use 0 only for a stated quality-only rerun.
  In the funnel the poll was about 91% of ALL3's critical path at `--time 1`; ALL3B cut ms/task 481.8 to 26.5 on
  train1–6 seeds 41–42 with an empty task-by-task diff (docs/research/haiku-phase3.md, note of 2026-11-03).
  Any pi-ab/hermes-ab Reproduce command dated before 2026-11-03 (hermes-lab.md, haiku-benchmark.md, edge-combined.md,
  edge-freelab.md and the rest) needs `--time-scale 0` added to reproduce its numbers: at 1 the tools conditions
  also get connector errors and per-second rate limits (sources.ts). `lab/haiku/run.sh` and `run-w.sh` pin 0.
- `--cards FILE` is only read; new cards go to `--cards-out` (default `<out>.cards.jsonl`): name it in later runs.
- Hermes needs a hermes-agent checkout with `<src>/.venv` (`uv sync --frozen --no-install-project`); the first task
  of each stream pays worker start-up (exclude it from wall times).
- Free and paid runs (and different graders) are not comparable: compare conditions within one run.
- **Pay once (`pi-ab.ts`):** `--replay DIR` replays the reader's and grader's calls (`DIR/{reader,grader}.jsonl`,
  keyed on the exact prompt, model, harness version, provider preferences and role) and appends new ones;
  `--replay-only` exits 3 on a miss; `--replay-timing` sleeps the recorded latency (without it, replayed calls take
  no time and the critical path understates Eden). `--reuse-arms F` copies `none`/`tools` from a matching earlier
  run (same model, grader, harness version, agent and grader prompts, time scale, seeds, suites, task wording; else
  it refuses). The prompts are checked by `promptsHash` (`armPromptsHash` in ab-common.ts: the system prompt, user
  turn, search tool, caps and grader prompt on a fixed probe); a results file without one cannot be reused. Both
  freeze one sample: fine for paired comparisons, but a variance estimate needs them off. The agent itself still runs
  live, and Hermes has neither yet (ab-replay.test.ts).
- **Report cost columns:** `(Eden)` is per-task calls only (reader, judge). Cards and bridge are booked to Eden's
  total but to no task: `bkfill` spreads each seed's background spend over its task runs with cards or bridge on,
  and `all-in` adds it. A stream's background spend is recorded as it happens, so a stream stopped early (budget,
  request cap) still counts. Reports from before 2026-11-03 lack it: `pi-ab-report.ts --reconcile report.txt
--ledger ledger-summary.jsonl --run PREFIX` recomputes it from the spend ledger (docs/research/haiku-phase3.md)
  and exits 1 when the columns miss the header's Eden total by more than $0.01.
- Funnel decoys surfaced overstate harm: live agents reject most decoys (docs/research/broad-set.md).
- **Live false concerns overstate harm too** (fix-w2b): 15 of 39 Haiku-graded control and neutral concerns were the
  grader's errors (a hedge, or an answer saying the opposite). Regrade the concerns (`regrade.ts --only-concerns`)
  and read them before acting on a false-concern difference; `fix-w2b/attribute.py` says how each decoy arrived.
- **`bun run funnel`'s ms/task is CONTENDED by default** (D139, since 2026-11-05): at `--time 0` it runs one process
  per core over blocks of suites × seeds. Quote latency, or diff ms/task against a `--baseline`, only from `--jobs 1`
  on both sides; the counts and the score do not depend on it (768 of 768 perTask rows identical).
- A wrapper around a sim source must copy `notifies` (and `listsByTime`) or `--push` silently does nothing: pi-ab's
  timing wrapper dropped it once, and the run polled as if no source notified.
- Hermes needs its `mcp` extra (`uv sync --frozen --no-install-project --extra mcp`), else "Hermes has no ask_context".
