# Ingest

User-Agent: `Edenbot/0.1` (`src/ua.ts`). **Code is private.** Dumps: [data.md](data.md).

Start from known seeds (catalogs, Wikipedia, arXiv, PubMed/PMC, OpenAlex, DOAJ, Semantic Scholar), then expand to **every robots-ok URL** (RFC 9309, including `*` and `$` path patterns). Live fetch is parallel (default 96 URLs/tick, 64 in flight, 3 per host). Live ticks prefetch robots.txt for unique origins before those fetches. The always-on worker takes two latest-crawl WET files per tick (fetch in parallel, commit serially). Gzip is requested as identity. Each WET GET uses HTTP Range `bytes=0-(EDEN_KNOW_WET_BYTES-1)` (default 8 MiB; 416 falls back to a capped GET). Outlinks from a fetched page join the frontier if they are not listed paywalls and not news/blog junk — catalog hosts are not required. Each tick also batches Wikipedia country articles (Action API, up to 50 titles), re-queues pages past TTL, and re-polls origin sitemaps daily (lastmod-first, sitemapindex children, maps fetched together). Common Crawl WET fills volume (default 120 kept records; each file is scanned 40× deeper than the keep cap, or `EDEN_KNOW_WET_SCAN`). Production scan is 2000 records. URIs that `keepWet` would reject from the header (paywall host, already digested, junk TLD, Content-Length < 80) skip UTF-8 decode. Gzip leftover grows geometrically instead of recopying the whole buffer each chunk. Truncated gzip prefixes inflate with `Z_SYNC_FLUSH`. The parser yields to the event loop at most every 100 ms. N ingest boxes partition `wet.paths` (`shardWetIndex`) and live URLs (`shardOwns`) with no overlap. The worker answers `GET /health` in a parent process; the tick runs in a child so a WET scan cannot starve probes. CDX remembers the query variant that last hit per host. Wikidata SPARQL is not fetched (robots-disallowed); capitals come from synth. CC-NEWS runs from `tick()` (`--news`). Wikipedia-family hosts are in. Listed paywalls are out. News/blog feeds are not — they starve the catalog frontier.

JS-heavy pages use JSON-LD / Open Graph / `<noscript>` in the first HTML. No Playwright. No generic RDF/XML, Turtle, or RFC PDF extract. Wikipedia infoboxes accept table rows **and** `infobox-label`/`infobox-data` divs. Overlay RFC `is` objects may be 96 characters (same as persistable).

Catalog XML/JSON still runs (RFC, W3C, IANA, SPDX, Unicode) as high-rank seeds, not as an allowlist. They are not re-downloaded every 20s: a successful catalog fetch is remembered for six hours, and `If-None-Match` is sent on the stream path. Catalog fetches run in parallel with a Wikipedia Action API batch (up to 50 titles). Stream catalogs enqueue HTTP `Link` targets; they do not fold HTML into XML. Compact publishes the overlay into the single `graph.kpk` when the WAL is due (default every 3 minutes, or immediately at 512 overlay nodes). After compact, crawl.bin keeps up to 8,000 frontier URLs and 8,000 page rows (catalog/wiki first) so a restart does not forget the crawl.
