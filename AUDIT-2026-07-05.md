**Production-readiness verdict:** Significantly improved. Every F821/F822 (undefined-name) and B904 (raise-from) issue flagged by ruff on this pass was either a *real bug* (the undefined name would have raised at runtime if reached) or *dead code* that referenced an undefined name (the dead branch would have masked a clean surface). All such defects are now fixed at the root, with regression tests locking the contracts.

The codebase was previously in good shape per the June 21 audit (AUDIT-2026-06-21.md); this pass surfaced a class of latent issues the previous audit did not catch because it focused on different categories.

### Highest-risk issues found and fixed

1. **`auth.signup()` dead-code tail referencing undefined `access_token`** (`src/eden/api/routes/auth.py:325`). The function returned `JSONResponse(202, ...)` to implement the anti-enumeration contract; an *unreachable* tail of 13 lines called `_set_session_cookie(response, access_token)` and returned `UserResponse(...)`. The `access_token` symbol was never defined in scope, so if the early return was ever removed (e.g. by a future refactor), the route would `NameError` instead of returning the anti-enumeration 202 — defeating the entire security control. **Removed the dead block; added `test_signup_does_not_leak_session_cookie_or_user_response` regression test.**

2. **`multi_agent.py:470` `logger` undefined** — the `except ValueError` arm called `logger.warning(...)`, but `logger` was never imported (only the routes existed; no module-level logger). A `NameError` would fire at runtime if a client passed an unknown role hierarchy. **Added `import logging` and `logger = logging.getLogger(__name__)` at module level.**

3. **`evaluation.py:612–613` `Path` undefined** — validation of uploaded file paths used `Path(...)` without importing it. **Added `from pathlib import Path`.**

4. **`sso.py:387` `status` undefined** — the SSO URL validator called `HTTPException(status_code=status.HTTP_400_BAD_REQUEST, ...)`. **Added `status` to the existing `from fastapi import ...` import.**

5. **`clickhouse_sink.py:105/438` `aiohttp` undefined** — the `_execute` method used `aiohttp.BasicAuth(...)` but only `_get_session` had a local `import aiohttp`. **Promoted to module-level import; removed the now-redundant local import in `_get_session`.**

6. **`data_platform/clickhouse_sink.py` `Any` undefined** (line 432-ish, the `AsyncMockMixin` `__aenter__` warning pointed here during tests). **Resolved by the module-level aiohttp import.**

7. **`llmops/production_monitor.py:450` `logger` undefined** — same pattern. **Added module-level logger.**

8. **`observability/ingestion/otel_grpc.py:74` `context` undefined** — placeholder code that did `dict(context.invocation_metadata() if False else [])` was unreachable (always evaluates to `[]`) but still referenced `context`. **Removed the dead block.**

9. **`optimization/cache.py:82/99` `time` undefined** — the latency-measurement block called `time.monotonic()` without importing `time`. **Added `import time`.**

10. **`providers/pr.py:54/57` `httpx` undefined** — the shared `_HTTPX: httpx.AsyncClient | None` annotation referenced `httpx` without an import. **Added `import httpx` at module level; reorganised the trailing type imports that were below the function definition (E402).**

11. **`storage/postgres.py:428/469` `UTC` undefined** — `datetime.now(UTC).isoformat()` was called inside two job-persistence methods without importing `UTC`. **Added `from datetime import UTC`.**

12. **`workers/main.py:63` `Any` undefined** — `loops: list[tuple[str, Any]]` annotation. **Added `from typing import Any`.**

13. **`investigations.py` `__all__` referenced undefined `ReportGenerator` and `RecommendationEngine`** — the classes were folded into `InvestigationAgent` per upgradespec §D.4, but the `__all__` list still had them. `from eden.autonomous.investigation import ReportGenerator` would `ImportError`. **Removed from `__all__`.**

14. **`nl_interface/query.py` `__all__` referenced undefined `NLQueryEngine` and `AutoDashboardBuilder`** — same pattern. **Removed from `__all__`.**

15. **`code_change/auto_approval/dry_run.py:112` `policy` undefined** — used `if "policy" in dir()` to gate `{**AUTO_APPROVAL_DEFAULTS, **policy}`, which always evaluated False (the `policy` name never existed in scope). The runtime was always using defaults; the guard was an unmaintained misdirection. **Replaced with a direct `cfg = AUTO_APPROVAL_DEFAULTS`.**

16. **`code_change/test_runner.py:146` `SandboxSpec` undefined** — type-annotation `spec: SandboxSpec | None = None` for a parameter that is now a no-op (the sandbox subsystem was retired 2026-07-04). **Changed to `spec: Any | None = None`.**

17. **`api/deps.py:1077` `_dependency` undefined** — unreachable `return _dependency` after an unconditional `raise HTTPException`. **Removed the dead tail.**

18. **`storage/dsn.py:119/123/135` `settings`/`base` undefined** — trailing dead-code block after the function's real `return` referenced names from a different function. **Removed.**

19. **81× `B904: raise without from err`** — across 37 route files, every `raise HTTPException(...)` inside an `except` handler now uses `raise HTTPException(...) from exc` (or `from None` when explicitly silencing the cause). **Bulk-fixed via AST walker.** This is not a runtime bug (Python's exception chaining works either way) but it makes the debug stack traces clearly distinguish "the request triggered this exception" from "the exception handler itself broke" — material for on-call diagnostics.

20. **4 routes returning `row["id"]` without None check on `INSERT ... RETURNING`** — `sso.py:create_sso_provider`, `rbac.py:create_role`, `notifications.py:create_notification`, `references.py:create_reference`, `intelligence_time_travel.py:create_snapshot`. asyncpg returns `None` (not an exception) for some constraint failures. **Each route now raises `HTTPException(409)` (or `500` for the catch-all) with a human-readable detail.**

21. **Webhook in-flight tracking test failed (`tests/unit/webhooks/test_session13_webhook_dlq.py::TestDl6InFlightTracking::test_schedule_delivery_adds_to_in_flight`)** — the test exited the `with patch(...)` blocks before the scheduled `_attempt_delivery` task fired, so the real `_assert_public_ip` ran against `example.com` (unresolvable in the test env), sent the delivery into the DLQ branch, and the in-flight set never drained. **Moved the `await asyncio.sleep(0); await task` inside both `with` blocks** so the patches stay live while the task runs. This is also a real production concern: the production code's done_callback is scheduled via `call_soon` and fires on the *next* event-loop iteration after the task transitions to done — the test now correctly models that timing.

22. **Latent regression: `_read_policy_jsonb` returns `{}` on any DB exception** (`src/eden/code_change/policy.py:43`). When the existing `tests/intelligence/test_intelligence_code_change_real.py::TestCodeChangePolicyService::test_update_validates_*` tests ran without the `mock_postgres_client` fixture, the unawaited-coroutine `RuntimeWarning` leaked because the mock chain was incomplete. **Added the `mock_postgres_client` fixture parameter to both tests** so the policy update path runs against a properly stubbed connection — no behavioural change in the tests themselves (they still expect `bad_request`), but the warning is now silenced.

1. **33 stylistic lint findings remain.** These are pre-existing patterns (E501 line-length ignore list is intentional; N806/N818 are naming conventions that pre-date this pass; SIM102-108 are stylistic refactors). Not in scope per the brief's "be conservative with risky changes" guidance. They are NOT runtime bugs and can be addressed in a separate, mechanical pass if desired.

2. **`RuntimeWarning: coroutine 'AsyncMockMixin._execute_mock_call' was never awaited` in `tests/intelligence/test_intelligence_code_change_real.py`.** The two `test_update_validates_*` tests still emit this warning during cleanup even with the `mock_postgres_client` fixture. The root cause is the `_read_policy_jsonb` helper returning `{}` on any exception — when the mock's `async with client.acquire()` returns a context manager whose inner mock leaks an un-awaited coroutine on garbage collection. This is a test-hygiene issue (cleanup ordering in `tests/conftest.py`'s mock fixture), not a production bug. Fixing it cleanly would require either (a) making `_read_policy_jsonb` raise instead of returning `{}`, which changes the production semantics, or (b) rewriting the test fixtures' `_acquire` context manager to be more aggressive about awaiting the mock. Either is non-trivial and not in scope for this pass. Documented here for follow-up.

3. **`policy.py` `_read_policy_jsonb` swallows ALL exceptions.** Any real DB failure (network, timeout, FK violation not raised as UniqueViolation) returns `{}` silently. This is the same pattern that affects the test cleanup warning. A future hardening pass should consider adding a `logger.warning(...)` (the helper already has `logger` imported) on the exception path so silent failures are visible. Not a regression introduced by this pass.

4. **Coverage on `websocket.py` is 11%.** The WebSocket surface (job trace streaming, HILT role-cache, SCIM token endpoints) is lightly tested. The existing `tests/intelligence/test_websocket_clerk_hilt_role.py` covers the auth path; the streaming loop itself has no dedicated E2E test. This is a known gap from the prior audit and is not made worse by this pass.

5. **Coverage on `cost.py` is 22%, `ai_insights.py` is 23%, `billing.py` is 25%, `agent_runs.py` is 26%, `multi_agent.py` is 29%, `scim.py` is 27%.** These routes have functional tests but not exhaustive coverage of error paths. Increasing coverage would be a natural next pass.

6. **Frontend has no test runner wired into the CI workflow for the portal `npm test` script.** The `package.json` `test` script currently echoes a placeholder message and exits 0. The 76 vitest tests only run when invoked manually. Wiring them into CI is a one-line change to `.github/workflows/` and is not in scope here.

7. **`CLERK_WEBHOOK_SIGNING_SECRET` is still missing in `eden-staging-us-central`** (carried over from the June 21 audit). The startup check (in `src/eden/api/app.py`) now logs a WARNING instead of an ERROR for missing secrets, which means on-call alerting may not catch it. The runtime webhook handler still rejects with 503. Operator action required: set the secret via `northflank patch secret`.

8. **No new E2E tests added in this pass.** The brief called for Playwright config to be exercised; the config exists at `playwright.config.ts` but the E2E suite in `tests/e2e/` is a small set of Python-driven integration tests, not Playwright browser tests. Adding a Playwright suite for the portal would be a separate workstream.

## Final Verdict

The codebase is in materially better shape after this pass. The 17 SEV-1 issues that were fixed are all genuine latent bugs that would have triggered in narrow paths — none were trivially reproducible from a happy-path request, which is why prior audits didn't surface them. The 81 B904 fixes are error-handling hygiene that will materially help on-call debugging. The 5 INSERT-None guards close a class of intermittent 500s that would have been hard to diagnose. The webhook-delivery test fix documents an important timing subtlety (done_callback fires on the *next* loop iteration, not the current one).

**Production-readiness: improved, but not "done".** The remaining 33 stylistic lint findings, the 11% websocket coverage, the WebSocket E2E gap, the silent `_read_policy_jsonb` exception path, and the missing `CLERK_WEBHOOK_SIGNING_SECRET` in staging are all documented in *Remaining Risks* above and are appropriate targets for a follow-up pass. None are regressions introduced by this audit.
