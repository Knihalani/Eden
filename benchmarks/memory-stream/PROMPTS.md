# Prompts used by StreamBench's model-run steps (for reproducibility; critic C2)

Each step's full prompt template, with `<batch>` / `<world>` placeholders.

| Step | Model | Template |
|---|---|---|
| Stream authors (`AUTHORING.md`, `briefs/`) | the session's default model (Claude Code subagents; model id not recorded per batch, a known gap) | "You are a stream author for StreamBench … Read AUTHORING.md, the world bible, your batch brief … Hard rules: one human event per planned turn …; state beats carry every specific token …; need beats must not contain the needed item's tokens …" |
| Sleep compiler (`SLEEP-SPEC.md`) | sonnet | "You are a sleep compiler … Read SLEEP-SPEC.md (follow it exactly), then your input … Be selective: durable facts, preferences, rules, plans, decisions, gotchas only, with rich `when` cues …" |
| Self-play (`selfplay.py`) | haiku | "For EACH row, write `pos`: 6 short, realistic prompts … where a careful assistant would NEED this memory, but the prompt must NOT mention or restate the memory's content …; `neg`: 6 realistic near-miss prompts … where the memory is NOT needed." |
| Judge ceiling (`judge.py`) | opus (session default) | "For each case, decide which memory rows a careful expert assistant would want injected into its context RIGHT NOW to act well on this turn, including proactive needs. Pick NONE when nothing is needed (the common case) … never more than 4." |
| Independent labeler (`label.py`) | sonnet | "List the item ids that a careful expert assistant would NEED in context to do this turn right: the item changes what the agent should say or do … STRICT: do NOT label items that are merely on-topic … most turns need nothing … Typical: 0 items; rarely more than 3." |
| Agent-pull host (`agentpull.py`) | sonnet | "You are simulating a coding agent (life: a personal AI assistant for Riya) that has a memory tool … decide, as a good agent would before acting: do you need to look something up in long-term memory to do THIS turn right …? Call the tool only when it would plausibly change what you do; most turns … need no lookup. If you call, write a short search query." Batched: 55–60 cases per subagent prompt, which is not a turn-by-turn host (critic C2, §1d). |
| Coverage check (C2-E2) | sonnet | "For each case decide which candidate facts the bullet actually CONVEYS … mentioning the same topic is not enough; a bullet that states an older/different value does NOT convey the fact." |
| Prompt rewriter (`rewrite.py`) | sonnet | "Rewrite each prompt as Jordan (life: Riya) would actually type it: shorter, telegraphic … keeping the same intent and every `keep` token … never include `avoid` tokens; pastes keep their body verbatim." |
| Haiku whole-store judge (C4-E7, `judge.py` tag `haiku`) | haiku | Same template as the judge ceiling, 15 cases per call. |
| F22 verifier (`verify.py`) | haiku | "For each case pick the candidate memory rows a careful assistant would want in context to act well on THIS turn, including proactive needs the user did not ask about. Pick none when nothing is needed (the common case); never more than 4." 50 cases per call, so later cases were visible (C4-E6). |
| F22 verifier, leak-free (`verify.py --per 1 --tag seq`, C4-E9) | haiku | Same template as the F22 verifier, one case per file in stream order: "Process the files … ONE AT A TIME, in numeric order. Read only the file you are processing; never open a later file ahead of time … pick the candidate memory rows a careful assistant would want in context to act well on THIS turn, including proactive needs … Pick none when nothing is needed (the common case); never more than 4." |
| F22b calibrated verifier (`verify.py --per 1 --tag cal --contrast 8`, C4-E11) | haiku | "Each file has one case: … `earlier_turns` (some of this user's ordinary turns from earlier sessions, for calibration: most turns like these need no long-term memory at all), `candidates` … For EACH candidate, give the probability (0.0–1.0, one decimal) that a careful assistant needs that row in context to act well on THIS turn — it changes what the assistant should say or do, including proactively. Being on-topic is not enough. Compared with the earlier turns, ask whether this turn is special. Most rows should be ≤ 0.2; most turns have no row above 0.5." Output `{"scores": {row id: p}}`; one case per file, stream order. |
| Judge ceiling, one case per call (`judge.py prep-seq`, C4-E12) | opus | Same template as the judge ceiling; one case per file with the store visible at its own moment, in stream order. |
| Anticipation (`anticipate.py`) | sonnet | "From the session so far and the store, predict up to k memories the NEXT moment may need, each with 2–5 short trigger phrases (or `always`). You never see the next message." |
| Red-team author (`redteam.py`) | session default | "Write new sessions continuing the world after its last session: hard but realistic turns (short, telegraphic, indirect needs, near misses), each human and trigger event labelled with the item ids it needs, or `neg`." |
| Draft checker (`draftcheck.py`, C4-E8) | haiku | "You are Eden, the user's memory, reviewing the assistant's draft reply before the user sees it. You see the turn, the recent context, the draft and up to 15 candidate memory rows. Block ONLY if the draft contradicts a row, or misses a row the user would clearly expect the assistant to know and that changes what it should say or do. On-topic but unneeded rows are not a reason; most drafts pass. If you block, list the row ids (≤ 3) and a one-line note to the assistant." One case per file, in stream order. |
| Draft reviser (`draftcheck.py`) | sonnet | "Revise your draft reply using the memory note and rows. Keep it as short as the draft; change only what the memory changes." |
| Downstream responder (`downstream.py items`, C4-E10) | sonnet | "Items are independent: answer each as a separate run where that packet is the ONLY long-term memory you have. Write the assistant's next reply: 1–4 sentences, then `Action: …`. Use packet facts only where they matter; never invent specific facts … say you'd check instead." One item per (turn, packet), shuffled, with its own id. The earlier list-of-packets form swapped the order on 13 of 45 life and 4 of 45 code cases. |
| Downstream judge with history (`downstream.py judge-prep`, `draftcheck.py judge-prep`) | opus | "Score EACH response 0–3 … `history_evidence` (dated excerpts of EARLIER sessions; true records of what happened then, though later ones can supersede) … A claim supported by the history evidence is NOT a fabrication; judge only whether it is still current and relevant." The evidence is a greedy idf cover (`evidence.py`) of the rare tokens the responses add to the turn. |
| Cross-batch supersession (`supersede.py`, C5-E5) | sonnet | "For each new row, find the older rows it REPLACES: the new row corrects the older fact, records that the state it describes changed (e.g. a migration, a new version, a renamed thing), marks the older task/plan as done or cancelled, or moves a date/time. Do NOT pair rows that merely add detail, are on the same topic but both still true, or describe different things. When unsure, do not pair. A partial replacement still counts if any specific claim in the older row is now false." Output `{"superseded": [{old, new, why}]}`; one batch per file (new rows + older live rows). |
| Dated delivery (`downstream.py prep-verify --dated`, `prep-h2h`, C5-E6/E7) | — (format) | Each delivered row is prefixed `[as of YYYY-MM-DD]`: for verifier rows, the date of the row's strict visibility time (its batch's last session); for eden bullets, the session date of the first earlier event containing the bullet. Responder prompt unchanged ("packet … long-term memory notes"). |
| Blank-slate designer (cycle 3) | session default | No access to STATE, LEDGER, the methods, or the sleep/self-play/judge artifacts; builds `methods_blank.py` from the raw stream and the stores only. |

All generators are Claude models. A non-Claude generator for a holdout is still open (BRIEF §4.9).
