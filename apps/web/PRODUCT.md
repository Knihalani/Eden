# Product

## Register

Landing is **brand**. The signed-in app is **product**. Do not mix: the public page is allowed to be cinematic; the dashboard is not.

## Users

Agent builders — solo or on a team. They sign up, wrap their agent, then use Eden as a product: see what compiled, review a request, edit the graph, Approve. The UI talks like a product, not like a compiler. Ease of reading still matters for people sitting next to the builder.

## Product Purpose

Tagline: **Making your agents more deterministic.** Compiling repeating agent tools (with a human Approve before they go live) is the first product, not the whole story.

Public site is a landing page whose job is Sign up. First session is a short onboarding panel that ends on a copy-paste setup prompt. After that they land on a **dashboard**, not a canvas: proof of activity (live tools, compiled runs, waiting, failed), the workflows they already have, and compile requests waiting. Opening a workflow or a request opens the **canvas**, where the graph is the editor. Click a node for a detail panel. Drag and edit, then Approve. **Approve** is where tokens saved, time saved, and measured quality appear — from the shadow counterfactual, never an `×` LLM-call ratio, never invented. A runtime key never turns a tool On.

Landing copy is **promise only**. Lead with the tagline. No invented metrics, logos, quotes, or customer counts. No internals (wrap mechanics, shadow runs, compiler, how runtime keys work).

## Brand Personality

Night desk. Quiet, exact, one ship accent. Closer to Linear/Vercel dark than a terminal. **Crimson** for Sign up and Approve only — cool red, high chroma, not ochre, not coral-orange, not gold-portal foil. Live is Pause / Resume in type, not a second hue. Same hexagonal **e**. Not gold, mint, lavender, ice, cyan, or ochre. Dashboard has no ship color.

## Anti-references

Signal Black + gold portal. IBM Plex wireframes. Fraunces highlighter-E. Cream paper. KPI card grids. Neon cyan-on-dark. Linear lavender `#5e6ad2`. Mint / garden / hue 155. Coral hue 32. Ice hue 250. Ochre / amber hue 78. Tables as Approve UI. Huge empty heroes. Glassmorphism stacks. Green success. Forced 12-step tooltip tours. Empty canvas as the first screen after signup. Fake social proof. Bounce/particle/gradient-text landing slop.

## Design Principles

1. Landing → account → short tour → setup prompt → **dashboard**. Canvas is a drill-in, not home.
2. Same `logo.webp`. Never redraw the mark.
3. Approve happens on the canvas after editing the graph. One chromatic CTA (crimson).
4. Flattened chrome: luminance stacking and hairlines, not nested cards or drop-shadow stacks.
5. A runtime key never turns a tool On.
6. Setup prompt defaults to placeholders. Including real env vars is an explicit extra action, with a way to strip them again.
7. Organizations from day one (a workspace, even if it is one person).
8. If it cannot be proven, it is not on the landing page.

## Accessibility & Inclusion

WCAG AA for body and muted text. Reduced motion disables landing scroll tricks, tour animation, pulse, and transitions — conversion path stays. Focus-visible rings on the crimson accent. Color is never the only state signal. Onboarding can be skipped.
