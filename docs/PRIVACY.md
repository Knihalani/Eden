# Privacy, security and subprocessors

Eden reads the most sensitive data a person has (mail, calendar, documents) on behalf of a tenant's agent. The
tenant's end users must be told Eden processes their data, and Eden in turn uses a model provider. This document
is the engineering side of that story. It is not legal advice and not a certification. Never claim "Eden is ZDR".

## Subprocessors (current design)

1. **OpenRouter**, routing to a model provider for the default's model roles (cards, intent requests, the ask-time
   reader; D112), by default Anthropic's Claude Haiku 5.5 (`EDEN_MODEL`, default `anthropic/claude-haiku-5.5`). They
   run only when `OPENROUTER_API_KEY` is set; without it no text leaves Eden for a model. Requests set
   `provider.data_collection: "deny"` and `provider.zdr: true`. **To verify before launch:** that these fields are honoured as named on OpenRouter's current
   API (the smoke test on 2026-10-27 shows the API accepted the request, not that routing was restricted), which
   providers serve the model under ZDR, and OpenRouter's own retention terms.
   **Lab only (D91):** the lab's runs on OpenRouter's free models set `OpenRouterOptions.allowLogging`, which sends
   `data_collection: "allow"` and `zdr: false`, because no free endpoint is zero-retention. Only lab scripts set it
   (`--allow-logging`, required whenever a `:free` model is named), only over generated sim worlds, never real user
   data. `OpenRouterModel.fromEnv`, the engine and the server never set it; tests pin that `fromEnv` sends "deny"
   whatever the environment says and that no file under the server, engine, client, sources, protocol, graph or
   redact packages names the option.
2. **Hosting provider** (not chosen).
3. The user's **source providers** are not Eden's subprocessors: the user connected them, and Eden only reads.

Tenants will need: a subprocessor list, a DPA, a data-flow diagram (this file is the start), regional hosting options,
and a statement on training (none).

## Controls in code

- **Isolation:** tenant from the API key; per-user partitioning of every cache, map row and budget (D9).
- **Redaction:** `sanitizeForStore` on all stored, indexed, logged or model-bound text (D10).
- **Read-only sources:** `McpSource` calls only its configured search tool, and refuses it unless the server declares
  it read-only or an operator trusts it (D7). Annotations are self-declared, so only trusted servers are connected.
  A list tool for the sync (`listTool`, D57) passes the same check, or the connection fails.
- **Per-user credentials (D108):** each user's sources are built from their own entry (`EDEN_USER_SOURCES_FILE` or the
  integrator's directory) and their MCP connections are held per (tenant, user, source); no connection, header or
  token is shared between users. Header values can name an environment variable so tokens stay out of the file; they
  are held in memory only while the user's connections are, and never logged. Forget, 15 minutes idle, a changed
  token, a directory error or a directory that does not answer within 5 s closes the connections; the directory is asked again at most every 60 s, so a revoked
  account stops being read within a minute. Tokens are issued and refreshed by the integrator (no OAuth flow in Eden).
- **Model-bound background work:** with a model key the default makes cards and intent requests (D59, D87, D112), so
  item text leaves Eden for the model provider even when no request is made; tenants who set a key must disclose it.
  Each role's budget caps it per session and per user per day, and one cap per tenant per day spans every role
  (`EDEN_MODEL_USD_PER_TENANT_DAY`).
- **Request-time item text to the model:** since D237 the default sends none (`pushCandidates` 5: the push hands up
  to five unvetted candidates to the tenant's own agent instead, with no model call by Eden). With `pushCandidates: 0`
  the reader (D95, D112) reads an acting request or ask: up to 15 candidates (`askReaderPool`; 60 at most), 240 characters each, redacted, go to the model provider
  while the agent waits, unless no candidate could constrain the request (`readerGate`); tenants who set a key must
  disclose it, and the reader's own `Budget` and the tenant's daily cap bound how much. Its short bearing is the one piece of model-written
  text that reaches the agent: validated to a fixed kind and ≤ 15 words, redacted, inert, and labelled as Eden's.
- **Prompt injection:** source text is wrapped and labelled as data; model prompts say item text is never
  instructions; the judge returns indexes only and its free text never reaches the agent, and ask answers are wrapped
  in the same data envelope, so a malicious item cannot add words of its own beyond being picked (D11, D19).
  Source and event text on a line of the judge's prompt and of the MCP answer's Sources block goes through one
  sanitiser (`safeLine`, D221): no line break of any kind, control, bidi or invisible tag character, and no tag
  opener, so it cannot forge another item or candidate line or close a fence. Packets and answers (render.ts) still
  collapse every line break and escape `<`, but keep other controls and `<` look-alikes until render.ts moves to it.
  `injection.test.ts` checks 20 payloads through packets, answers and the judge prompt on every run.
  The agent still receives the item text: tenants should treat injections as untrusted input.
- **Deletion:** `POST /v1/forget` drops a user's (or one source's) cache and map rows and the user's live sessions,
  aborting in-flight lookups so nothing is re-cached afterwards (D17), and closes the user's (or that source's) source
  connections (D108). It does not change the configuration: the next lookup reconnects if the directory still lists
  the source, so revoking access means removing it from the directory too.
- **Secret gate gaps closed (D220):** a bare New Relic user key and a presigned or signed object URL's signature (S3,
  GCS; plain, JSON-escaped or percent-encoded) are redacted. Not covered: CloudFront, SigV2 and Azure SAS signatures
  (generic parameter names), and a Sentry DSN (public by Sentry's design).
- **Fail-open client:** an Eden outage never blocks the tenant's agent.
