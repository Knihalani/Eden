# Eden Memory — Decision register

**Dated 2026-09-29.** Every open choice from the review rounds, decided. Each decision cites the evidence it rests on. Where a decision overrules a recommendation from one of the research reports, the row says so and says why.

**Precedence:**
- This register decides.
- `A4-DELIVERY-CONTRACT.md` specifies what the register decides.
- `ROADMAP.md` orders the work.
- Research reports (`research/R0–R6`) and appendices A1–A3 are evidence. Where they disagree with this register, the register wins.

**Evidence keys:**
- **R0** hook facts (raw docs)
- **R1** cue experiment (+ Addendum A, policy triggers)
- **R2** cue architecture
- **R3** review of the new docs (real transcripts, extractor runs)
- **R4** citation audit
- **R5** scope on 19 real repos
- **R6** real usage (this machine's transcripts)
- **A1** first adversarial review
- **A2** technical choices
- **A3** nature mechanisms

## 1. Identity, windows, scope

| # | Decision | Evidence | Overrules |

## 2. What memory is (kinds and extraction)

| # | Decision | Evidence |
|---|---|---|
| **D6** | **Six typed kinds; only slot facts supersede.** New lock **L8**. Kinds: `slot` (keyed current value), `policy` (a user rule bound to action classes), `intent` (a transient "not yet / before X / until Y" bound to a trigger and expiry), `procedure` (verified how-to), `gotcha` (error signature → fix that worked), `episode` (the diary). Each kind has its own supersession, cue and refractory rule (A4 §3) | R3 F1/E8 (today's extractor collapses `we use pnpm` and `we use postgres` onto one key); R6 §7.2 |
| **D7** | **Slot table (normative, ~15 slots at launch).** Slots: `auth.provider`, `pkg.manager`, `db.engine`, `orm`, `test.runner`, `node.version`, `lang.version`, `framework`, `deploy.target`, `ci.system`, `formatter`, `linter`, `commit.style`, `branch.base`, `gh.account`. Patterns cover `S is V`, `S: V`, **`use/using/with A for B`**, **`use A (not|instead of|rather than) B`** (sets A, invalidates B), and `we (switched|moved|migrated) (from B) to A`. Each slot has `subject_aliases`, `value_class` and `default_scope`: `root` for `pkg.manager`, `commit.style`, `branch.base`, `gh.account`, `ci.system` and `deploy.target`; `working` for the rest. A value outside `value_class` is accepted only if it is a single capitalized or identifier-shaped token **not** in the status lexicon (`broken, down, failing, flaky, slow, fixed, working, done, weird, annoying, wrong, fine, ok, good, bad, new, old`). A bare `(we |i )?(always )?use V( here)?` counts when V is in exactly one slot's `value_class`. A `root` slot is written at `""` unless the utterance names a path or scope, or the working scope already has its own row <br>**Additional patterns (R8 E3 held-out misses):** retraction `we (don't|do not|no longer) use V( anymore)?` / `we('re| are) dropping V` → invalidate; `we('re| are) (on|using|now on) V`; `our <subject alias> (run|runs) on V`; `we (deploy|host) (to|on) V` → `deploy.target`; `PRs go (against|into) V` → `branch.base`; `(switched|moved|migrated) (X )?to A from B`; `use A for B, not C` → invalidate C; a trailing qualifier word after V (`yarn berry` → `yarn`). Slots found **only** by the sleep LLM are stored `extractor=llm` (candidate) until a regex match, a citation (D8) or a restatement confirms them. Gate: regex slot recall ≥ 0.70 on the held-out E3 batch (today 0.38), 0 false slots on status/trap items. | R3 F1/F10, R6 §9.7 (durable facts arrive inside imperatives), R8 E3 (regex slot precision 0.98, held-out recall 0.38), R7 §9 (status words would re-open A1 D10) |
| **D8** | **Repo facts are mined from evidence, not chat.** Sleep reads lockfiles (`pnpm-lock.yaml` → `pkg.manager=pnpm`), `.nvmrc` / `engines`, `package.json` dependencies and scripts (framework, test runner, auth SDK), CI files and `Cargo.toml` / `pyproject`. Each becomes a slot fact with `src=tool` and a **citation**. A later user statement overrides it | R6 §9.7 (the user almost never states these); A2 §2.12a (Copilot-style citations) |
| **D9** | **Policy extraction.** A policy is a negative or positive imperative on an action class, `don't|never|always|without asking|ask before|only after`, **user-typed** (D12). Rules: <br>• A mention with a temporal qualifier (`yet`, `for now`, `until …`, `before …`, `after …`, `this time`, `in this PR`) is **always an intent**, however often it recurs. It expires when its action completes, or after 7 days. <br>• An unqualified mention is a **policy candidate** keyed by `(class, polarity, object)`. `object` is the normalized direct object (`pr`, `main`, `migrations`, `.env`), or `*` when there is none ("don't merge yourself"). <br>• A candidate becomes a **pin** when `never/always` is explicit, or when the same `(class, polarity, object)` appears unqualified in **≥ 2 sessions**. <br>• A pin is **proposed** as user-global when the same `(class, polarity, object)` pin exists in ≥ 2 repos (D11). <br>**Fixes (R8 E3):** (1) `before`/`after` make an **intent** only when followed by a time or event noun phrase (`before friday`, `after launch`); a precondition clause (`before you …`, `after CI is green`) keeps a standing **policy**; `today`, `this week` join the qualifier list. (2) Triggers add `hold off (on)`, `no <verb>ing`, `leave … (unmerged|as a draft|alone)`, `wait (before|for)`, `without checking with me`; exclude `don't forget to`, `never mind`, questions (`why does it always …?`) and descriptive clauses (`we always forget …`), the only sources of regex false durables. (3) **Class-default objects** normalize to `*` in the key (integrate/review → `pr`; history-rewrite/branch/push → `branch`; dependency → packages; deploy → prod); without this, LLM object agreement of 0.48–0.84 splits one rule into several keys. (4) A `protected-path` class (`.env`, `infra/`, lockfiles), guarded on Edit/Write. (5) **Extraction architecture:** regex at write time (provisional, usable this session) + an opt-in sleep LLM that **confirms** regex extractions and **extends** with candidates. LLM-only candidates need one confirmation (recurrence, explicit `never`/`always`, or a D30 restatement) before they can arm the guard. | R8 E3 (held-out rule recall 0.72; 3/217 false durables, all from D9 triggers); R6 §6 (git/PR category: 28 mentions, 17 cross-session recurrences; many "not yet"); R7 §3 (class + polarity alone promotes transient and unrelated rules). **Overrules** the R3 cut list (intents deferred): R6 §6 shows "not yet" constraints are the largest restated class |
| **D10** | **Gotchas.** When the same command exits non-zero and then exits 0 within 5 tool calls, with a changed file between them, sleep records `gotcha{error_sig, fix_summary, files}`. `error_sig` = the first error line with paths, numbers, hashes and line:col normalized | R2 §3.5 |
| **D11** | **User-global scope** (above the repo root) is written by an explicit phrase (`in all my projects`, `everywhere`, `globally`), by `eden memory remember --global`, **or** by a user-confirmed proposal when the same `(class, polarity, object)` pin exists in ≥ 2 repos (D9). The proposal is shown once at SessionStart: `Proposed for all projects: … (say "yes, everywhere" to keep)`. Rendered `(all projects)`. Never inferred from facts | R6 §6 (verify thoroughly: 4 projects; explain plainly: 3 projects). **Overrules** R3 F18 and its cut list (auto-classification): R6 shows real cross-project norms, and confirmation removes the leak |

## 4. Cues and retrieval

| # | Decision | Evidence | Overrules |
|---|---|---|---|
| **D15** | **The hot path stays lexical (lock L6 kept, now with measured grounds).** The reasons are measured: <br>• static embeddings are cheap but lose on quality (0.38–0.46 vs 0.56); <br>• bge-small wins by +0.01–0.03, inside the CIs, and costs 165 ms cold, which is over budget; <br>• nothing bridges zero-overlap cues at acceptable silence. <br>**Re-open condition (revised by R8):** bge-small is the wrong candidate (+0.01 recall vs strong paraphrases; its advantage is silence). The candidate is a **≥ 1B embedder served warm** (daemon or self-hosted container) as a **separate dense gate**, never an RRF union (the union inherits BM25F's false fires). nemotron-3-embed-1b gained +0.14 recall@4 at half BM25F_ctx's FIR on the fixture and recovered 0.32 of strong zero-overlap paraphrases at a dev-5% point, but collapsed at strict silence (0.003) and is hosted (0.4–1 s). Re-open when such a model, served warm within the Submit budget, beats BM25F+context by > 0.05 recall@4 at equal FIR on ≥ 300 real hard negatives. Also measured: LLM-written hard negatives raise BM25F_ctx FIR from 15% to 25.5%, so R1's hand negatives understated the silence problem | R1 §0, §6; R8 E1, E5 | A2 §2.1's latency argument, now replaced by measurement |
| **D16** | **The cue is the situation, not the prompt.** `q = prompt ⊕ previous user turn ⊕ path tokens (last_paths) ⊕ previous assistant message (weight rises for continuations: "yes", "do it", "continue")`, with per-part mass limits (R2 §5.2). Eden's own delivered tokens are stripped from `q_prev` | R1 §0.5 (ctx recall 0.18 → 0.41, no FIR cost); R2 §4.3; R6 (13% of prompts are "continue") |
| **D17** | **Ranking and gate.** BM25F (value ×3, subject ×2, matured aliases ×1.5, body ×1; k1 = 1.2, b = 0.75) over a bounded candidate set (\|C\| ≤ 200; fat terms read newest-64). Admit if top score ≥ τ_repo, then keep rows ≥ 0.7·top. **τ_repo is refit at sleep**, and always **after** any alias or bridge batch is added, so a replayed silence set of **real logged prompts** (seeded with R1's and R8's 98 vocabulary-rich generated hard negatives) stays silent. The kind prior may never exceed one rare-token match. Only **identifier-shaped** tokens (paths, `ERR_*`, flags, versions, ids) count as STRONG; a plain rare word is MEDIUM <br>**Partly built in P0.2** (`src/memory-gate.ts`), for rows whose source shows the user did not type them (D12): admitted on one identifier-shaped match with the prompt (STRONG) or on a shared content word with at least two cue parts, out of the prompt, the previous typed prompt and the agent's last message (MEDIUM, A7 §4); a function word is WEAK. BM25F, τ_repo and the 0.7·top cut are P4.2's and P4.3's; rows the user typed, rows of unknown source and gists keep today's lexical admission | R1 §6 (90/150 negatives **contain** a df ≤ 5 token, so that rule would fire on them; thresholds transfer poorly); A1 D7 | R2 STRONG-by-df |

Topical words (tests, docs, logs, explain) stay on the lexical path | R1 Addendum A: policy recall 0.47 at 4% FIR on negatives, vs ≤ 0.22 for similarity at 5–15% FIR. **On unseen phrasings (R8 E1-c, kimi-k3 cues): 0.18 (0.26 of reachable) at 10% FIR, similarity 0.000.** So the prompt-side trigger is secondary: its lexicon must grow through D21's class-word learning, and the phrasing-independent **PreToolUse guard (D19) is the primary policy channel**. 18 of 60 held-out policy cues concern non-action policies (style, research depth) that no trigger reaches; those arrive via SessionStart pins (≤ 3) and lexical cues. Costs: 19% of other positive cues gain a policy bullet; 1.6 policy bullets per policy cue; the lexicon author had seen 12/60 cues |

## 5. Delivery

| # | Decision | Evidence |
|---|---|---|
| **D23** | **Delivery points** (one ledger per window): <br>• SessionStart: ≤ 3 policy pins for the likely scope, plus `Updated:` items; <br>• UserPromptSubmit: **human submits only**; <br>• SubagentStart: ≤ 3 bullets for the task's scope (task paths captured at `PreToolUse(Agent)`, A4 §5.3; else the parent's read set). Claude Code dedupes re-runs for the same subagent; <br>• PostToolBatch: first touch of a new scope in this epoch, STRONG only, ≤ 2 bullets; <br>• PostToolUseFailure: gotchas; <br>• PreToolUse: policy guard (D19); PreToolUse(Agent) only records the task paths. | R0 F10/F12/F27, R6 §5.1 (a new-scope batch happens about once per turn, on 2.6% of batches), R3 F2 |
| **D24** | **Non-human submits are silent.** A prompt whose first non-space characters are `<task-notification`, `<agent-message`, `<cross-session-message` or `<teammate-message`, **or** whose text equals a `session_crons[].prompt` seen in the window's last Stop payload, gets no packet and does not advance the turn counter. It may carry only `Updated:` items. There is **no payload `origin` field** (R0 F30); the transcript's `origin.kind` is used only at encode time to correct `src`. Queued prompts are human and count <br>**Built in P0.2** (`src/memory-turn.ts`, `src/memory-window.ts`): the tag may follow a peer message's one-line preamble, `Another Claude session sent a message:` (R0 F34; the live payload is not captured yet). Cron prompts are kept as hashes in the window's `ctx.log`. A non-human submit returns before any store is opened, so it also encodes nothing at that point (A4 §5.1 step 0); `ack` and `continuation` submits are encoded but not answered | R6 §4.2, §9.1 (the largest single lever) |
| **D25** | **Ledger mechanics.** <br>• **Storage:** `delivery.log` is append-only, with snapshots at Stop **and SubagentStop** under `flock`, written by rename. Before folding, the log is rotated by rename (`delivery.log` → `delivery.log.<n>`), never truncated in place. Readers fold snapshot + logs (a union with max). `hturn` is the count of distinct `prompt_id`s among `turn` records appended at human Submits. <br>• **Refractory:** a `cid` is not re-injected while it sits in the live window at the same `ver`. <br>• **Re-eligibility:** pins, policies and intents after **400 KB** of transcript growth **and** a fresh cue; slot facts, gotchas, procedures and episodes after 1.2 MB. For a child window, distance is measured on its own `subagents/agent-<agent_id>.jsonl`, not on the main `transcript_path`. Both distances are unmeasured proxies (A5 `re-eligibility`). <br>• **Epochs:** `clear` bumps the epoch. After compaction, only the cids whose value tokens are **absent from `compact_summary`** are re-armed. `resume` keeps the ledger; `fork` copies it. <br>• **Rewind:** branch points are found by the delta encoder (A4 §3.3); deliveries made on an abandoned branch are dropped. <br>• **Overflow:** above 256 entries, evict the oldest epoch first, then the least recent episodes. <br>**Built in P0.2** (`src/memory-ledger.ts`), the refractory rule only: every delivered bullet is a `deliver` record in the window's `delivery.log` (`cid`, `ver`, `off`, `att`, `ht`), SessionStart's included, and a bullet whose `cid` and `ver` were delivered in this epoch, less than 400 KB (rules) or 1.2 MB (everything else) of transcript ago, and not on an abandoned branch, is dropped.
