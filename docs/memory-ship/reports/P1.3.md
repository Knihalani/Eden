# P1.3 — Residual + per-window shadow set

**Outcome:** merged. What a window's instruction files already state is no longer delivered. The files are the CLAUDE.md and rule files InstructionsLoaded reports, nested ones while they are loaded, AGENTS.md where the project has no CLAUDE.md, and the project's auto-memory MEMORY.md. D26's residual now sees the user's typed prompts on Claude Code's transcripts, and it reads negation, questions and D7's bare `use V`. A forked session no longer encodes its parent's conversation again. `shadow` is green, `residual` stays green, and every guard is within tolerance except the R6 replay's `packet_rate` (53/122 vs `main`'s 50/122), which the user accepted and which is filed to P4.3.

## What changed
- **The shadow set (D27, R7 §13), per window.** It is built on captures of Claude Code 2.1.294 (a recorder hook, no Eden) and on its binary's own text.
  - **InstructionsLoaded** is now registered: the plugin's `hooks.json` (async, as Claude Code runs it), `eden setup`, `eden doctor` (9 memory events) and `eden hook`. It appends `{path, reason, att}` to `windows/<win>/shadow.log`, where `att` is the `prompt_id` of a lazy load. It opens no store and prints nothing.
  - **Epochs.** SessionStart `compact` and `clear` append an `epoch` record. A lazy load (`nested_traversal`, `path_glob_match`) counts until the next epoch and while its prompt is on the branch (a rewind abandons it). An eager load (`session_start`, `include`, `compact`) stays. The basis is a capture: after `/compact` the lazily loaded files had left the context (the model reported their markers gone), and no `compact` reload fired.
  - **From disk** (no InstructionsLoaded fires for these):
    - AGENTS.md or `.claude/AGENTS.md`, read only where no folder from the session's folder up to the repo's top has a CLAUDE.md. Captured: with a CLAUDE.md the AGENTS.md marker was not in context; without one it was. Claude Code's `instructionFiles` default says the same.
    - The project's auto-memory index: `projects/<canonical root with every other character "-">/memory/MEMORY.md`, beside the session's own folder. The canonical root is a worktree's main checkout, a subfolder's repo top, else the session's folder. Past 200 characters the folder is found by prefix (Claude Code adds a hash). Only the first 200 lines and 25,000 bytes are read, as Claude Code loads them, and none when `CLAUDE_CODE_DISABLE_AUTO_MEMORY` is set.
  - **Delivery.** The files are read at each Submit and SessionStart: at most 64 KB in all, failing open to an empty set. Each sentence they state is dropped from a note, and the note's other sentences are kept, because a legacy gist holds several items. The wide event logs `drops.shadow`.
- **The statement test (D26), shared by the residual and the shadow set** (`src/memory-residual.ts`):
  - **Jaccard ≥ 0.6 needs the same polarity.** Content words drop "not", so "Do not run the migrations on staging" no longer states "Run the migrations on staging".
  - **The slot rule reads only an asserted value.** A question does not assert: a sentence ending in "?", or opening with a question word or an auxiliary and holding no clause break. Nor does a value with a negation before it in its clause ("not npm", "no longer use postgres").
  - **D7's bare `use V` states the row's slot** ("Use pnpm, not npm" states "The package manager is pnpm").
  - A slot is a slot-shaped sentence of a fact or a gist. The residual still drops a whole note only.
- **Typed prompts (P0.5's follow-up).** `typedPrompt` now counts a line with `origin.kind: "human"`, through `isHuman` from `memory-authority.ts`. Before this, every Claude Code typed prompt was skipped. So D26's residual held no earlier typed prompt, and A7's `q_turn`, the gate's second cue part, was always empty. Both now hold the previous typed prompt.
- **A fork's first delta (P1.2's follow-up).** `parentLines` (`memory-fork.ts`) skips the lines whose uuid the parent's turn map holds: the parent's copied conversation, which the parent's delta already encoded. It fails open, encoding everything as before.
- **The simulator (P0.0a's follow-up, a `fixture:` commit).**
  - A main-thread file access under a folder with its own CLAUDE.md writes a `nested_memory` attachment and fires InstructionsLoaded `nested_traversal` with the captured key order.
  - The attachment is a window entry, so a compaction or rewind drops it.
  - Each file loads once until a compaction, and none loads in a subagent (R0 F35).
  - The `shadow` arm gains `nested-never-injected`.
- Key files:
  - `src/memory-shadow.ts` (new): the shadow log, epochs, loaded files, AGENTS.md and MEMORY.md.
  - `src/memory-residual.ts`: `Said` with polarity, the asserted-value slot rule, `unsaidText`.
  - `src/memory-delivery.ts`: `cue.shadow`, `drops.shadow`, `unsaidNotes`.
  - `src/memory-transcript.ts`: `typedPrompt`.
  - `src/memory-fork.ts`: `parentLines`.
  - `src/memory-repo.ts`: exports `realpathOrSelf`.
  - `packages/cli/src/memory-hook.ts`: InstructionsLoaded, the shadow epoch, the shadow set at Submit and SessionStart, the fork's first delta.
  - Registration: `packages/cli/src/{hook,setup,doctor}.ts`, `plugins/eden-memory/hooks/hooks.json` and `README.md`.
  - Harness: `benchmarks/memory-long-horizon/harness/{session,transcript,payloads}.ts` and `arms/delivery.ts`.
  - `docs/memory-ship/DECISIONS.md` D26 and D27, `A4-DELIVERY-CONTRACT.md` §1 (`shadow.log`), `A7-CUES.md` §8.

## Decisions made
- **AGENTS.md only where the project has no CLAUDE.md** (D27 says "plus AGENTS.md"): captured on 2.1.294 and stated by Claude Code's `instructionFiles` default. The folders run from the session's to the repo's top, a narrower walk than Claude Code's own, which goes up to `/`.
- **MEMORY.md is the project's index** (D27 says "auto-memory MEMORY.md"), resolved as Claude Code's `defaultPath` resolves it (review round 1). The settings that move or turn it off (other than the environment variable) are not read: filed to S1.
- **A lazy load leaves at a compaction or `/clear`, an eager one stays** (D27 says "including lazy and `compact` loads"). This follows the capture: no `compact` reload fired, and nested files left the context.
- **`shadow.log`, append-only, instead of A4's `shadow.json`.** Loads arrive from parallel async hooks, and appending needs no lock. A4 §1 now says `shadow.log`.
- **No `shadowfacts.json` cache** (A4 §1). The files are read at each delivery. On 64008f835 (`shadow-cost.ts`, 200 reads after 20 warm-ups, two runs, load 2.27): 0.946 / 0.959 ms p50 and 1.504 / 1.499 ms p99 for this repo's 10 KB CLAUDE.md and 2 KB MEMORY.md; 4.693 / 4.689 ms p50 and 5.669 / 5.491 ms p99 with DECISIONS.md loaded too (496 sentences, capped at 64 KB). The Submit timing guard, measured with these reads, passed. The 64 KB budget bounds a delivery, and past it the rest is not read, which costs a repeat, never a miss.
- **The shadow set strips sentences; the residual drops whole notes.** Sentence stripping on conversation text cut "label: 7" from an ICL row ("7" is not a content word, so "label:" matched it), so the residual keeps P0.2's note-level reading. Instruction files state items one per line, and a legacy gist holds several, so the shadow set strips.
- **The slot rule's value classes, before P3.3.** D7's bare `use V` counts when V is in one slot's value class. Without value classes, the value is taken to name the row's slot. Subject words still stand for aliases: filed to P3.3.
- **Polarity on the Jaccard path** (D26 says Jaccard ≥ 0.6) applies to the residual and the shadow set alike. It moves R6 by one packet (above).
- **The SessionStart briefing (gists) applies the shadow set.** A4 §5.1 step 7 is the Submit's, but D27 says "never injected" and the arm's leak was a SessionStart gist.
- **Child windows get no shadow set yet.** No child delivery point exists, and SubagentStart is P2.5's.
