## What changed

- **CI can pass.** On a fresh install `main` failed all three CI steps. On this branch `bun run typecheck`, `bun run test` and `bash scripts/build-cli.sh` all exit 0 (numbers below).
- **The CLI and the memory hook load on a fresh install.** Bun 1.3's isolated linker only links a package's declared dependencies, and `packages/cli` declared none. So on a clean clone every `@eden/*` import from the CLI failed, including `packages/cli/src/memory-hook.ts`, the module the eden-memory plugin loads first. The plugin then fell through its fallback chain and printed `{}`: memory silently did nothing (end-to-end evidence below). This is the one behaviour change, and it restores intended behaviour. The user's main checkout was unaffected because it still had links from an older install.
- **The lost `packages/cli/src/demo.ts` is restored.** `cli.ts`, `apps/control/src/demo.ts`, `demo.test.ts` and the CLI build's smoke test all use it, but it was never committed. It was rebuilt from the only surviving copy, the compiled module in a 2026-09-01 CLI bundle, and checked against that bundle's own functions: 0 differences.
- **Type errors fixed with no runtime change.** Emitted JavaScript is unchanged except in the following places, each shown equivalent in its commit:
  - a restored export;
  - three comparisons that TypeScript proves false;
  - `filter(Boolean)` rewritten as a type-guard arrow;
  - `if (have > 0)` on a boolean;
  - the `latin1` TextDecoder label, which WHATWG defines as the same decoder as `windows-1252`;
  - one unread, side-effect-free property.
- **The whatever loop's collateral damage is quarantined, not hidden.** Every quarantined test or file has a GitHub issue that says why and how to un-quarantine it: 65 issues, #2–#66, label `quarantine`. The loop's own guard ran 6 test files, so it never saw what it broke.
  - 26 files are listed in `scripts/test-quarantine.txt`. `test.sh` skips them.
  - 140 tests in 35 files are marked `test.failing`. They still run, and CI goes red again when one starts passing.
  - 17 tests in 7 files skip only when gitignored local data is absent.
- **Security-relevant quarantines** (issues #45, #19, #42, #55, label `bug`). Tests assert that secrets and identifying data are not persisted, and on `main` they are:
  - raw `ghp_…` tokens and a password in the memory store;
  - an `sk-ant-…` key through memory import;
  - the cwd in the JSONL.

  This slice does not change that behaviour. P0.4 (trust gate) owns the fix.

## Decisions made

- **The real error count was larger than planned.** ROADMAP and EXECUTION cite 112 typecheck errors, which is what CI printed. A parse error hid the root program's semantic pass: 303 errors behind it. With the dependency fix, 226 unique sites remained (`tc3`). All are fixed except the 21 in two quarantined wrap test files, which are excluded. The scope and gate are unchanged.
- **"No behaviour change".** I read this as: no change to what the product does when it runs. Every code fix is type-only or proven equivalent. The exception is environmental: the CLI and memory hook now load on a fresh install. Without that, the CLI build, the CLI tests and the plugin cannot work, so it is part of making CI green.
- **Workspace deps are devDependencies.** The published CLI inlines them (`scripts/build-cli.sh`). As `dependencies`, `workspace:*` had made the package uninstallable (see 476be7e5f), and consumers never install devDependencies.
- **`demo.ts` is restored, not the `demo` command removed.** Removing the command would have meant weakening the build's smoke test (`eden demo --help` must mention T-100). The rebuilt module was checked against the compiled original for all 12 exports and 4 `demoCli` paths: `differences: 0`.
- **The accidentally dropped `export` of `steerAnthropicToolUses` is restored.** 3d3c5ae69 lost it while inlining, and it was public before through `index.ts`.
- **How to quarantine** (ROADMAP: "fix or quarantine, one tracked issue per quarantined test"):
  - (a) A file that cannot load, or whose every test fails for one cause, goes in `scripts/test-quarantine.txt`. Skipping it loses no passing test.
  - (b) A deterministic code-caused failure in an otherwise healthy file becomes `test.failing`. The test still runs, and a fix turns CI red until the marker is removed.
  - (c) A test that needs gitignored local data skips when the data is absent. This follows P0.0d's "skipped: private set absent" pattern. `test.failing` would be wrong here: the test is not broken, and it passes where the data exists.
  - Each issue covers one file and lists every test it quarantines: 65 issues for 67 files, since two discovery shims share their `src/` file's issue. One issue per test case would have been about 200 near-identical issues.
- **Verification uses a non-nested tree.** The slice worktree sits under the main checkout, so tsc and Bun also resolve from ancestor `node_modules`: `/Users/…/node_modules/@types/node` 24.5.2 and the main checkout's own. That produced two phantom errors, and it can mask missing dependencies. Every number above comes from worktrees under the scratchpad, which, like CI, have no ancestor `node_modules`.
- **`fixture:` commit cf2924d2e.** `benchmarks/memoryagentbench/protocol.test.ts` pins the exact `exec bun test` line of `test.sh`; it now pins the new line, which adds `$ignore`. Same strictness, same intent: root src tests are passed as files.
- **Four lines went over 120 characters (121–127).** In each, `test(` became `test.failing(` or `test.skipIf(...)(`. Wrapping them would mean re-indenting whole test bodies, and R-5 introduces the formatter, which owns wrapping.
