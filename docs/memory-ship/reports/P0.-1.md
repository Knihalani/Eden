# P0.−1 — Green CI baseline

**Outcome:** Merged. CI's three steps (typecheck, test, CLI build) now pass on a fresh install. Before, all three failed. The CLI and the eden-memory hook now load on a fresh clone, and the whatever loop's broken tests are quarantined, each with a tracking issue.
**PR:** https://github.com/Knihalani/Eden/pull/68 · **Merge commit:** recorded on PR #68 after the merge (a rebase merge rewrites SHAs) · **Date:** 2026-09-30

## What changed

- **CI can pass.** On a fresh install, `main` failed all three CI steps. On this branch `bun run typecheck`, `bun run test` and `bash scripts/build-cli.sh` all exit 0, including under an empty `HOME`, as on a CI runner (numbers below).
- **The CLI and the memory hook load on a fresh install.**
  - Bun 1.3's isolated linker only links a package's declared dependencies, and `packages/cli` declared none.
  - On a clean clone, every `@eden/*` import from the CLI failed. That includes `packages/cli/src/memory-hook.ts`, the module the eden-memory plugin loads first.
  - The plugin then fell through its fallback chain and printed `{}`: memory silently did nothing (end-to-end evidence below).
  - This restores intended behaviour.
  - Consequence: fresh installs now also get today's memory behaviour, including the secret-persistence bugs below. Before, they stored nothing at all.
  - The user's main checkout was unaffected, because it still had links from an older install.
- **The lost `packages/cli/src/demo.ts` is restored.**
  - `cli.ts`, `apps/control/src/demo.ts`, `demo.test.ts` and the CLI build's smoke test all use it, but it was never committed.
  - I rebuilt it from the only surviving copy: the compiled module in a 2026-09-01 CLI bundle.
  - Compared with that bundle's own functions: 0 differences.
- **Type errors are fixed without runtime change.** Emitted JavaScript is unchanged except in these places, each shown equivalent in its commit:
  - a restored export;
  - three comparisons that TypeScript proves false;
  - `filter(Boolean)` rewritten as a type-guard arrow;
  - `if (have > 0)` on a boolean;
  - the `latin1` TextDecoder label (WHATWG: same decoder as `windows-1252`);
  - one unread, side-effect-free property.
- **One product fix: the transparent-serve config cache is keyed on the config path.**
  - `readConfigSafely()` cached the config, or `null`, for 2 s whichever `EDEN_HOME` it had been read from.
  - Four `hook.test.ts` tests passed only because an earlier test had cached the user's real `~/.eden/config.json`. On a clean machine they fail: `packages/cli/src` under an empty `HOME` gave 407 pass, 4 fail before the fix and 411 pass, 0 fail after it.
  - Production processes never change `EDEN_HOME` mid-run, so their behaviour is the same.
- **The test suite no longer writes to the real `~/.eden`.**
  - Twenty test files restore `EDEN_HOME` by deleting it. After that, `edenHome()` falls back to `$HOME/.eden`.
  - Ten `apps/control` tests never set `EDEN_HOME`, and `syncLiveTools()` writes `~/.eden/live-tools.json`.
  - `scripts/test.sh` now runs everything under a throwaway `HOME`, printed as `test HOME:` and removed on exit, and clears every `EDEN_*` variable from the calling shell.
  - Tracking issue: #67. The incident is described under "Verification notes".
- **The whatever loop's collateral damage is quarantined, not hidden.**
  - Every quarantined file or test has a GitHub issue saying why and how to un-quarantine it: 65 issues, #2–#66, label `quarantine`.
  - The loop's own guard ran only 6 test files, so it never saw what it broke.
  - 26 files are listed in `scripts/test-quarantine.txt`, and `test.sh` skips them.
  - 140 tests in 35 files are marked `test.failing`. They still run, and CI goes red again when one starts passing.
  - 17 tests in 7 files skip only when gitignored local data is absent.
- **Security-relevant quarantines** (issues #45, #19, #42, #55; label `bug`). These tests assert that secrets and identifying data are not persisted, and on `main` they are:
  - raw `ghp_…` tokens and a password in the memory store;
  - an `sk-ant-…` key through memory import;
  - the cwd in the JSONL.

  The memory code is unchanged. Because of the dependency fix, fresh-install users of the plugin now reach it. P0.4 (trust gate) owns the fix and should be prioritised.

## Decisions made

- **The real error count was larger than planned.**
  - ROADMAP and EXECUTION cite 112 typecheck errors, which is what CI printed.
  - A parse error hid the root program's semantic pass, with 303 errors behind it.
  - With the dependency fix, 226 unique sites remained (`tc3`). All are fixed except the 21 in two quarantined wrap test files, which are excluded.
  - The scope and gate are unchanged.
- **"No behaviour change"** is read as: no change to what the product does when it runs. Every code fix is type-only or proven equivalent, with two exceptions:
  - Environmental: the CLI and memory hook now load on a fresh install. Without that, the CLI build, the CLI tests and the plugin cannot work, so it is part of making CI green.
  - The config cache is keyed on its path. It is identical in production, where `EDEN_HOME` is fixed per process. It fixes the product defect those four hook tests exposed instead of working around it in the tests; a test-only cache reset or a quarantine would also have turned CI green.
- **Counter-metric reinterpretation.**
  - The prereg and PROGRESS say "test count before = after, minus named quarantines". That cannot hold literally. On the baseline, Bun reported 96 load errors ("errors"), whose files' tests were never counted; the dependency and parse fixes let most of those files load, so the count went from 2225 to 3300.
  - The check actually applied is the intent: no test that passed on the baseline stops passing (0 of 2052), and every non-passing test is fixed or named in an issue.
  - This decision is recorded here, not by editing the prereg.
- **Workspace deps are devDependencies.** The published CLI inlines them (`scripts/build-cli.sh`). As `dependencies`, `workspace:*` had made the package uninstallable (see 476be7e5f), and consumers never install devDependencies.
- **`demo.ts` is restored, not the `demo` command removed.** Removing the command would have meant weakening the build's smoke test (`eden demo --help` must mention T-100).
- **The accidentally dropped `export` of `steerAnthropicToolUses` is restored.** 3d3c5ae69 lost it while inlining; it was public before, through `index.ts`.
- **How to quarantine** (ROADMAP: "fix or quarantine, one tracked issue per quarantined test"):
  - (a) A file that cannot load, or whose every test fails for one cause, goes in `scripts/test-quarantine.txt`. Skipping it loses no passing test.
  - (b) A deterministic, code-caused failure in an otherwise healthy file becomes `test.failing`. The test still runs, and a fix turns CI red until the marker is removed.
  - (c) A test that needs gitignored local data skips when the data is absent. This follows P0.0d's "skipped: private set absent" pattern. `test.failing` would be wrong here: the test is not broken, and it passes where the data exists.
  - Each issue covers one file and lists every test it quarantines: 65 issues for 67 files, because two discovery shims share their `src/` file's issue. One issue per test case would have been about 200 near-identical issues.
- **Verification uses a throwaway `HOME` and a non-nested tree.**
  - The slice worktree sits under the main checkout, so tsc and Bun also resolve from ancestor `node_modules` (`/Users/…/node_modules/@types/node` 24.5.2, and the main checkout's).
  - The real `HOME` holds a `~/.eden/config.json` that CI does not have.
  - The final numbers come from a scratchpad worktree with no ancestor `node_modules` and a throwaway `HOME`, like CI.
- **Test edits outside `fixture:` commits.** The type fixes in 1de81f329 and 7f43ba7b1 changed some test inputs:
  - the `wrap.test.ts` outbox loop body;
  - the `manifest: null` fixtures in `load.test.ts`, `digest.test.ts` and `refresh.test.ts`;
  - the removed `sequence` fields in `fail.test.ts` and `refusal.test.ts`;
  - the dropped `opts` argument in `know-inject.test.ts`.

  None of them changes an expected value. The reviewer checked that the base versions of all 33 type-edited test files give identical outcomes (417 tests), apart from the 11 now marked `test.failing`; `wrap.test.ts` does not parse on base and was excluded. They were not split into `fixture:` commits after the fact. The one expected-value edit (`protocol.test.ts`) is in `fixture:` cf2924d2e.
- **Four lines went over 120 characters (121–127).** In each, `test(` became `test.failing(` or `test.skipIf(...)(`. Wrapping them would mean re-indenting whole test bodies, and R-5 introduces the formatter, which owns wrapping.
