## What changed
- **A4 §5.1 step 4a's slot detector** (`cuedSlots`, `src/memory-slots.ts`; R2 §6.1b, A7 §1 layer 2). It reads the user's own words: the typed prompt, and on a continuation the proposal it accepts. A slot it names reaches that slot's live keyed row in the read set by key (STRONG), whatever words the cue shares with it. A cue names a slot in three ways:
  - **A seed** names its slot alone. A seed is a phrase that names nothing else: "package manager", "test runner", "auth provider", "lockfile", ".nvmrc", "install the dependencies", and the rest of the list.
    - The seeds are calibrated as R2 asks: no prompt of the silence set names a slot. That set is `src/memory-silence-seeds.json`: R1's 70 dev negatives and R8's 98 (0 of 168 hits).
    - So bare "install" (R1's "how do I install node on Ubuntu…", which named the package manager on `main`), "database", "auth", "node", "deploy", "ci" and "test" name nothing alone.
  - **A topic word with an ownership word.** A word of a slot's topic (its D7 aliases, and R2's "login", "sign in", "sso", "spec") names the slot only in a cue about this project: "we", "our", "this repo", and "us" in lowercase, not after "let" or "tell".
    - "what database do we use?" names the database. "explain database indexes", "how does SSO work with SAML?", "the log in the console" and "is US hosting cheaper?" do not.
  - **A7 §7's setup bundle.** A setup cue about this project ("how do I set up the repo on a new laptop?", "set up this monorepo on my laptop") names the package manager and the Node version.
  - **Matching rules.** Phrases match as words of the prose, never inside a path or a filename ("login" in `app/login.ts`). Each lexicon is one expression compiled at load. A 20 KB prompt costs about 1.2 ms (load about 4); round 1's version cost 67 ms (the reviewer's measurement, load about 15).
- **The keyed lookup** gives a row stating a value instead of another ("The database is sqlite instead of postgres") as the value it asserts (`assertedOnly`), as the lexical path already did.
- **`liveCopulaLatest`** (P3.3's follow-up): a prompt stored whole as an episode ("The database is postgres. Reply with just OK.") no longer displaces the keyed fact it states. A newer fact the user typed still wins.
- **Harness** (`fixture:` a15962fd1): `cuebench-code` reports recall@4 per category, and counts R8's `nim-neg` as negatives. On `main` the arm printed "negatives FIR 0/0".
- **Files:**

## Decisions made
- **Calibration is a fixed lexicon, checked by a test** (R2 §6.1b: per-slot thresholds "so the silence set produces zero slot hits"). For a lexicon, the threshold is which words it keeps. The set is A7 §4's seeds: R1's dev negatives, never its test ones, and R8's 98. The sleep-trained model R2 describes is later work (P5.3).
- **Words that pass calibration are still left out when they name anything:** "session", "format", "workflow". ("gh" is a `gh.account` alias, so with an ownership word it names the slot: "our gh account".) The silence set is generated text and holds few of a user's words. Topic words need an ownership word (round 1).
- **By design, a topic word with an ownership word names its slot even when the prompt is not asking for the value.** Examples: "we need to fix the bug in the node parser" → the node version; "write a poem about our database" → the database. The guards and the real negatives (24/125 on both sides) show no cost; the silence sets have no ownership words to test it with.
- **P3.4's "installing", "reinstall" and "lockfile" stay seeds**, although "what is a lockfile in general?" names the package manager. `main` names it by them too.
- **The detector reads the user's own words** (the typed prompt; the proposal on a continuation), as P3.4 built it. A4 says "on q"; R2 says "prompt ⊕ q_prev". The A4 note says so.
- **The bundle is the package manager and the Node version.** A7 §7's "env location" is no D7 slot, so it has no key.
- **The keyed-row rule yields only for episodes** (round 1). A4 §3.1's newest statement is the value, so a newer typed fact wins.
