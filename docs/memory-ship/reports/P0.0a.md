# P0.0a — Harness: Claude-shaped event + transcript simulator, process-per-event runner

**Outcome:** Merged. The memory program now has a Claude Code simulator: it replays R6-shaped sessions through a plugin's real hooks, one process per hook, with payloads that match real Claude Code 2.1.285 key for key. The canonical session through `plugins/eden-memory` runs 101 hook processes, all exit 0, and fresh runs from different run directories agree. Before, the long-horizon bench called `openMemory()` in one process and could emit no hook event.
**PR:** PENDING_PR_URL · **Merge commit:** recorded on the PR after the merge (a rebase merge rewrites SHAs) · **Date:** 2026-10-03

## What changed

- **A Claude Code session simulator** (`benchmarks/memory-long-horizon/harness/`). It drives a plugin's real hooks the way Claude Code does. Before it, the long-horizon bench called `openMemory()` in one process and emitted no hook payload.
  - **Payloads.** The 13 hook events the memory design uses (A5 §3.1, plus PostToolUse and SessionEnd), field for field and in field order, as Claude Code 2.1.285 sends them. The reference is a capture from real sessions, not the docs alone (see Decisions).
  - **One process per hook.** Each matching handler of each event runs in a fresh process, matched by the plugin's `hooks/hooks.json` under the documented matcher rules, with the payload on stdin. Handlers of one event run in parallel. A batch of Reads fires its PostToolUse hooks concurrently, as Claude Code does.
  - **The real transcript format**, from this machine's transcripts: line kinds, each kind's most common field order, and `parentUuid` chains.
    - Kinds covered: typed, queued and mid-turn prompts; task notifications; peer messages; tool calls and results; `hook_additional_context` and `queued_command` attachments.
    - Structure covered: rewinds (append-only branches); `compact_boundary` with its summary; subagent transcripts and their meta files.
    - Timing: lines reach the file after their step's hooks ran, because the real file lags (R0 F8). `--flush eager` writes them at once.
  - **Hook answers act on the session**, as in Claude Code:
    - contexts are saved as attachments where Claude Code puts them;
    - a prompt that UserPromptSubmit blocks is erased, and its turn does not run;
    - a denied or declined tool call does not run;
    - PreCompact can block compaction.
    - Not simulated, but logged: a Stop or SubagentStop hook that would keep the agent going, and a PostToolBatch block.
  - **R6-shaped sessions.** A seeded generator writes a session as a plain-data script, and a player replays it. Its shape follows R6 (A5 §3.8):
    - human prompts per session;
    - about 1.7 non-human submits per human prompt;
    - a rewind in 27% of sessions;
    - about 8 subagent windows per session;
    - R6's tool calls per turn;
    - compaction at 600k tokens.
  - **`replay.ts`** runs one session through a plugin and prints a JSON summary: events per point, exit codes, fail-open counts, latency, contexts, transcript size, and a digest of the event sequence, payloads and exit codes.
  - **Reproducible.** A run depends only on its script and seed. It does not depend on where it lives, or on what a hook printed: hook output changes the session only through control flow and the transcript. With a deterministic plugin, two runs from run directories of different lengths produce byte-identical transcripts once the run directory is taken out of the paths.
  - **Isolation.** Every run lives in its own directory. Hooks get `HOME`, `EDEN_HOME` and `EDEN_MEMORY_DIR` inside it, and inherit nothing from the caller except `PATH`, `TMPDIR` and `LANG`.
- **No product code changed.** Outside `harness/`, the diff is one line in the root `tsconfig.json` (`benchmarks/memory-long-horizon` is now typechecked), the long-horizon README, and docs.
- **R0 gains four verified hook facts (F31–F34)** from the capture. The one later slices most need: compaction fires a SubagentStop for an internal agent with `agent_type: ""` (F32).

## Decisions made

- **The reference is real payloads, not only the docs.** A5 §3.1 asks for payloads "exactly as in R0". R0 lists fields, but not their order or when optional ones appear. So the fixtures hold:
  - the key lists of 23 payload shapes, recorded by a probe plugin in two real Claude Code 2.1.285 sessions on this machine;
  - the line keys and each kind's most common key order, from this machine's transcripts.
  - Keys and formats only, so no transcript text enters git. Secret scan: 0 hits.
  - The rules this gave are now R0 F31–F34. For example, `permission_mode` is on UserPromptSubmit but `effort` is not, and `/compact` fires a SubagentStop for an internal agent with `agent_type: ""`.
- **Two deviations from the captured resume-then-compact order**, both asserted in `fidelity.test.ts`:
  - (a) The capture has a second `InstructionsLoaded(session_start)` just before PreCompact, when `/compact` ran in the resumed `-p` process. The simulator does not fire it, because one capture cannot say when it happens in general.
  - (b) After compaction the simulator fires `InstructionsLoaded(compact)`, per the docs. The captured process ended right after PostCompact, so the capture neither confirms nor refutes it.
- **A hook's answer acts on the session only through control flow and the transcript** (review finding 1 and its consequence).
  - The context estimate (4 characters per token) counts conversation text, with the run directory as a fixed placeholder, and leaves hook-injected context out.
  - Real Claude Code would count that context, so `context_tokens` on a resume is low by its size. The gain: a plugin whose packets vary between runs cannot change the payloads that follow, so a disagreement between runs points at the plugin, not the harness.
  - The digest therefore covers what the pre-registration names (event sequence, normalized payloads, exit codes). The first digest also covered output kind and whether a context came back; that went beyond the pre-registration and would have flagged eden-memory's own variation (#98).
- **Concurrency follows what Claude Code did.** Two Bash calls from one message were dispatched one after another in the captured debug log. So a batch runs its calls one by one, unless every call is a Read, which runs concurrently (R0 F11). Several Agent calls in one batch are not modelled concurrently.
- **Background subagents are split into launch and completion.**
  - Launch: PreToolUse(Agent), SubagentStart, PostToolUse(`async_launched`), PostToolBatch.
  - Completion, later: the body, SubagentStop, then the task notification.
  - In between, Stop and SubagentStop list the subagent in `background_tasks` (parent-scoped, per the docs; fixed in review). Its events are serialized with the main thread's, not interleaved.
- **Not simulated, and so disclosed** (review finding 6). A hook that keeps the agent going: Stop or SubagentStop exit 2, `decision: "block"` or `additionalContext`, and a PostToolBatch block. The runner reads and logs these answers, but the session does not continue, and a Stop context is not saved. Auto compaction is placed between turns, before the next prompt; only a manual `/compact` was captured.
- **No rewind across a compaction** (review finding 7). After compaction, prompts of the compacted conversation are no longer rewind targets, in the simulator and in the generator. This is our reading of Claude Code's rewind menu, not verified.
- **Unverified texts, kept short and labelled in the code:**
  - the refusal texts for a hook `deny`, a `defer`, and an `ask` in `dontAsk` mode (the decline text is verbatim from this machine's transcripts);
  - `hookName` on a tool-event context attachment (the event name, as observed for UserPromptSubmit and SessionStart);
  - where a SubagentStart context lands in the child transcript (after the task prompt);
  - the compact summary's wording after its first sentence;
  - the async-launch text, which is truncated.
- **Peer messages.** UserPromptSubmit receives `<agent-message from="…">…</agent-message>`, the form of the real `queued_command`, while the transcript line carries Claude Code's preface (observed). The live payload for an idle peer message was not captured (R0 F34).
- **Hook environment.** Hooks get a minimal environment (PATH, TMPDIR, LANG, the Claude Code variables, and HOME, EDEN_HOME and EDEN_MEMORY_DIR inside the run dir), not the caller's whole environment. This keeps runs reproducible and isolated (CLAUDE.md), where real Claude Code passes its full environment. The test asserts what the hook process actually saw.
- **The runner refuses handler features it does not model**, rather than running them differently: `if`, `async`, and non-command handler types. P2.3 needs `if` and will extend the runner.
- **A timeout kills the hook's process group**, so a child such as `sleep` cannot hold the pipes open. The payload is passed as a buffer, because a hook that exits without reading a large stdin otherwise stalled the runner. I found that while reviewing my own code and added a regression test.
- **Generator calibration came after the pre-registration, against its fixed bands.** The bands are R6's measurements and were not edited.
  - Before review, three iterations: the first missed 2 bands (human-prompt median 4 and max 29; tool calls per turn p50 25), the second missed 1, the third met all 6.
  - In review, the mean subagent windows were re-centred on R6's 8.2 (8.84 before; 1.58 subagents and 0.31 peers per turn), after the reviewer found one held-out window above 9.5.
  - The modelled splits are named in `shape.ts`: subagents cluster in 35% of turns; 88% run in the background; 20% of non-human submits arrive mid-turn; 8% of Bash calls fail.
- **The canonical session's seed is chosen by a stated rule** (review finding 2). Among seeds 1–3,000 whose script has every feature, take the one nearest R6's ratios (|non-human ÷ human − 1.7| / 1.7 + |subagent windows − 8.2| / 8.2; ties: fewer tool calls). That is 1937: 10 non-human submits for 6 human prompts (1.67) and 8 subagent windows. Seed 2043, used before review, had been picked mainly for size, and its ratio, 1.33, was outside the band its test name claimed.
