# P0.8 — Flags, shadow mode, wide events, circuit breaker

**Outcome:** merged. Each delivery point now has an `off | shadow | on` flag, read from files on every event:
- `off` is identity;
- `shadow` runs the pipeline, prints nothing, and writes only `delivery.shadow.log`.

Every memory hook invocation appends one text-free wide event. An unhandled exception at an `on` point forces it to `shadow` for 24 h. Every `hooks.json` entry point exits 0 with nothing on stdout or stderr, even with no `bun` on PATH. `off` and `shadow` are green on all 34 arms that drive a delivery point (0 of 39 before), and `fail-open` is green. With no flag file, delivery is unchanged.

## What changed

**Flags (EXECUTION X7), `src/memory-flags.ts`.**
- There are seven flags: `deliver.submit`, `deliver.session_start`, `deliver.subagent`, `deliver.batch`, `deliver.failure`, `guard.context` and `guard.ask`.
- **Precedence:** environment > repo file > user file > default.
  - The environment variables are `EDEN_FLAG_DELIVER_SUBMIT`, …, and `EDEN_POLICY_GUARD` for `guard.ask`.
  - The repo file is `<repo>/.eden/flags.json`. The repo is the nearest folder holding `.git`; a linked worktree's repo is its main checkout. No git process runs.
  - The user file is `$EDEN_HOME/flags.json`.
- **Defaults** (no source sets the flag) are what each point did before flags existed:
  - `on` for `deliver.submit` and `deliver.session_start`;
  - `shadow` for the points not built yet;
  - `off` for `guard.ask`.
- **Unknown values** resolve to `off` (`shadow` for `deliver.submit`). The master `EDEN_MEMORY` follows the same rule now: any value other than the on words and `readonly` is `off` (`src/memory-consent.ts`).
- **Lifecycle:** release flags must be removed by 2027-06-30. A test fails after that date; the kill switch `guard.ask` has no date.

**Shadow and off at the hook** (`packages/cli/src/memory-hook.ts`, `src/memory-ledger.ts`, `src/memory-window.ts`).
- **`shadow`:** the point writes its `turn`, `deliver` and `epoch` records to the window's `delivery.shadow.log` and prints nothing.
  - Its refractory rule reads the live and shadow ledgers; a live point reads only the live one.
  - `hturn` counts turns from both ledgers.
- **`off`:** writes no ledger and retrieves nothing, but the Submit is still encoded.
- **Compaction:** the epoch goes to every ledger file the window has, and to the ledger of each mode in use (review round 1).
- **`would_preempt`:** logged at a shadow Submit. It lists the cids of shadow deliveries from the last 3 human turns that the prompt states again: one of its sentences, or the whole prompt. A slot counts only at the same value.
- **PreCompact** answers only as `deliver.submit` allows, and writes no ledger.

**Wide events** (`src/memory-events.ts`). One line per memory hook invocation, in `<memory root>/hook.log.d/<yyyy-mm-dd>.jsonl`. Fields:
- `ev`, `point`, `mode`, `flags`;
- `repo` (a hash of the repo top), `win`, `hturn`, `prompt_id`, `prompt_hash`;
- `submit` (`human` or `non-human`); a non-human one also has `nonhuman` (the D24 rule it matched) and `preamble`;
- `turn_mode`, `cids`, `drops` (validity, gate, residual, refractory, shape), `would_preempt`;
- `ms`, `aborted`, and `err` (the error's class and throwing line, never its message).

No prompt or row text is written. `EDEN_MEMORY=off` and `readonly` write none.

**Circuit breaker** (`src/memory-breaker.ts`).
- **When it checks:** after an exception or an abort at an `on` point.
- **The budget:** over a fixed 200 of the point's latest wide events, more than 0.1% exceptions or 0.5% aborts. One exception, or two aborts, trips it.
- **What it does:** writes `$EDEN_HOME/flags.auto.json`, which forces the point to `shadow` for 24 h.
- **The notice:** the next SessionStart whose flag is not `off` tells the user once (a `systemMessage`).

**Fail-open.**
- `plugins/eden-memory/hooks/hooks.json`: every command ends in `2>/dev/null || true` (was `|| echo '{}'`).
- `runMemoryHookStdin` prints nothing when it has nothing to say (it printed `{}`).
- `eden doctor` probes the hook without that suffix, so a crash still shows.

**`eden doctor --memory`** (`packages/cli/src/doctor-memory.ts`) has three new lines:
- `flags`: each flag's mode and source, and an unknown value is named;
- `breaker`: forced points and how to clear one;
- `kill switches`, narrowest first: a point's flag (the repo file wins in a repo), then `EDEN_MEMORY=off`, then `claude plugin disable` / `disableAllHooks`.

**Also changed:**
- `scripts/submit-timing.ts` runs each side's `hooks.json` command;
- the plugin README documents the flags;
- EXECUTION §5 and A5 have "Built in P0.8" notes, and A5 records `abort_rate`.

## Decisions made

- **Absent flag means the point's default, `on` for the two points that deliver today.** A5 §4 defines `on` as the arm run with no flag file, so green arms stay green. EXECUTION principle 2 ("merge dark") is about new behaviour, and X8 stage 1 writes `shadow` into a flag file. So merging P0.8 changed no delivery. X7's "unknown values" is read as values a source sets that are none of the three modes.
- **The master `EDEN_MEMORY`'s unknown values are `off`**, as X7 says ("this reverses today's `memoryConsent`").
- **The repo file is `<repo>/.eden/flags.json`**, like D3's in-repo `.eden/scopes`.
  - The repo is found by a stat walk to the nearest `.git`, with a linked worktree mapped to its main checkout: D1's common-dir idea without a 20–40 ms git call per event. P0.5 brings the real repo key.
  - X7's precedence lets a repo file beat the user file. The doctor says so; the security question is filed for P2.3.
- **Breaker rates are over a fixed 200**, and checked only after an exception or an abort (a rate rises only then).
- **A breaker entry expires after 24 h.** EXECUTION §5 says both "forced to `shadow` for 24 h" and "Re-enabling needs a new stage evaluation". I read the first as the hold, and the second as the only way to turn a point back on sooner. If the cause remains, the next exception trips it again.
- **The breaker's notice is a `systemMessage`** (shown to the user, not the model) at the next SessionStart whose flag is not `off`. `off` stays identity.
- **A compaction epoch is written even while a point is `off`, when the window already has a ledger.** A4 §4 (a compaction re-arms everything) is weighed against A5 §4 (`off`: no ledger write). Without the epoch, turning the point back on would revive deliveries from before the compaction. The `off` arms start with no ledger, so they still see none. With every point `off` and no ledger yet, nothing is written. EXECUTION says so.
- **`would_preempt` is matched by content-word hash** (a slot needs the same value), as an estimate until P5.1 logs D30's `restate`. **`would_ask` waits for the guard** (P2.3).
- **`aborted` is always false**, because no budget abort exists before P4.2. So `abort_rate` is 0 by construction, stated wherever it is reported.
- **PreCompact has no point of its own.** It answers as `deliver.submit` allows, writes no ledger, and the breaker does not cover it. Its wide event has `cids` but no `point` or `mode`. Under `shadow` its refractory read is the live ledger alone. Nothing prints in that case.
