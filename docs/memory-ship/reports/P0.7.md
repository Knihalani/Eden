# P0.7 — Cache-safe placement (wrap / OpenAI inject)

**Outcome:** merged. The wrap and `AgentMemory.inject` put a turn's packet at the tail of its human message and keep it there in every later request, so a conversation's cached prefix stays byte-identical. Measured with the pre-registered conversation: 0 prefix breaks in 11 request pairs on each of four paths, against 7 on `main`. The wrap now answers a turn as the hook answers a Submit, and reads a request by source (D12). `eden setup`'s hooks now run memory as the plugin does, and they print nothing.
**PR:** https://github.com/Knihalani/Eden/pull/128 · **Merge commit:** rebase-merged; the head of `main` after the merge is in the PR (no follow-up commit, to spare a CI run) · **Date:** 2026-10-10

## What changed
- **Placement (D29, A4 §5.9).**
  - **Where the packet goes.** It ends the turn's human user message: the end of a string, or a text block after the message's own blocks. It never goes into `system` or before the history. The Anthropic wrap puts its Know card in the same tail.
  - **Later requests.** Every later request of the conversation carries the same text on that message: each tool-loop step, and each later turn. This is how the hook's packet stays in Claude Code's transcript.
  - **Turn keys.** A message is keyed by a hash chain over the messages up to it. `cache_control` markers, place fields and the wrap's own tail are left out of the key.
  - **When a packet is computed.** A turn's packet is computed when its message ends the request (the turn's opening request), and reused while the tool loop follows. A turn unused for 1 h is forgotten.
- **The Anthropic proxy** (`handleAnthropicMessages`):
  - It runs memory before setting its cache breakpoints, so the last breakpoint covers a new turn's packet.
  - It turns every message's string content into its one text block, so a message keeps one shape whether or not it ends the request, with or without a packet.
  - Before, only the last message was converted. The next request sent it back as a string, which changed the turn's message (found while planning the e2e; see the prereg amendment).
- **A turn is answered as the hook answers a Submit (A4 §5.1).** The steps run in this order:
  1. the user's forgets (A6 §3);
  2. the turn mode (`ack` and `continuation` get no packet);
  3. retrieval;
  4. validity;
  5. A7 §4's episode gate;
  6. D26's residual, read from the request's own last typed prompts and the assistant text between them;
  7. A4 §4's refractory rule, over the packets the request still carries, with its distances in bytes after the delivering message;
  8. D28's shape and D14's wording.

  `src/memory-delivery.ts` holds steps 4–7, which the hook's Submit now calls. Its behaviour is unchanged: guard digests are identical.
- **Sources (D12).**
  - A request's `system` and `developer` text is the host's and is not stored. `injectBody` used to observe `body.system` as a user turn.
  - A user message's text blocks are `src:user` when typed. Wrappers, such as Claude Code's reminder blocks, and D24's non-human submits are not memory.
  - Pasted spans become `src:paste` episodes, and assistant text `src:agent`.
  - Tool output is not encoded by `inject`. The wrap's tool-trace observer records it, now as `src:tool` (round 1): an episode without its instructions, never a fact or a pin.
- **Encode once.** A message is encoded the first time a request carries it, as the client's delta (A4 §3.3).
  - Messages up to the last one this process encoded are history read again (`reread`), as in a conversation first seen after a restart.
  - The message that opens a turn is encoded, and its forgets recorded, every time. A new conversation may open with an earlier one's words.
  - Read-only memory writes and marks nothing.
- **`eden setup`'s Claude hooks mirror the plugin's (D34, A4 §5.5).**
  - PostToolBatch records each batch. PostToolUse runs as `batched`, doing only Eden's compiled-tool work.
  - Stop is a sync `stop-fast` and an async `stop-sleep`, and SubagentStop is async.
  - The stage reaches hookd as `?stage=` and the CLI as `eden hook <stage>`.
- **Fail-open output (EXECUTION §5).**
  - Every setup command drops its calls' stderr and ends in `2>/dev/null || true`; `preHookCommand` also uses `curl --fail`.
  - `eden hook` and hookd print nothing when memory has nothing to say; they used to print `{"ok":true}`.
  - `eden hook` used to wait out its 2.5 s timeout timer on every call. It now exits when its answer is in. My runs (`/usr/bin/time -p`, a Stop payload, `EDEN_HOOKD=0`, temp home, empty store): 2.59 s before the fix, 0.08–0.09 s after. The reviewer's (3 runs each, with the final-tree CI running alongside): `main` 2.80 / 2.93 / 2.84 s, the slice 0.33 / 0.29 / 0.30 s.
- **Key files:**
  - `src/memory-wrap.ts`: placement, turn memo, sources, encode-once, a turn's answer; `injectedPackets` reads packets back.
  - `src/memory-delivery.ts`: A4 §5.1 steps 5–7, shared by the hook and the wrap.
  - `src/memory-hook-packet.ts`: `packetOf` gives the packet and the notes it delivered.
  - `packages/wrap/src/know-inject.ts`, `anthropic.ts`, `tool-observe.ts`: the wrap paths.
  - `packages/cli/src/setup.ts`, `hook.ts`, `hookd.ts`, `doctor.ts`: setup's hooks and their output.
  - `benchmarks/wrap-cache/prefix.ts`: the pre-registered measure.
  - Tests: `packages/wrap/src/cache-placement.test.ts` (the gate), `src/memory-wrap.test.ts`, `packages/wrap/src/tool-authority.test.ts`, `packages/cli/src/setup-memory-hooks.test.ts`.
- **Tests that read the old placement.**
  - About 30 test files read the packet from a `system` message; they now use `injectedPackets`.
  - Assertions on the legacy `[fact · 0m · user]` tags and on 6-bullet packets now assert D14's wording and D28's shape.
  - Cues that restated their own row were reworded, because D26 counts the current prompt as residual.
  - Seven benchmark harnesses (lme-v2, memoryagentbench, memory-holdout, memory-bakeoff) read `injectedPackets`.
  - The locked 2k bench reads the packet from its header on (`fixture:` commit).

## Decisions made
- **Every later turn keeps its packet, not just the tool loop.** D29 says "for every tool-loop step of the turn". Dropping a packet at the next turn would change that message and break the cache from there on. Keeping it is what the hook's packet does in the transcript, and it is what makes the refractory rule's "still in the window" readable from the request itself.
- **The refractory rule reads the packets still in the request.** It uses an in-process memo of each turn's delivered `(cid, ver)`, with A4 §4's distances measured in bytes after the delivering message. It does not use a window's `delivery.log`: the wrap has no window key. Filed to P1.1.
- **A turn's packet is recomputed whenever its message ends the request.** Reusing it could hand a new conversation that opens with an earlier one's exact words a packet that still holds something the user has since forgotten (A6 §3). Accepted by the reviewer; the costs are under follow-ups.
- **Tool output stays with the tool-trace observer** (compact traces, and page trees in experience files: M23.2), now as `src:tool`. `inject` reads tool results only as D12's paste-rule evidence.
- **The Anthropic proxy normalizes every string content to one text block**, rather than having the wrap emit blocks. This covers turns with no packet too, and requests where memory is off.
- **D28 skips a bullet over 900 bytes rather than cutting it** (as the hook does). The wrap therefore no longer delivers an oversized fact, procedure or ICL shot that legacy `packNotes` let through. The M20.3 tests now assert the skip.
- **D26 counts the current prompt as residual.** A cue that restates a row no longer retrieves it, and an ICL shot repeated as the prompt is not delivered; "The movie was great. label:" still retrieves "… label: 28".
- **`stderr` silence follows the plugin** (`2>/dev/null || true`). Gemini CLI, Codex and OpenCode now get empty stdout instead of `{"ok":true}` (not verified against each host).

## Not done / follow-ups
- **Filed to P1.1** (PROGRESS): the wrap's memo is per process. It writes no `delivery.log`, so shadow measures and `would_preempt` never see wrap traffic, and a restart forgets which packets earlier turns carried. The wrap also has no X7 flag point; decide whether `deliver.submit` governs it before stage 2.
- **Known limit (by choice): two conversations, one opening.** When two conversations open with the same words within an hour and get different packets, the earlier one's next request carries the newer packet on its first message: one prefix break. A client's side requests that end on the turn's message (Claude Code's small side calls, for example) recompute it the same way. The main conversation keeps its bytes only while the store returns the same packet.
- **Edited history.** When a client edits earlier history, every message after the edit gets a new key and is encoded again as new, not reread. A test shows that an old statement encoded again does not displace a newer value.
- **Pre-existing, no owning slice: setup's fallback can lose the payload.** When hookd is down but its key file exists, curl reads the hook payload from stdin before it fails, so the `bun … hook` fallback gets nothing and the event is lost. Fix by buffering stdin in the command, or by letting `eden hook` read a saved copy.
- **Async `stop-sleep` under hookd.** It sits in hookd's serial queue, so the next Submit waits behind it; P0.6 measured `stop-sleep` p99 at about 264 ms. Under `claude -p`, Claude Code cancels the async handler at exit (seen in e2e 2 after its work was logged); interactive sessions keep running.
- **Quarantined tests:**
  - The M43 forget tests (#42) still fail before any forget: "what database do we use" retrieves nothing for "Use postgres." (no shared word). This is a retrieval fixture issue, not the wrap's authority, so they stay quarantined.
  - `memory-order.test.ts`'s quarantined system-observe-throw test has no subject now (the system prompt is never observed). It needs a user decision to delete.
  - `src/memory-harmed.test.ts` (#50, quarantined as a file) still fails as on `main`.
