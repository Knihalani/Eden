# P0.3 — Ids, clocks, persisted validity

**Outcome:** Merged after four code-review rounds (APPROVE; the user allowed one round past the three-round limit). Concurrent and sequential writers no longer lose rows: `spawn-writers` keeps 200/200 facts in 20 of 20 repetitions, where `main` kept 81–87. A later plain statement now supersedes a numbered-list item, the supersession survives a reload, and ages are real. One guard is missed and filed: the 1,000-turn soak is slower than `main`'s, because `main`'s store stays small by losing rows (#98).
**PR:** see the merged PR titled "P0.3: Ids, clocks, persisted validity" · **Merge commit:** recorded in the follow-up report commit · **Date:** 2026-10-08

## What changed
- **Row ids are ULIDs** (#98, A1 D2). Two hook processes never mint the same id, so a later writer no longer replaces an earlier writer's rows.
- **Every row gets a per-store `seq`** (A4 §1), claimed under the store lock `<root>/.lock` with a 50 ms wait; the counter is `<root>/seq`.
  - A writer that cannot get the lock in time appends its rows to `pending.jsonl`. So does a writer whose store file's own lock stays taken; before, those rows were silently lost (A1 D11).
  - Sleep settles pending rows: it gives each its `seq` and merges it into its store.
  - While settling, time decides between a pending row and a stored row giving the same subject another value, since the pending row got its seq late.
  - A pending copy of a row the store already holds brings only its seq and validity.
  - A sleep that dies mid-settle loses nothing: the taken file is kept until it is done, and lines appended to it late are put back.
  - The store is the memory root until P0.5 keys stores by repo.
- **Rows persist `t`, `seq`, `invalid_at`, `invalid_by` and `valid_until`** (A1 D3).
  - `invalid_at` is the seq of the row that superseded this one; `invalid_by` is that row's id while it waits for its seq.
  - Validity only moves from live to superseded: a process holding a stale copy cannot undo another process's supersession.
- **Order is by `seq` everywhere; list numbers are not clocks** (A1 D8). This covers rows, `assemble`, the semantic store, sleep and hop completion.
  - A heading over a numbered list ("Notes for this repo: 1. … 2. …") is stored item by item, so a later statement can supersede one item.
- **Supersession follows A4 §3.0, §3.1 and D31.**
  - Only typed rows supersede: tool and assistant rows do not.
  - When both rows are slot-shaped, the old value is logged as `stale_for` for older text, including the whole-prompt episode.
  - Sleep moves a losing fact row to history (`invalid_by` the winner) instead of deleting it. Reading the transcript again therefore never learns the old value anew.
  - A user's restatement of an old value is learned again only if it is the last statement the user typed about that subject in the batch.
  - The hook marks its transcript reads `reread`, and a re-read never re-learns.
  - The Submit hook encodes the transcript before the prompt.
- **Real ages, on a simulated clock when given.** `EDEN_NOW` is the memory clock: it stamps row times, validity records and gist times, and ages are measured against it. A row whose time was never kept claims no age (A1 D6: no more "0m").
- **`eden memory dump --json`**, the `spawn-writers` contract: every store's rows under A4 §1's names, the rows waiting in `pending.jsonl` (each listed once), and every window's ledger records.
- **P0.2's validity follow-ups** (D31's "Built in P0.3" note):
  - plural stems match their singular ("caches" / "cache");
  - a capitalized word opening a clause after a label, colon or list marker is exempt;
  - no bare list marker survives as a bullet;
  - a revocation keeps a joined rule about another action.
- **Performance** (after the first measurement):
  - row needles are computed lazily;
  - sleep skips narrative and ICL rows before its text tests;
  - SessionEnd only encodes and leaves the sleep to the Stop before it, because Claude Code cancels SessionEnd at 1.5 s (R0).

## Decisions made
- **The store is the memory root until P0.5** (A4 §1 says per repo). `seq`, `.lock` and `pending.jsonl` live there, beside the shared semantic store and `validity.jsonl`.
- **`invalid_at` is a seq** (A4 §3.1: "`invalid_at = seq`"). While the superseding row waits in `pending.jsonl`, the superseded row carries `invalid_by` (the superseder's ULID); sleep resolves it. Readers treat either as superseded.
- **The seq lock guards only the counter.** The store file keeps its own lock, so the 50 ms wait covers a sub-millisecond critical section. A store-lock failure also pends rows instead of losing them (A1 D11).
- **List numbers.** "Delete the numbered-list-beats-everything rule" is read as A1 C2's "list numbers are not clocks".
  - Every place that used a serial as a time now uses the row's time and store order: rows, semantic store, `assemble`, sleep, hop completion.
  - Within one text the later statement wins.
  - Legacy tests that encoded the old rule (M20.1/2, M21, M22, M40) were rewritten to the new rule. Tests whose own point was something else were reordered so they keep it.
  - A heading's numbered list is split into items (`listUnderHeading`). Without that, the gate's own scenario stores the whole list as one speaker-labelled row that nothing can supersede.
- **Superseded rows stay as history.** Sleep marks losers superseded instead of deleting them (A4 §3.1: superseded values go to history). Deleted rows were re-learned from the next transcript read as the newest value, a churn the A1 D3 fix made visible.
- **Restatement** (A4 §3.1, D12):
  - The `observe` API cannot tell new messages from a re-read, so a superseded text is re-learned only at the position of the user's last typed statement of its subject in the batch.
  - The hook passes `reread` on every transcript read, and a re-read never re-learns.
  - Called directly without the flag, `observe` re-learns a batch whose last typed statement is the old value, even when the superseder came from outside the batch (the reviewer's probe p4). That is accepted, because requiring the superseder inside the batch would block a genuine one-message restatement (M7.3).
- **Only typed rows supersede** (A4 §3.0, A6 §2.1). Before P0.3 an assistant's or a tool's copula superseded a user's row only until the next reload. With `invalid_at` persisted, that would have become durable poisoning.
- **D31 `stale_for` from supersession.** When both rows are slot-shaped (P0.2's `legacySlot`), the superseded value is logged like D7's switch: the old value, tied to its subject words.
- **The comma case changed after results** (round-1 finding 5). P0.2's follow-up listed "comma" among the clause openings to exempt; P0.3 exempts after a label, colon or list marker only. After a comma a capital marks a name ("Redis, Make and Docker"), and missing a stale mention there is worse than dropping a sentence (G2 over G1). The red commit's case "Before the deploy, Make sure …" now asserts the opposite, and D31's note says so.
- **Times.** Rows carry the time they are encoded, not the transcript message's timestamp (A4 §3.3, P0.6). Validity records are compared with rows by time: a retraction's record is written before its Submit's own rows, so a later restatement is newer.
- **Ages.** A time below 1e11 ms is a legacy list serial and shows no age.
- **`rewind` recorded green honestly:** its `no-postgres` passes through supersession, not rewind detection. A P0.6 follow-up asks for a check that tells the two apart.
- **SessionEnd only encodes** (R0: a 1.5 s budget). What arrives after the last Stop is stored but not slept over in that session (filed to P0.6, D34's idle sleep).
- **Follow-up row 78's "persisted `invalid_at` replaces `validity.jsonl`"** is deferred to P3.3. The clause-level log still carries retractions, switches, revocations and `stale_for` across gists and other sessions' rows; rows now keep `t`, so its time comparison is real.
