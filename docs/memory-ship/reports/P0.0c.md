## What changed

- **All 44 arms of A5 §4 exist and run.** Each is a script played through a plugin's hooks in the harness, one process per hook, or a product entry point driven as a process. Each returns named checks; a failing check names the A5 assertion, or a control the assertion needs, that did not hold.
  - floor: 10 arms + `fail-open`;
  - place: 5;
  - delivery: 11;
  - cues and policy: 17 (`scale-20k` and `scale-1e6` apart).
- **`arms.json` records today's result for every arm and flag state.** For each it gives:
  - the slices whose PROGRESS gate cites it;
  - its A5 text;
  - for `on`, `off` and `shadow`: `red` with the exact failing check ids and why, or `green`.
  Today, against `plugins/eden-memory`:
  - `on`: 39 red and 5 green;
  - `off` and `shadow` (for the 39 arms with a delivery point): 39 red each.
- **CI holds every run to the record** (EXECUTION X4: "CI fails if a red arm fails for a different reason").
  - The gate (`arms/gate.ts`, eight `<group>.gate.test.ts` files) runs every recorded state at CI scale against `plugins/eden-memory`.
  - It fails when a red state fails any other set of checks, when a red state passes, and when a green state fails.
  - A check today's plugin flips between identical runs is listed as `unstable` and left out. One check is: `scoped`'s `junk-on-disk`, explained below.
- **Flag runs (A5 §4 header, X7).** `off` and `shadow` write `~/.eden/flags.json` with every delivery-point flag set, and are judged by generic checks:
  - `off`: `ran`, `exit-0`, `quiet` (nothing printed at a delivery point), `no-context`, `no-ledger`;
  - `shadow`: the same, plus `shadow-ledger`, `wide-events` and `no-live-ledger`.
- **Every arm can pass.** It passes, in every recorded flag state, against a reference:
  - the scripted plugin in a new reference mode, with the arm's answer table in A4 §5.8's wording;
  - a reference CLI implementing each entry point the arms define.
  Each `<group>.reference.test.ts` runs them. Every "never X" arm also has a control, so a silent plugin fails it.
- **Entry points the arms define.** Arms whose subject sits inside Eden drive a product command, and the slice that turns the arm green provides it. Each arm's header holds the contract, and A5 §4 lists them:
  - `eden memory dump --json`;
  - `remember --jsonl -`;
  - `extract --jsonl -`;
  - `scopes --json <path>…`;
  - `migrate --dry-run --json | --apply | --rollback`, with `EDEN_MIGRATE_CRASH_AFTER`;
  - `aliases --batch FILE --json`;
  - `eden sleep --idle --after 0`.
- **Harness extensions** (`harness/session.ts`, `runner.ts`, `window.ts`):
  - repos sharing one home (`projectName`);
  - sessions started in a git worktree (`addWorktree`, `SessionPlace`: cwd, branch, transcript directory, `CLAUDE_PROJECT_DIR`);
  - the simulated clock handed to hooks as `EDEN_NOW` (`clockEnv`, off unless set);
  - `permissionDecisionReason` read from PreToolUse answers;
  - a fork subagent's window seeded from the parent's (simulated; see Decisions).
  The canonical replay keeps its digest.
- **No product code changed.**

## Decisions made

- **An arm's red reason is its exact set of failing checks, not a message.** The gate compares sets, so a red arm that starts failing a different check is caught, as EXECUTION X4 asks. A check today's plugin flips between identical runs is named `unstable`, with its measured flips, and the gate leaves it out.
- **Flag runs set every delivery-point flag, not only the arm's own** (A5 §4 header: "its delivery point's flag").
  - With every point off, identity and "no ledger write" can be asserted for the whole run.
  - Per-point independence is P0.8's unit test.
  - "No stdout" is read strictly: today's `{}` fails `quiet`, as CLAUDE.md's "prints nothing" says.
- **`fail-open` injects a real fault, not a product seam:** the memory root is a regular file, so every store access throws. The script fires every hook event Claude Code has (`covered` checks the plugin's registered ones all ran).
- **Arms that must be passable before memory is per repo** (P0.3, P0.4, and others with no cross-session clause) run in one session. They use compaction with a blank summary to take statements out of the window: after it, only a packet can meet a need, and a stale value can only come from the store. Arms about sessions span sessions, a simulated day apart.
- **Controls.**
  - Every "never X" arm has one: `negation`, `poison`, `secrets`, `nonhuman`, `shadow`, `citation`, `budget`, the scale arms' small store; `continue` and `residual` get theirs from a second cue that must pack.
  - A control's cue shares words with the fact it needs. It tests that the plugin delivers at all, not cue quality (CueBench does that).
  - Three cues were changed for this reason after a first run showed today's lexical match missing them: `compaction` and `re-eligibility` now say "merge the PRs", the rule's own word, and `nonhuman`'s control asks for the database.
- **`cross-session` and `worktree` follow A5's "fact in session 1; cue in session 7".**
  - Sessions 2–6 each state one unrelated fact, as real sessions state things.
  - `worktree` writes from `.claude/worktrees/agent-x`.
  - Both pass today, as recorded: the plugin's global gist store carries the fact.
  - I did not keep reshaping the scripts until today's plugin failed.
- **`policy-recur` reads each clause against its contrast** (D9, D11):
  - not a pin after one session, a pin after two;
  - not in repo C before the confirmation, there after it.
  Without the contrasts, today's global gist store passed two clauses for the wrong reason.
- **Entry points.**
  - An arm whose subject is inside Eden (rows, ids, the scope catalog, extraction, migration, aliases, sleep) drives a product command, as a user or scheduler would: a process, in the repo, with the hooks' environment.
  - The harness never parses Eden's store files.
  - `migrate` and `sleep` follow the commands EXECUTION §9 and A4 §6 name; `remember` follows D11's. The others are this slice's.
  - Until a slice provides one, the arm fails at that step for that reason, and does not run the rest.
  - The slice that builds an entry point may revise its contract in a visible `fixture:` commit.
- **`EDEN_NOW` (epoch ms) is the clock seam** handed to hooks and the CLI.
  - Without it, a product sees the real clock and none of a script's skipped days (7-day intent expiry; a gotcha a week later).
  - P0.3 (clocks) should honour it.
- **`re-eligibility` reads "399 KB / 401 KB" as just under and just over both readings of 400 KB.** It lands in 390,000–399,900 and 409,700–425,000 bytes of the main transcript, measured as the hook sees the file.
- **`secrets`:**
  - 30 shapes × 4 channels × 3 positions, 360 cases.
  - Positions: opening a message, inside a sentence, an env-file line. A5's "pasted" is the paste channel. "Split" (a secret across two events) has no rule in D13, so it is not built.
  - A shape recognisable only by its keyword keeps the keyword before the value, as D13's rule reads it.
  - Values come from a seeded stream with split prefixes, so nothing secret-shaped is committed.
- **`migrate`:**
  - The legacy stores were written by today's plugin. Five secret shapes it stores unredacted are placeholders; only shapes its tokenizer keeps whole qualify.
  - The no-transcript session is mapped through R-7's session map (EXECUTION §1, §9).
  - `secret_bytes` counts the new store only: the read-only legacy tree and the backup must keep the old bytes for a byte-identical rollback.
  - A crash leaves either the old memory tree and no legacy tree, or exactly the completed apply's tree.
- **R5 rows.** R3 F9's root-only monorepo row expected a two-segment fallback, which D3 (the R5 rule) replaced, so the row lists its services in `.eden/scopes`. F9's worktree row is R5's row k.
- **CueBench through the hooks.**
  - The fixture's live memories are planted (R1 planted only live ones).
  - Each cue is a fresh session: its previous user turn (R1 `prev_turn`, else "look at these files") with Reads of `last_paths`, then the cue.
  - A bullet carries the memory whose content tokens it holds at ≥ 60% (best match), so a reworded bullet still counts.
- **The scale arms:**
  - "Gold recall unchanged" (P6.1) is recall at N ≥ recall on the same world with no filler, and the small store must meet some needs.
  - Silence is A5 §2's 5%; p99 is Submit's.
- **Sleep** runs where an arm needs it, between sessions, after 45 simulated idle minutes: heavy sleep comes at ≥ 30 min (A4 §6). No check asserts that the command exists; behaviour shows whether sleep did its work.
- **Fork subagents.** A4 §5.3 and A5 `subagent` name a fork subagent that inherits the parent's context. Claude Code 2.1.285 rejected `subagent_type: "fork"` in the end-to-end session ("Agent type 'fork' not found"). The harness simulates one (agent type `fork`, window seeded from the parent's) so the clause runs, and labels it simulated in the record and the code.
- **CI scale:**
  - `scoped` runs 48 junk turns (full: 4752, then 15840);
  - `budget` runs 100 human turns (full: 300); at 100, today already exceeds 6k tokens;
  - `spawn-writers` runs 1 repetition (full: 20);
  - the fixture arms ask a fixed subset (the first cues of each category; full: every cue).
