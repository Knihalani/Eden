# P3.5 — Cascade + first-touch delivery

**Outcome:** merged. A folder's own slot value now hides an ancestor's (D5 for typed facts, not just mined ones), and a PostToolBatch's first touch of a scope can deliver that scope's facts (`deliver.batch`, `shadow` by default). `cascade` and `first-touch` are green. `scoped` at full scale still misses its needs and junk for the 2,000-row store cap, as `main` does; the user accepted that until P6.1.
**PR:** https://github.com/Knihalani/Eden/pull/142 · **Merge commit:** MERGE_SHA · **Date:** 2026-10-15

## What changed
- **D5, cascade with override, for every slot fact** (`cascaded`, `src/memory-place.ts`, replacing P3.4's mined-only `withoutOverriddenMined`). It runs at Submit, SubagentStart and PostToolBatch.
  - A slot fact, typed or mined, is not delivered at a read-set folder below its scope when a folder between has its own live row of one of its slots, whatever that row's value. "We use node 20 across the repo" says nothing at apps/web once "apps/web runs node 22".
  - A row stating two slots is dropped when either is overridden (G2 > G1). So is an ancestor's value in a two-scope read set where one folder overrides it.
  - A split statement ("we use pnpm and vitest" typed in apps/web: two rows of one text, A4 §3.2) is recognised by its other part. Where that part's value does not hold, the part is said by its own keys alone ("Package manager: pnpm"), at the root and at siblings.
  - The cost is one pass over the live rows, cheapest test first, only for the slots the candidates state.
- **PostToolBatch first touch** (A4 §5.5, D23: `firstTouch` in `packages/cli/src/memory-hook.ts`, `pointOf` → `deliver.batch`).
  - A catalog scope below the root that no batch of this window touched in this epoch delivers at most 2 of its own slot facts, typed or cited. The batch's tool and Bash paths count, and at most 2 new scopes per batch.
  - The facts go through validity, D5, the residual, the shadow set, the ledger and the budget.
  - Touches are hashed `touch` records in the window ledger (`firstTouches`, `src/memory-ledger.ts`, kept in the snapshot), so a compaction or a clear makes every scope new again.
  - A subagent's batch uses its own window, transcript and shadow set by type.
  - X7: `off` records and delivers nothing; `shadow` writes `delivery.shadow.log` only. Read-only consent delivers nothing.
- **Follow-ups closed:**
  - `..` in a path a row names is resolved, and a reading that leaves the repo names nothing (`namedScopes`).
  - Validity reads a clause's own folder with the scope catalog where the point has it (`placePhrase`): "src/db.ts …", "/home/…" and "ci/cd …" are no folder.
  - SessionStart(compact)'s gists are read at the root and at the window's read set. A legacy supersession recorded in a folder (`supersededAt`) holds for a line naming that folder, or one read from it.
  - The light sleep assembles legacy winners per scope and states each by its scope ("In packages/cli, stack uses Redis", `scopedWinners`, `src/sleep.ts`).
  - SessionStart briefs the pins visible from the last session's read set, read from the window `last-session.json` names (`likelyPlace`, `lastSessionWindow`).

## Decisions made
- **The root is never a new scope** (A4 §5.5 "a new scope"). Every session starts in the repo, its facts reach the cue that needs them, and in a single-package repo every batch would otherwise brief the root's facts unasked.
- **A first touch's items are the scope's own keyed slot facts.** An ancestor's values reach the folder by cascade at their cue; "STRONG only" (D23) is read as keyed slots.
- **Touches live in the window ledger as hashed records.** `ctx.log` keeps only 3 turns, and the ledger already carries epochs, folds and the live/shadow split. A shadow point reads the live touches too. A rewind does not un-touch a scope (fewer deliveries, never more).
- **Bash `cd`/path arguments count as touches**, as D4 counts them as places. At most 2 new scopes per batch, as a read set holds at most 2 (D4).
- **Read-only consent delivers nothing at a batch.** PostToolBatch stays a writing event; without a ledger record every batch would deliver again.
- **D5 counts "a row of its own" whatever its value** (review round 1). A row stating two slots goes when either is overridden. Facts of no D7 slot keep P3.2's cascade without override, since their legacy subject is no key.
- **A split part is restated by its own keys where its other part's value does not hold** ("Package manager: pnpm"), rather than shown whole or withheld. The P3.3 follow-up suggested "only where every value holds"; review round 1 showed that withholds a true root value (G1).
- **The likely scope is read from the last session's window** (`last-session.json`, P3.4), not from a new `last_read.json`. That window's `ctx.log` holds its last 3 turns. With no such window, no pin is left out.
- **The catalog's clause folder applies only where the point has the catalog** (Submit, SubagentStart, PostToolBatch). The sleeps and SessionStart keep P3.3's reading.
- **`fan-out`'s check reads the whole turn** (78ff42814). A5 states it per turn, and the batch's first touch now gives the bullet.
