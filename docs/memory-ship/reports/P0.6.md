# P0.6 — Delta encode, PostToolBatch recording, rewind detection, stop-fast

**Outcome:** merged, with one guard missed and filed. The hooks no longer re-read the transcript or sleep over the whole store at Stop: over a 1,000-turn session, Submit's p99 grows 48.0 ms instead of 541.7 ms, and Stop's sync part shrinks instead of growing 3.7 s. A rewind takes back what the abandoned branch said. Missed: the R6 replay's `packet_rate` is 50/122 (41.0 %) against P0.2's ≤ 30 % (`main` 18/122 on the same sessions), filed to P4.3 with its cause.
**PR:** https://github.com/Knihalani/Eden/pull/127 · **Merge commit:** rebase-merged; the head of `main` after the merge is in the PR (no follow-up commit, to spare a CI run) · **Date:** 2026-10-10

## What changed
- **Delta encoder (A4 §3.3).** Each window reads its transcript once, line by line, from a mark in `windows/<win>/hwm.json`.
  - The mark holds the offset after the last complete line read, the typed prompts, a rolling map of the last 5,000 lines to their turn, and the `promptId`s a rewind abandoned.
  - It advances only under `hwm.lock`, taken without waiting. A read that finds nothing new leaves it unwritten.
  - A window with no mark starts at the transcript's last 256 KB.
  - Typed prompts are left to their Submit's payload (R0 F8; D12's paste split).
- **Rows name their origin.** Rows carry `src_uuid` (their transcript line), `prompt_id` (their turn's) and the line's time (A4 §1).
- **Rewind detection.** A typed prompt whose parent turn is not the newest typed prompt is a branch point.
  - The prompts back to that turn are abandoned. Their rows go to history, except a text the current branch says again.
  - Ledger deliveries made on the abandoned branch no longer count. The ledger reads this from `hwm.json`, not from a 1.5 MB tail parse at each Submit.
  - A compaction's boundary is followed by `logicalParentUuid`. A parent outside the map abandons nothing.
- **Submit** reads the delta, then one 256 KB tail: the residual, `q_turn`, the paste rule's tool results, and the newest assistant line. The agent's last message comes from `qprev.json` unless that tail holds a newer assistant line.
- **PostToolBatch (A4 §5.5)** replaces PostToolUse in the plugin. It writes:
  - one `ctx.log` record for the batch: paths, Bash exit codes and D10 error signatures;
  - the batch's tool traces;
  - the main window's delta.

  `stop-sleep` compacts `ctx.log` to the last 3 turns past 32 KB.
- **Stop is split (D34).**
  - The sync `stop-fast` writes `qprev.json` and the crons, and opens no store. `qprev.json` holds the last 8,000 characters of the agent's message, which pass through the secret gate first, with a 512-character margin.
  - The async `stop-sleep` and SessionEnd encode the delta and the last message, then run the light sleep: pending `seq`s, the session gist, and the turn's how-to.
  - They also start the detached idle sleeper (`eden sleep --idle`). One sleeper runs per repo store, and it runs the full sleep once the repo's hooks have been quiet for `EDEN_SLEEP_IDLE` (5 min).
  - A host with one Stop hook gets both stages. The hook never sleeps in-process any more.
- **SubagentStop** is async. It encodes the subagent's last message or the host's tool result, but not the child's own transcript (deferred, see Decisions).
- **Retrieval's postings** (P0.3's follow-up: the load-time index over large narrative rows):
  - They hold only rows `relevant` can score (≤ 12 needles). Long rows are read only up to their 13th needle, and they no longer fill the candidate pool.
  - `observe`'s end-punctuation duplicate check is now a set lookup.
- **Secret scan once per text:** `scrubMemoryText` returns a large text it produced unchanged, closing P0.4's follow-up.
- **Harness** (`fixture:` commits, prereg amended):
  - The runner models `async: true` handlers, and the world waits for them before its next event.
  - Latency is reported per handler (`<event> (async)`), with the p99 of each quarter.
  - Replays hand hooks the simulated clock.
  - Hook processes run with `EDEN_SLEEP_IDLE=off`. After 5 simulated idle minutes, the world runs the plugin checkout's `eden sleep --idle --after 0`; the R6 replay runs it after each session.
  - `rewind` gained `no-abandoned`, and `secrets` ends on a reply quoting secrets.
- **Key files:**
  - `src/memory-delta.ts`: the encoder.
  - `src/memory-batch.ts`: the batch record.
  - `src/memory-window.ts`: `ctx.log` batches and compaction, `qprev.json`.
  - `src/index.ts`: row origin, `abandon`, postings.
  - `src/memory-ledger.ts`: the branch check.
  - `src/sleep.ts`: `lightSleep`.
  - `src/memory-scrub.ts`: the memo.
  - `packages/cli/src/memory-hook.ts`: one handler per event, Stop's stages, fail-open steps.
  - `packages/cli/src/memory-sleep.ts`: `eden sleep`, the idle sleeper.
  - `packages/cli/src/doctor.ts`: PostToolBatch fills the tool slot.
  - `plugins/eden-memory/hooks/hooks.json`, `scripts/hook.ts`.

## Decisions made
- **Flatness's tolerance is 74.7 ms**, A5's Submit p99 A/A floor. A5 forbids a tolerance tighter than its floor, and the floor exceeds the usual +10 ms (prereg).
- **Typed prompts are not encoded by the delta encoder**:
  - Their Submit payload carries them (A4 §3.3).
  - Splitting a pasted span again without that moment's tool results could give it the user's authority (D12).
  - Questions, which `observeCue` does not store, are no longer stored by a later re-read.
- **The idle sleeper waits through activity instead of exiting (D34 says exit).** The pending sleeper is the only one a repo gets, so exiting would leave a repo whose last Stop came during the wait unslept until its next session. D34's row now says what P0.6 built.
- **One sleeper per store sleeps with the session that started it.** Other sessions' gists and how-tos come from their own light sleep.
- **The light sleep is pending `seq`s, the session gist and the turn's how-to.** Without the gist, `negation`'s control (met through "stack uses Redis") fails between turns. Without the how-to, a verified run is no procedure by the next turn. Every pass that rewrites or rescans the store is the idle sleeper's.
- **`qprev.json` holds text, not rare tokens:**
  - The turn mode's proposal check reads text.
  - Own-delivery stripping and rare-token selection are P4.1's (A7 §2–3).
  - The text is the message's last 8,000 characters, through the secret gate.
- **PostToolUse stays** for `eden setup`'s hosts, without a transcript read. A host with no window mark, or one that sends the conversation, re-reads its last 40 messages from 256 KB.
- **The postings change is a retrieval behaviour change** outside the ROADMAP row, taken from P0.3's filing. The guards clear it; R6 does not (above).
- **SubagentStop does not encode the child transcript** (A4 §5.7b deferred, the user's choice). `main` never encoded it either: its SubagentStop re-read the parent transcript.
- **The harness models async handlers as finishing before the next event.** So it never exercises the race between an async `stop-sleep` and a fast next Submit; the encoder's lock and the fail-open steps are what cover it.
