## What changed

**Rounds 1–3** (reviewed three times; unchanged since `be9a31c5a` unless round 4 says otherwise):
- **Non-human submits get nothing (D24).** A prompt that opens with `<task-notification`, `<agent-message`, `<cross-session-message` or `<teammate-message` gets no packet; so does a prompt equal to one of the window's last Stop `session_crons`. The hook returns before it opens any store (A4 §5.1 step 0), so the submit is not encoded at that point, and the human-turn counter does not advance.
  - The tag may follow a peer message's one-line preamble, `Another Claude session sent a message:` (R0 F34; see Decisions).
  - Cron prompts are kept as 16-hex SHA-256 prefixes in `windows/<win>/ctx.log`, appended only when a Stop's crons differ from the last kept, never as text.
- **Ack turns get no packet (A7 §2).** Up to 3 tokens of {ok, thanks, cool, nice, great, got it, sounds good}; or {continue, keep going, next, go on} when the agent's last message proposed nothing (no trailing `?`, no "shall I / want me to / should I / next I'll / I can").
- **Continuation turns get no packet until the situation cue (P4.1).** "yes / do it / go ahead / proceed", the continue words after a proposal, or ≤ 4 content tokens after a proposal.
- **Ack and continuation turns are still encoded and counted** (A4 §5.1: step 1 encodes, step 2's mode only decides the answer).
- **A human-turn counter (A4 §4).** Each human Submit appends `{"k":"turn","prompt_id":…,"off":…}` to `<memory root>/windows/<session>/delivery.log`; `hturn` counts distinct `prompt_id`s. Readonly consent writes none.
- **Bullets are not filled to a fixed count (D28, UserPromptSubmit).** In retrieval order, a bullet is skipped once its kind is full (≤ 2 rules, ≤ 1 procedure, ≤ 2 episodes), at most 4 in all; a repeated bullet is dropped; one that does not fit 900 bytes is skipped, never cut.
- **Declarative wording (D14), claiming only the source a row shows (A6 §2.1).** Every packet opens `Eden memory, recalled from earlier sessions:`; the old `Eden Memory:` header is still recognized. "Rule you set: …" and "(you said, …)" appear only for a row whose `src` is `user`; other bullets end with A6's label and the age when the row shows them (`(from a tool result, …)`, `(earlier session notes, …)`). No `[kind · age · src]` tag reaches Claude from the hook.
- `AgentMemory.recall` is `inject`'s retrieval, split out so the hook shapes and words the notes itself.
- **The gate's instrument:** `arms/r6-replay.ts` replays the sessions R6 measured through a plugin's hooks, from a frozen copy, and prints counts only.

**Round 4** (the user asked to continue until every target and guard is met). Each item is a spec step the legacy hook skipped; the R6 counts showed which ones the targets need (see Verification notes for every look):
- **Validity (A4 §3.1, §5.1 step 5; D7, D31).** A retraction ("we no longer use Redis", "not … anymore", "we dropped X"), a switch ("switched/moved/migrated … from B to A", "replaced B with A", "use A, not B", "A instead of B") or a revocation ("you can merge PRs yourself now") typed at a human Submit is appended to `<root>/validity.jsonl` with its time (typed text only, A4 §3.0). Every delivery point then drops a sentence of an older row or gist that still names the value, or forbids the revoked action; the sentence stating the change stays. An episode keeps such a sentence when the cue asks history ("before", "used to", "previously", "was", "why did we"); facts and rules do not.
- **Text the user did not type keeps its source (D12, A6 §2.1).** The hook marks a transcript tool result and a PostToolUse result `src: "tool"`; `observe` tags rows from it `src:tool` and rows from assistant text `src:assistant`. D14 then words them "(from a tool result, …)". Before, the hook passed tool results to `observe` as if the user had typed them.
- **The episode gate for such rows (A7 §4, D17).** A row tagged `src:tool` or `src:assistant` is an episode (A4 §3.0, D12) and is admitted only on STRONG evidence (an identifier-shaped token it shares with the prompt: a path, a filename, an error code, a flag, a version, an id, a symbol) or MEDIUM evidence from at least two cue parts (a content word shared with the prompt, the previous typed prompt or the agent's last message; a function word is WEAK). Rows the user typed, rows of unknown source and gists keep today's lexical admission.
- **D26's residual filter.** A bullet the conversation already states is dropped: the current prompt, the last 2 typed prompts and the assistant text between them, read from the transcript's last 256 KB, never tool results, and nothing before a compaction. An episode or rule is residual at content-token Jaccard ≥ 0.6 with one sentence; a slot (a fact the legacy copula reader parses whose value is one or two tokens and not a D7 status word) when its value and a subject word share a sentence.
- **The ledger's refractory rule (A4 §4, D25).** Every delivered bullet is a `deliver` record in the window's `delivery.log` (`cid`, `ver`, `off`, `att`, `ht`), SessionStart's included. A bullet with the same `cid` and `ver` delivered in this epoch, less than 400 KB (rules) or 1.2 MB (everything else) of transcript ago, is not delivered again, unless it was delivered on a branch a rewind abandoned (its prompt line is in the transcript but not on the current `parentUuid` chain). A slot is keyed by its subject (its value is the `ver`); rules and episodes by a hash of their content words, so near-identical text shares a `cid`. A compaction starts a new epoch, which re-arms everything; `resume` keeps the ledger.
- **SessionStart (A4 §5.2).** `resume` brings nothing new. After `compact`, no pins: they are re-armed and come back on their cue. The legacy gists, the only memory one session passes to the next until P0.5, stay at startup, `clear` and `compact`: the 3 latest that are still valid (validity before selection, A4 §5.1), within 900 B.

## Decisions made

Rounds 1–3 (reviewed):
- **D24, the peer preamble.** R0 F34: an idle peer message's transcript line opens `Another Claude session sent a message:` and then `<agent-message …>`; its UserPromptSubmit `prompt` was never captured. The detector accepts that one preamble line before the tag. A human typing that exact preamble followed by the tag is not a realistic false positive. Follow-up: P0.8's wide events show the live shape.
- **D24, encoding.** A non-human submit returns before any store opens (A4 §5.1 step 0). Its text reaches the store later, through the transcript, at the next human Submit or Stop. Before, `inject` stored the notification itself as a user message, which D12 forbids.
- **Ack and continuation are encoded** (A4 §5.1 step 1 before step 2); a test covers a reply to the agent's question.
- **Continuation is silent.** A4 §0 G3 allows a continuation to inject only on STRONG `q_prev` evidence, which nothing can tell before P4.1. On the R6 corpus it applies to 4 of 137 human prompts. The cost: "ok merge it" after "Shall I merge?" gets no packet (P2.2, P4.1).
- **A7's proposal markers as written**, plus: "I can't" and "I cannot" are not offers. A7's ack limit counts tokens.
- **D28, "stop at the first empty stage"**, read as "never fill": no stage pulls items in to replace one a cap or the byte limit skipped. Soft limit 4 holds for every Submit bullet; the hard limit 6 is for `Updated:` items (P1.1).
- **D14 and A6 §2.1, provenance.** The source label comes from the row's `src`; a row without one claims nothing. A rule-kind row without `src` is a plain bullet. Gists and procedures show their source through their kind.
- **D14, the header everywhere**, the old mark still recognized; the scope parenthetical waits for P3.1.
- **`re-eligibility`'s `refractory-399` is recorded `unstable`**, a flake that predates P0.2 (3 of 25 isolated runs on 172b490d3, 9 of 53 on rounds 1–3's code). Its cause is not found.
- **The turn counter writes now**, so every flagged arm's `off` state also fails `no-ledger` and its `shadow` state `no-live-ledger` (34 each); round 4's `deliver` records go to the same file and changed no record.

Round 4:
- **Which spec steps, and why these.** P0.2's ROADMAP levers (silence, ack, variable k, wording) cannot move the human packet rate further on `main`: chatter was already silent and the replay's base packets average 2.7 bullets, not R6's fixed 6. The remaining waste, by counts on round 3's packets, was rows of the session's own store: 17 of 99 bullets repeated an earlier delivery, 32 restated the last prompts, and on the next design about 45 of 76 came from text the user had not typed, an approximate count (Verification notes). The spec controls for exactly these are A4 §5.1's steps 5–7 (validity, the gate, novelty: D26 and the ledger) and D12's sources. Each is built only as far as the legacy store allows, and the slices that own the rest are named below.
- **Validity's lexicon is A4 §3.1's and D7's, on legacy text.** Without keyed slots (P2/P3) or persisted `invalid_at` (P0.3), an invalidation is a value token plus a time, and a sentence is dropped when it names that token and is older. So "We no longer use zebra." drops every older sentence naming "zebra", in any scope: wider than a slot's supersession, never narrower. The log keeps the value token and the time, not the prompt. Gists carry the time they were written, which can be later than the statement they summarize; such a gist is not dropped.
- **The history exception** keeps episodes only (D31's `stale_for` is on episodes); a superseded fact or a revoked rule is dropped whatever the cue says (A4 §5.1 step 5's "superseded / invalid → drop").
- **Sources (D12) without P0.4.** Only the hook's own inputs are marked: transcript tool results and PostToolUse results (`src:tool`), assistant text (`src:assistant`, which `observe` already received with its role). Tool output stays stored, now as an episode with its true source, as A4 §3.0 says; P0.4 adds D12's kind rule (episodes only), the wrappers and paste stripping. Rows written before this change have no `src` and keep today's admission.
- **The episode gate (A7 §4) without τ.** A7 also asks an episode for BM25F ≥ τ_repo, which needs P4.2 and P4.3; until then the cue-part rule stands alone. The cue parts are those available before P4.1: the prompt, the previous typed prompt (`q_turn`) and the agent's last message (`q_prev`); `q_path` waits for `ctx.log` (P0.6). WEAK words are a fixed function-word list until the repo's df exists (P4.3). The gate applies only to rows whose source is known to be untyped: iteration 1 (below) applied it to every unkeyed row and lost recall the arms require.
- **D26's slot rule on legacy facts.** A "slot" is a fact the copula reader parses whose value is one or two tokens and not a D7 status word ("auth is failing" is not a slot); its subject's words stand for P3.3's aliases. Every other row uses the Jaccard rule. The procedure-command exception waits for procedures with commands (P4.6).
- **The ledger's keys (A4 §4).** Without P2.1's and P3.3's keys, a slot's `cid` is its subject and its `ver` its value; rules and episodes are keyed by a hash of their sorted content words. Two rows saying one thing in different words get different `cid`s; the end-to-end session shows one such case (Evidence).
- **The ledger's rewind check** reads the transcript's last 1.5 MB at Submit, past the 1.2 MB distance, and only when a candidate matches a live delivery. A delivery whose prompt line is in that tail but off the current `parentUuid` chain is abandoned; a prompt line not written yet counts as on the branch (A4 §4). P0.6's delta encoder will hold the branch state instead.
- **Epochs.** `compact` re-arms everything. D25 re-arms only the `cid`s whose value tokens `compact_summary` dropped, which needs PostCompact (P1.2); so `compaction`'s `a-not-rearmed` stays red, as recorded. `/clear` opens a new session and so a new window with an empty ledger (the simulator models it so; R0).
- **SessionStart after `compact` brings no pins** (A4 §5.2: re-arm, then deliver on cue). The legacy gists stay at every SessionStart but `resume`: they are the only memory one session passes to the next until P0.5, and the `negation` arm's control is met only by the gist briefed after a compaction (round 4's V7 dropped them there and broke it). D23's pins-only briefing waits for P0.5 and P2.5: iteration 1 (below) tried it and need_miss went to 100% on the one run measured.
- **SessionStart takes the 3 latest *valid* gists** (validity, step 5, before selection, step 8), looking through at most 12, and is not shaped by D28's ≤ 2-episode cap: on development seeds 4–6 the cap dropped the gist that carried later cues' items, and need_miss rose (seed 5: 2/6 → 4/6).
- **Iterations not kept, all measured and disclosed** (Verification notes): iteration 1 (`6988a6df5`: the A7 §4 gate on every unkeyed row, D23's pins-only SessionStart), iteration 2 (`77ffc8a3b`: the same gate, ≤ 8 pins and the 3 latest gists kept with the legacy identity check applied to them, resume brings nothing), and dev candidates V2–V9.
