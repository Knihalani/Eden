## What changed

**Rounds 1–3** (reviewed three times; unchanged since `be9a31c5a` unless round 4 says otherwise):
- **Non-human submits get nothing (D24).** A prompt that opens with `<task-notification`, `<agent-message`, `<cross-session-message` or `<teammate-message` gets no packet; so does a prompt equal to one of the window's last Stop `session_crons`. The hook returns before it opens any store (A4 §5.1 step 0), so the submit is not encoded at that point, and the human-turn counter does not advance.
  - The tag may follow a peer message's one-line preamble, `Another Claude session sent a message:` (R0 F34; see Decisions).
  - Cron prompts are kept as 16-hex SHA-256 prefixes in `windows/<win>/ctx.log`, appended only when a Stop's crons differ from the last kept, never as text.
- **Ack turns get no packet (A7 §2).** Up to 3 tokens of {ok, thanks, cool, nice, great, got it, sounds good}; or {continue, keep going, next, go on} when the agent's last message proposed nothing (no trailing `?`, no "shall I / want me to / should I / next I'll / I can").
- **Continuation turns get no packet until the situation cue (P4.1).** "yes / do it / go ahead / proceed", the continue words after a proposal, or ≤ 4 content tokens after a proposal.
- **Ack and continuation turns are still encoded and counted** (A4 §5.1: step 1 encodes, step 2's mode only decides the answer).
- **A human-turn counter (A4 §4).** Each human Submit appends `{"k":"turn","prompt_id":…,"off":…}` to `<memory root>/windows/<session>/delivery.log`; `hturn` counts distinct `prompt_id`s. Readonly consent writes none.
- **Bullets are not filled to a fixed count (D28, UserPromptSubmit).** In retrieval order, a bullet is skipped once its kind is full (≤ 2 rules, ≤ 1 procedure, ≤ 2 episodes), at most 4 in all; a repeated bullet is dropped; one that does not fit 900 bytes is skipped, never cut.
- **Declarative wording (D14), claiming only the source a row shows (A6 §2.1).** Every packet opens `Eden memory, recalled from earlier sessions:`; the old `Eden Memory:` header is still recognized. "Rule you set: …" and "(you said, …)" appear only for a row whose `src` is `user`; other bullets end with A6's label and the age when the row shows them (`(from a tool result, …)`, `(earlier session notes, …)`). No `[kind · age · src]` tag reaches Claude from the hook.
- `AgentMemory.recall` is `inject`'s retrieval, split out so the hook shapes and words the notes itself.
- **The gate's instrument:** `arms/r6-replay.ts` replays the sessions R6 measured through a plugin's hooks, from a frozen copy, and prints counts only.

**Round 4** (the user asked to continue until every target and guard is met). Each item is a spec step the legacy hook skipped; the R6 counts showed which ones the targets need (see Verification notes for every look):
- **Validity (A4 §3.1, §5.1 step 5; D7, D9, D31), read narrowly.** Only D7's and A4 §3.1's own forms, in typed text without A6 §2.1's pasted spans, questions or conditionals, invalidate:
  - a retraction or a switch with a "we" subject ("we no longer use Redis", "we're not using Jest anymore", "we dropped Sentry", "we switched/moved/migrated … from B to A"), or "use A, not B" (or instead of, rather than) at the start of a sentence or after "we"; the value must be capitalized or identifier-shaped and not a path (D7's rule outside a slot's value class), so "array", "src" or a lowercase "npm" never is one;
  - a revocation "you can <verb> … now" whose verb is an A7 §5 action-class verb (merge, push, deploy, delete, install, …); it revokes only a rule forbidding an action of that class that names the same object, or none when it names none (D9).
  Each is appended to `<root>/validity.jsonl` with its time. Every delivery point drops a sentence of an older row or gist that still names the value as a whole token (never inside a path or filename), or forbids the revoked action; the sentence stating the change stays. An episode keeps such a sentence when the cue asks history ("before", "used to", "previously", "was", "why did we"); facts and rules do not.
- **Text the user did not type keeps its source (D12, A6 §2.1).** The hook marks a transcript tool result and a PostToolUse result `src: "tool"`; `observe` tags rows from it `src:tool` and rows from assistant text `src:agent` (A6 §2.1's name). D14 then words them "(from a tool result, …)". Before, the hook passed tool results to `observe` as if the user had typed them.
- **The episode gate for such rows (A7 §4, D17).** A row tagged `src:tool` or `src:agent` is an episode (A4 §3.0, D12) and is admitted only on STRONG evidence (an identifier-shaped token it shares with the prompt: a path, a filename, an error code, a flag, a version, an id, a symbol) or MEDIUM evidence from at least two cue parts (a content word shared with the prompt, the previous typed prompt or the agent's last message; a function word is WEAK). Rows the user typed, rows of unknown source and gists keep today's lexical admission.
- **D26's residual filter.** A bullet the conversation already states is dropped: the current prompt, the last 2 typed prompts and the assistant text between them, read once per Submit from the transcript's last 256 KB (the same read gives the gate its previous typed prompt), never tool results, and nothing before a compaction; the current prompt's own line, when already written, is not one of the two. An episode or rule is residual at content-token Jaccard ≥ 0.6 with one sentence; a slot (a fact the legacy copula reader parses whose value is one or two tokens and not a D7 status word) when its value and a subject word share a sentence.
- **The ledger's refractory rule (A4 §4, D25).** Every delivered bullet is a `deliver` record in the window's `delivery.log` (`cid`, `ver`, `off`, `att`, `ht`), SessionStart's included. A bullet with the same `cid` and `ver` delivered in this epoch, less than 400 KB (rules) or 1.2 MB (everything else) of transcript ago, is not delivered again, unless it was delivered on a branch a rewind abandoned (its prompt line is in the transcript but not on the current `parentUuid` chain). A slot is keyed `s:` by its subject (its value is the `ver`); rules and episodes by a hash of their content words, so near-identical text shares a `cid`. A compaction starts a new epoch, which re-arms everything; `resume` keeps the ledger.
- **SessionStart (A4 §5.2).** `resume` brings nothing new. After `compact`, no pins: they are re-armed and come back on their cue. The legacy gists, the only memory one session passes to the next until P0.5, stay at startup, `clear` and `compact`: the 3 latest that are still valid (validity before selection, A4 §5.1), within 900 B.

- **`false_rate`, read plainly.** The point estimate is +0.65 pp, above the +0.5 pp tolerance. A5 §2 counts a regression of a sampled metric "only if a paired test rejects at 95%", and for a tolerance under its A/A noise floor (`false_rate`'s is 1.85 pp) it asks for "the paired per-cue test … over several fresh runs per side". That test does not reject (p = 0.125), as in rounds 1–3 (2 vs 2, p = 1.0). Both sides are near 100%: nearly every bullet on an annotated cue states none of that cue's needed or allowed items. The base's 4 non-false bullets are one auth bullet each in 6-bullet packets on generated prompts naming `apps/web/…/auth.ts`, whose `allowed` item is the auth provider; none is a storyline need cue. The final code's packets on those prompts hold at most 4 bullets, and none states it. If the reader holds the tolerance as a point threshold instead, this guard misses by 0.15 pp.

Round 4:
- **Which spec steps, and why these.** P0.2's ROADMAP levers (silence, ack, variable k, wording) cannot move the human packet rate further on `main`: chatter was already silent and the replay's base packets average 2.7 bullets, not R6's fixed 6. The remaining waste, by counts on round 3's packets, was rows of the session's own store: 17 of 99 bullets repeated an earlier delivery, 32 restated the last prompts, and on the next design about 45 of 76 came from text the user had not typed, an approximate count (Verification notes). The spec controls for exactly these are A4 §5.1's steps 5–7 (validity, the gate, novelty: D26 and the ledger) and D12's sources. Each is built only as far as the legacy store allows, and the slices that own the rest are named below.
- **Validity reads only D7's and A4 §3.1's forms, narrowly** (review cycle 2, round 1, found the first version a blocker). A false invalidation silently drops a memory the user still needs, which the guards cannot see: their prompts never contain these phrasings beyond the storyline's three, and R6 has no recall measure. So:
  - a retraction or a switch needs a "we" subject, or "use A, not B" at the start of a sentence or after "we" (D7); questions, conditionals and A6 §2.1's pasted spans never count;
  - the value must be capitalized or identifier-shaped and not a path: D7 accepts a value outside a slot's value class only in that shape, and P3.3 brings the classes. Lowercase tool names ("we switched from npm to pnpm") therefore invalidate nothing yet, and `stale-episode` ("packages/cli switched its database from postgres to sqlite") stays red;
  - a revocation needs an A7 §5 action-class verb and revokes only a rule of that class naming the same object, or naming none when it names none: D9 keys a rule by `(class, polarity, object)`. A rule's object is approximated by its sentence's content words ("PRs" and "PR" match).
  On the public fixtures: E3, 330 labelled items: 1 retraction, correct, and 17 labelled ones missed; CueBench, 677 prompts and previous turns: none fires. Without keyed slots or persisted `invalid_at`, an invalidation is still a value token plus a time, and a sentence is dropped when it names that token and is older, in any scope. Gists carry the time they were written, which can be later than the statement they summarize; such a gist is not dropped (`negation`'s `no-redis` stays red for this reason).
- **The history exception** keeps episodes only (D31's `stale_for` is on episodes); a superseded fact or a revoked rule is dropped whatever the cue says (A4 §5.1 step 5's "superseded / invalid → drop").
- **Sources (D12) without P0.4.** Only the hook's own inputs are marked: transcript tool results and PostToolUse results (`src:tool`), assistant text (`src:agent`, A6 §2.1's name; `observe` already received it with its role). Tool output stays stored, now as an episode with its true source, as A4 §3.0 says; P0.4 adds D12's kind rule (episodes only), the wrappers and paste stripping. Rows written before this change have no `src` and keep today's admission.
- **The episode gate (A7 §4) without τ.** A7 also asks an episode for BM25F ≥ τ_repo, which needs P4.2 and P4.3; until then the cue-part rule stands alone. The cue parts are those available before P4.1: the prompt, the previous typed prompt (`q_turn`) and the agent's last message (`q_prev`); `q_path` waits for `ctx.log` (P0.6). WEAK words are a fixed function-word list until the repo's df exists (P4.3). The gate applies only to rows whose source is known to be untyped: iteration 1 (below) applied it to every unkeyed row and lost recall the arms require.
- **D26's slot rule on legacy facts.** A "slot" is a fact the copula reader parses whose value is one or two tokens and not a D7 status word ("auth is failing" is not a slot); its subject's words stand for P3.3's aliases. Every other row uses the Jaccard rule. The procedure-command exception waits for procedures with commands (P4.6).
- **The ledger's keys (A4 §4).** Without P2.1's and P3.3's keys, a slot's `cid` is `s:` plus its subject and its `ver` its value; rules and episodes are keyed by a hash of their sorted content words. Two rows saying one thing in different words get different `cid`s; the end-to-end session shows one such case (Evidence).
- **The ledger's rewind check** reads the transcript's last 1.5 MB at Submit, past the 1.2 MB distance, and only when a candidate matches a live delivery. A delivery whose prompt line is in that tail but off the current `parentUuid` chain is abandoned; a prompt line not written yet counts as on the branch (A4 §4). P0.6's delta encoder will hold the branch state instead.
