# P0.2 — Stop the bleeding: non-human + ack silence, variable k, declarative wording

**Outcome:** Blocked, not merged: the code is complete, reviewed (3 rounds) and green in CI, but ROADMAP's two R6 targets are missed and the `stale_rate` guard fails, so A5's ship rule leaves the merge to the user. What works on the branch: no packet on task notifications, peer messages or session crons (0 of 246 in the R6 replay, was 221), no packet on ack or continuation turns, a human-turn counter, packets of at most 4 bullets within 900 bytes, and wording that claims no source a row cannot show.
**PR:** https://github.com/Knihalani/Eden/pull/119 (open, not merged) · **Merge commit:** none · **Date:** 2026-10-06

## What changed

- **Non-human submits get nothing (D24).** A prompt that opens with `<task-notification`, `<agent-message`, `<cross-session-message` or `<teammate-message` gets no packet; so does a prompt equal to one of the window's last Stop `session_crons`. The hook returns before it opens any store (A4 §5.1 step 0), so the submit is not encoded at that point, and the human-turn counter does not advance.
  - The tag may follow a peer message's one-line preamble, `Another Claude session sent a message:` (R0 F34; see Decisions).
  - Cron prompts are kept as 16-hex SHA-256 prefixes in `windows/<win>/ctx.log`, appended only when a Stop's crons differ from the last kept, never as text.
- **Ack turns get no packet (A7 §2).** Up to 3 tokens of {ok, thanks, cool, nice, great, got it, sounds good}; or {continue, keep going, next, go on} when the agent's last message proposed nothing (no trailing `?`, no "shall I / want me to / should I / next I'll / I can").
- **Continuation turns get no packet until the situation cue (P4.1).** "yes / do it / go ahead / proceed", the continue words after a proposal, or ≤ 4 content tokens after a proposal. A4 §0 lets a continuation inject only on STRONG evidence from the previous assistant message, which nothing can tell before P4.1.
- **Ack and continuation turns are still encoded and counted** (A4 §5.1: step 1 encodes, step 2's mode only decides the answer). `AgentMemory.observeCue` is what `recall` stores after retrieving, and the hook calls it for those turns.
- **A human-turn counter (A4 §4).** Each human Submit appends `{"k":"turn","prompt_id":…,"off":…}` to `<memory root>/windows/<session>/delivery.log` (A4 §1's layout); `hturn` counts distinct `prompt_id`s. Without a `prompt_id`, the prompt's hash and the offset key the record. Readonly consent writes none.
- **Bullets are not filled to a fixed count (D28, UserPromptSubmit).** In retrieval order, a bullet is skipped once its kind is full (≤ 2 rules, ≤ 1 procedure, ≤ 2 episodes, gists counted as episodes), at most 4 in all; a bullet that says what an earlier one said is dropped; one that does not fit 900 bytes is skipped, never cut. Nothing replaces a skipped bullet. SessionStart keeps its legacy selection (≤ 8 pins, 3 gists), now within 900 bytes.
- **Declarative wording (D14), claiming only the source a row shows (A6 §2.1).**
  - Every packet opens `Eden memory, recalled from earlier sessions:` (the wrap's too). Packets with the old `Eden Memory:` header are still recognized: no second packet goes into such a history, and `stripMemoryPacket` removes either header with its bullet lines.
  - A rule reads `Rule you set: …` only when the row's `src` is `user`. A row without one makes no authority claim (A6 §2.1), and A6 lets such a row create no policy, so a rule-kind row without `src` is a plain bullet.
  - Other bullets end with A6's source label and the age when the row shows them: `(you said, 3 weeks ago)`, `(from a tool result, …)`, `(earlier session notes, …)`. A row without a `src` shows only its age, `(2 hours ago)`, or nothing.
  - No writer records `src` before P0.4, so today no hook bullet says "you said" or "Rule you set". Gists (`earlier session notes`) and procedures (`from a tool result`) show their source through their kind.
  - No `[kind · age · src]` tag reaches Claude from the hook. SessionStart uses the same renderer.
- `AgentMemory.recall` is `inject`'s retrieval, split out so the hook can shape and word the notes itself. `inject` keeps its packing and labels (the wrap's surface, P0.7). `recall` fails open and counts the swallow, as `inject` did.
- **The gate's instrument:** `arms/r6-replay.ts` replays the sessions R6 measured through a plugin's hooks, from a frozen copy, and prints counts only.

## Decisions made

- **D24, the peer preamble.** R0 F34: an idle peer message's transcript line opens `Another Claude session sent a message:` and then `<agent-message …>`; its UserPromptSubmit `prompt` was never captured. The detector accepts that one preamble line before the tag. If the live prompt is the bare tag, nothing changes; if it carries the preamble, D24's literal test would miss it. A human typing that exact preamble followed by the tag is not a realistic false positive. Follow-up: P0.8's wide events show the live shape; then settle D24's wording.
- **D24, encoding.** A non-human submit returns before any store opens (A4 §5.1 step 0, before step 1's encode). Its text reaches the store later, through the transcript, at the next human Submit or Stop, which read the last 40 transcript messages today. Before, `inject` stored the notification itself as a user message, which D12 forbids. This changes the store; a scratch variant that encodes them anyway did not lower the stale rate (Guards).
- **Ack and continuation are encoded.** They return no packet but are stored as `recall` would store them (A4 §5.1 step 1 before step 2). Review round 1 found the first version skipped this, losing replies to the agent's questions ("zebrapkg uses pnpm"); a test now covers it.
- **Continuation is silent.** ROADMAP lists only ack/chatter for P0.2, but A4 §0 G3 allows a continuation to inject only on STRONG `q_prev` evidence, and nothing can tell STRONG evidence before P4.1. Silence is the reading that keeps G3. On the R6 corpus it applies to 4 of 137 human prompts. The cost is real: "ok merge it" after "Shall I merge?" gets no packet, where A7 would deliver a policy through a trigger hit on the proposal (P2.2, P4.1).
- **A7's proposal markers as written**, plus one refinement: "I can't" and "I cannot" are not offers. "I can see …" in a report still counts as a proposal (A7's v1 rule); P4.1 tunes it. A7's ack limit counts tokens ("sounds good, got it, thanks" is 5).
- **D28, "stop at the first empty stage".** Read as "never fill": no stage pulls items in to replace one a cap or the byte limit skipped. The per-kind caps are A4 §5.1 step 8's. Soft limit 4 holds for every Submit bullet; the hard limit 6 is for `Updated:` items, which do not exist yet (P1.1). Merging same-subject slot facts needs P3.3's slots; identical bullets are merged now. The old packer kept an oversized first copula whole past 900 B; D28's 900 B is a hard limit, so such a bullet is skipped.
- **D14 and A6 §2.1, provenance.** The source label comes from the row's `src` (A6 §2.1); a row without one renders with no authority claim. Review round 1 found the first version had followed the legacy default (`user`) and written "you said" and "Rule you set" for every row, including tool results and the `poison` arm's planted line. Now a row without `src` shows only its age; round 2 made a rule-kind row without `src` a plain bullet too (round 1 had written `Rule on record:`), since A6's table lets no such row be a policy. Gists and procedures show their source through their kind, as `noteSource` already did. Ages appear only for rows with a wall-clock time; episodes persist none until P0.3.
- **D14, the header everywhere.** The header is the one packet mark (`MEMORY_MARK`), so every packet-recognizing check (echo protection, the wrap, tests) follows it; the old `Eden Memory:` mark is still recognized.
