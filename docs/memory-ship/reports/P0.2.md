## What changed

**Rounds 1–3** (reviewed three times; unchanged since `be9a31c5a` unless round 4 says otherwise):
- **Non-human submits get nothing (D24).** A prompt that opens with `<task-notification`, `<agent-message`, `<cross-session-message` or `<teammate-message` gets no packet; so does a prompt equal to one of the window's last Stop `session_crons`. The hook returns before it opens any store (A4 §5.1 step 0), so the submit is not encoded at that point, and the human-turn counter does not advance.
  - The tag may follow a peer message's one-line preamble, `Another Claude session sent a message:` (R0 F34; see Decisions).
  - Cron prompts are kept as 16-hex SHA-256 prefixes in `windows/<win>/ctx.log`, appended only when a Stop's crons differ from the last kept, never as text.
- **Ack turns get no packet (A7 §2).** Up to 3 tokens of {ok, thanks, cool, nice, great, got it, sounds good}; or {continue, keep going, next, go on} when the agent's last message proposed nothing (no trailing `?`, no "shall I / want me to / should I / next I'll / I can").
- **Continuation turns get no packet until the situation cue (P4.1).** "yes / do it / go ahead / proceed", the continue words after a proposal, or ≤ 4 content tokens after a proposal.
- **Ack and continuation turns are still encoded and counted** (A4 §5.1: step 1 encodes, step 2's mode only decides the answer).
- **A human-turn counter (A4 §4).** Each human Submit appends `{"k":"turn","prompt_id":…,"off":…}` to `<memory root>/windows/<session>/delivery.log`; `hturn` counts distinct `prompt_id`s. Readonly consent writes none.
- **Bullets are not filled to a fixed count (D28, UserPromptSubmit).** In retrieval order, a bullet is skipped once its kind is full (≤ 2 rules, ≤ 1 procedure, ≤ 2 episodes), at most 4 in all; a repeated bullet is dropped; one that does not fit 900 bytes is skipped, never cut.
- **Declarative wording (D14), claiming only the source a row shows (A6 §2.1).** Every packet opens `Eden memory, recalled from earlier sessions:`; the old `Eden Memory:` header is still recognized. "Rule you set: …" and "(you said, …)" appear only for a row whose `src` is `user`; other bullets end with A6's label and the age when the row shows them (`(from a tool result, …)`, `(earlier session notes, …)`). No `[kind · age · src]` tag reaches Claude from the hook.
- `AgentMemory.recall` is `inject`'s retrieval, split out so the hook shapes and words the notes itself.
- **The gate's instrument:** `arms/r6-replay.ts` replays the sessions R6 measured through a plugin's hooks, from a frozen copy, and prints counts only.

**Round 4** (the user asked to continue until every target and guard is met). Each item is a spec step the legacy hook skipped; the R6 counts showed which ones the targets need (see Verification notes for every look):
- **Validity (A4 §3.1, §5.1 step 5; D7, D9, D31), read narrowly.** Only D7's and A4 §3.1's own forms invalidate, read from the typed prompt after the store's secret redaction and without A6 §2.1's pasted spans, questions or conditionals:
  - a retraction or a switch with a "we" subject ("we no longer use Redis", "we're not using Jest anymore", "we dropped Sentry", "we switched/moved/migrated … from B to A"), whose value is one token that ends its clause and is capitalized or identifier-shaped, never a path. So "array", "src", a lowercase "npm", or "Node" of "we no longer use Node 16" never is one. D7's "use A, not B" waits for P3.3: without a slot it cannot be told from a coding instruction ("Use POST instead of GET");
  - a revocation "you can <verb> … now" whose verb is an A7 §5 action-class verb (merge, push, deploy, delete, install, …). It revokes a rule of that class only when the rule's own object (the words after its negated verb, to the end of its clause) is within the revocation's, and the revocation's object is named in the rule (D9's `(class, polarity, object)`). "You can merge PRs yourself now" revokes "don't merge it yourself"; "you can delete the branch now" does not revoke "never delete the main branch".
  A switch also keeps what it names before "from": a scope path ("apps/web") and subject words ("the queue"); a sentence naming another scope, or lacking the subject, keeps the value. A retraction never supersedes a rule sentence (one with never, always, don't, must, avoid), read sentence by sentence even inside a pinned row; only a revocation does (A4 §3.1). Each invalidation is appended to `<root>/validity.jsonl` with its time. The sleep, which rewrites a session's gist at every Stop (later than what it states), checks each fact and rule sentence of the gist against the log at its source's time before composing it (A4 §3.3). Every delivery point drops a sentence of an older row or gist that still names the value as a whole token (never inside a path or filename), or forbids the revoked action; the sentence stating the change stays. The whole sentence goes, a still-valid clause in it included. An episode keeps such a sentence when the cue asks history ("before", "used to", "previously", "was", "why did we"); facts and rules do not.
- **Text the user did not type keeps its source (D12, A6 §2.1).** The hook marks a transcript tool result and a PostToolUse result `src: "tool"`; `observe` tags rows from it `src:tool` and rows from assistant text `src:agent` (A6 §2.1's name). D14 then words them "(from a tool result, …)". Before, the hook passed tool results to `observe` as if the user had typed them.
- **The episode gate for such rows (A7 §4, D17).** A row tagged `src:tool` or `src:agent` is an episode (A4 §3.0, D12) and is admitted only on STRONG evidence (an identifier-shaped token it shares with the prompt: a path, a filename, an error code, a flag, a version, an id, a symbol) or MEDIUM evidence from at least two cue parts (a content word shared with the prompt, the previous typed prompt or the agent's last message; a function word is WEAK). Rows the user typed, rows of unknown source and gists keep today's lexical admission.
- **D26's residual filter.** A bullet the conversation already states is dropped: the current prompt, the last 2 typed prompts and the assistant text between them, read once per Submit from the transcript's last 256 KB (the same read gives the gate its previous typed prompt), never tool results, and nothing before a compaction; the current prompt's own line, when already written, is not one of the two. An episode or rule is residual at content-token Jaccard ≥ 0.6 with one sentence, or, when it has several sentences (the legacy store keeps a whole prompt as one row), when each of them is; a slot (a fact the legacy copula reader parses whose value is one or two tokens and not a D7 status word) when its value and a subject word share a sentence.
- **The ledger's refractory rule (A4 §4, D25).** Every delivered bullet is a `deliver` record in the window's `delivery.log` (`cid`, `ver`, `off`, `att`, `ht`), SessionStart's included. A bullet with the same `cid` and `ver` delivered in this epoch, less than 400 KB (rules) or 1.2 MB (everything else) of transcript ago, is not delivered again, unless it was delivered on a branch a rewind abandoned (its prompt line is in the transcript but not on the current `parentUuid` chain). A slot is keyed `s:` by its subject (its value is the `ver`); rules and episodes by a hash of their content words, so near-identical text shares a `cid`. A compaction starts a new epoch, which re-arms everything; `resume` keeps the ledger.
- **SessionStart (A4 §5.2).** `resume` brings nothing new. After `compact`, no pins: they are re-armed and come back on their cue. The legacy gists, the only memory one session passes to the next until P0.5, stay at startup, `clear` and `compact`: the 3 latest that are still valid (validity before selection, A4 §5.1), within 900 B.

## Decisions made

Rounds 1–3 (reviewed):
- **D24, the peer preamble.** R0 F34: an idle peer message's transcript line opens `Another Claude session sent a message:` and then `<agent-message …>`; its UserPromptSubmit `prompt` was never captured. The detector accepts that one preamble line before the tag. A human typing that exact preamble followed by the tag is not a realistic false positive. Follow-up: P0.8's wide events show the live shape.
- **D24, encoding.** A non-human submit returns before any store opens (A4 §5.1 step 0). Its text reaches the store later, through the transcript, at the next human Submit or Stop. Before, `inject` stored the notification itself as a user message, which D12 forbids.
- **Ack and continuation are encoded** (A4 §5.1 step 1 before step 2); a test covers a reply to the agent's question.
- **Continuation is silent.** A4 §0 G3 allows a continuation to inject only on STRONG `q_prev` evidence, which nothing can tell before P4.1. On the R6 corpus it applies to 4 of 137 human prompts. The cost: "ok merge it" after "Shall I merge?" gets no packet (P2.2, P4.1).
- **A7's proposal markers as written**, plus: "I can't" and "I cannot" are not offers. A7's ack limit counts tokens.
- **D28, "stop at the first empty stage"**, read as "never fill": no stage pulls items in to replace one a cap or the byte limit skipped. Soft limit 4 holds for every Submit bullet; the hard limit 6 is for `Updated:` items (P1.1).
- **D14 and A6 §2.1, provenance.** The source label comes from the row's `src`; a row without one claims nothing. A rule-kind row without `src` is a plain bullet. Gists and procedures show their source through their kind.
- **D14, the header everywhere**, the old mark still recognized; the scope parenthetical waits for P3.1.
- **`re-eligibility`'s `refractory-399` is recorded `unstable`**, a flake that predates P0.2 (3 of 25 isolated runs on 172b490d3, 9 of 53 on rounds 1–3's code). Its cause is not found.
- **The turn counter writes now**, so every flagged arm's `off` state also fails `no-ledger` and its `shadow` state `no-live-ledger` (34 each); round 4's `deliver` records go to the same file and changed no record.
- **The R6 replay protocol**: SessionStart, Stop and UserPromptSubmit only; human prompts as R6 §1.2 defines them; one shared Eden home in session order; a frozen copy.
- **`budget` (P1.1's arm) green at CI scale** (rounds 1–3: 3,974–4,043 tokens per epoch over 100 turns; 8,595 in the base record); red at A5's 300 turns.
- **#57:** "EDEN_MEMORY_CAP=40 clamps to 10" passes now, so its `test.failing` marker is removed.

Round 4:
- **Which spec steps, and why these.** P0.2's ROADMAP levers (silence, ack, variable k, wording) cannot move the human packet rate further on `main`: chatter was already silent and the replay's base packets average 2.7 bullets, not R6's fixed 6. The remaining waste, by counts on round 3's packets, was rows of the session's own store: 17 of 99 bullets repeated an earlier delivery, 32 restated the last prompts, and on the next design about 45 of 76 came from text the user had not typed, an approximate count (Verification notes). The spec controls for exactly these are A4 §5.1's steps 5–7 (validity, the gate, novelty: D26 and the ledger) and D12's sources. Each is built only as far as the legacy store allows, and the slices that own the rest are named below.
- **Validity reads only D7's and A4 §3.1's forms, narrowly** (review cycle 2 found the first version a blocker in round 1, and the second still dropping unrevoked rules in round 2). A false invalidation silently and permanently drops a memory the user still needs, store-wide, and the guards cannot see it: their prompts contain no such phrasing beyond the storyline's three, and R6 has no recall measure. So:
  - a retraction or a switch needs a "we" subject (D7), and its value must end its clause, so "We no longer run CI on Fridays", "… the AWS SDK v2" and "… Node 16" retract nothing; questions, conditionals and A6 §2.1's pasted spans never count;
  - the value must be capitalized or identifier-shaped and not a path: D7 accepts a value outside a slot's value class only in that shape, and P3.3 brings the classes. Lowercase tool names ("we switched from npm to pnpm") therefore invalidate nothing yet, and `stale-episode` ("packages/cli switched its database from postgres to sqlite") stays red;
  - D7's "use A, not B" is not read at all until P3.3 can tie it to a slot: "Use POST instead of GET for this endpoint" is an instruction about code, not a switch;
  - a switch keeps the scope path and subject words it names before "from" (D7 ties a switch to a slot's subject): "We switched packages/cli from Postgres to SQLite" spares "apps/web uses Postgres", and "we moved the docs from Notion to GitHub" spares "design specs live in Notion"; a sentence naming no scope is still read as in scope;
  - a retraction supersedes slot facts and makes episodes `stale_for` (A4 §3.1), never a rule. That is read sentence by sentence: a rule sentence (never, always, don't, must, avoid) is spared even when retracted values appear in it, while a fact sentence is superseded even inside a legacy pinned row (the legacy store pins any row whose text says "don't" or "never", facts included). `616046a71` made this change after `58d0834bf`'s seed-2 runs had 12 stale bullets, which I attributed to whole-row exemption by inference, without reading those bullets. A later seed-2 replay of `616046a71` showed six stale bullets with another cause, the gist below; the 12 were probably the same, not verified. The per-sentence reading stands on A4 §3.1 alone;
  - a revocation needs an A7 §5 action-class verb and revokes a rule of that class only when the rule's object, the words after its negated verb to the end of its clause, is within the revocation's object, and the revocation's object is named in the rule. That is D9's `(class, polarity, object)` read from text: "you can merge PRs yourself now" revokes "never merge PRs yourself" and "push the fix to the PR, but don't merge it yourself" (object `*`, the PR named), not "never merge PRs without a review", "never merge" or "never delete the main branch" after "you can delete the branch now";
  - the prompt passes the store's own secret redaction (`AgentMemory.storableText`, the chain every stored row passes) before anything is read, so the log can hold no token a row would not.
  On the public fixtures: E3, 330 labelled items: 1 retraction, correct, 17 labelled ones missed, no revocation; CueBench, 677 prompts and previous turns: none fires. Without keyed slots or persisted `invalid_at`, an invalidation is a value token plus a time, and a sentence is dropped when it names that token and is older, in any scope; the whole sentence goes, a still-valid clause in it included (seed 1's gist lost "the database is postgres" with "the auth provider is Auth0"). A session gist carries the time it was written, which the sleep renews at every Stop, later than the statements it summarizes: a gist rewritten after "We no longer use Redis" still said "stack uses Redis" and passed validity (a seed-2 replay of `616046a71` briefed it six times; the real-session control on `616046a71` briefed "stack uses ZebraCache" after its retraction). So the sleep checks each fact and rule sentence against the log at its source's time before composing the gist (`17abbd05d`; A4 §3.3, rows get their message's time), and SessionStart still checks the gist at its own time. `reload-stale` and `negation` (`no-redis`) turn green with it.
- **Rows have no time on disk.** The legacy store does not persist a row's `at`, so validity reads a row, and a gist's source, as older than every invalidation. A value restated after its retraction is therefore not delivered again, at Submit or in a gist, until P0.3 persists times: silence rather than a stale value, the direction A5's hard gate on `stale_rate` asks for.
- **D26 on a row of several sentences.** The legacy store keeps a whole prompt as one row beside its sentences. - **Sources (D12) without P0.4.** Only the hook's own inputs are marked: transcript tool results and PostToolUse results (`src:tool`), assistant text (`src:agent`, A6 §2.1's name; `observe` already received it with its role).
