## What changed

- **Non-human submits get nothing (D24).** A prompt that opens with `<task-notification`, `<agent-message`, `<cross-session-message` or `<teammate-message` gets no packet; so does a prompt equal to one of the window's last Stop `session_crons`. The hook returns before it opens any store (A4 §5.1 step 0), so the submit is not encoded at that moment and the human-turn counter does not advance.
  - The tag may follow a peer message's one-line preamble, `Another Claude session sent a message:` (R0 F34; Decisions).
  - Cron prompts are kept as 16-hex SHA-256 prefixes in `windows/<win>/ctx.log`, appended only when a Stop's crons differ from the last kept, never as text.
- **Ack turns get nothing (A7 §2).** Up to 3 of {ok, thanks, cool, nice, great, got it, sounds good}; or {continue, keep going, next, go on} when the agent's last message proposed nothing (no trailing `?`, no "shall I / want me to / should I / next I'll / I can"). The submit is still encoded and counted.
- **Continuation turns get nothing until the situation cue (P4.1).** "yes / do it / go ahead / proceed", the continue words after a proposal, or ≤ 4 content tokens after a proposal. A4 §0 lets a continuation inject only on STRONG evidence from the previous assistant message, which nothing can tell before P4.1.
- **A human-turn counter (A4 §4).** Each human Submit appends `{"k":"turn","prompt_id":…,"off":…}` to `<memory root>/windows/<session>/delivery.log` (A4 §1's layout); `hturn` counts distinct `prompt_id`s. Without a `prompt_id`, the prompt's hash and the offset key the record. Readonly consent writes none.
- **Bullets are not filled to a fixed count (D28).** In retrieval order, a bullet is skipped once its kind is full (≤ 2 rules, ≤ 1 procedure, ≤ 2 episodes, gists counted as episodes), at most 4 in all; a bullet that says what an earlier one said is dropped; one that does not fit 900 bytes is skipped, never cut. Nothing replaces a skipped bullet.
- **Declarative wording (D14).** Every packet opens `Eden memory, recalled from earlier sessions:` (the wrap's too). The hook writes a rule as `Rule you set: <text>` and ends every other bullet with its source and age: `(you said, 3 weeks ago)`, `(from a tool result, …)`, `(from a summary of earlier work, …)`. No `[kind · age · src]` tag reaches Claude from the hook. SessionStart's briefing uses the same renderer.
- `AgentMemory.recall` is `inject`'s retrieval, split out so the hook can shape and word the notes itself. `inject` keeps its packing and labels (the wrap's surface, P0.7); `recall` fails open and counts the swallow, as `inject` did.
- **The gate's instrument:** `arms/r6-replay.ts` replays the sessions R6 measured through a plugin's hooks, from a frozen copy, and prints counts only.

## Decisions made

- **D24, the peer preamble.** R0 F34: an idle peer message's transcript line opens `Another Claude session sent a message:` and then `<agent-message …>`; its UserPromptSubmit `prompt` was never captured. The detector accepts that one preamble line before the tag. If the live prompt is the bare tag, nothing changes; if it carries the preamble, D24's literal test would miss it. A human typing that exact preamble followed by the tag is not a realistic false positive. Follow-up: P0.8's wide events show the live shape; then settle D24's wording.
- **D24, encoding.** A non-human submit returns before any store opens (A4 §5.1 step 0, before step 1's encode). Its text reaches the store later, through the transcript, at the next human Submit or Stop, as today's hook reads the last 40 transcript messages there. Before, `inject` stored the notification itself as a user message, which D12 forbids. This also changes the store a little (the stale-rate note above).
- **Continuation is silent.** ROADMAP lists only ack/chatter for P0.2, but A4 §0 G3 allows a continuation to inject only on STRONG `q_prev` evidence, and nothing can tell STRONG evidence before P4.1. Silence is the reading that keeps G3. On the R6 corpus it silences 3 of 137 human prompts. The cost is real: "ok merge it" after "Shall I merge?" gets no packet, where A7 would deliver a policy through a trigger hit on the proposal (P2.2, P4.1).
- **A7's proposal markers as written**, plus one refinement: "I can't" and "I cannot" are not offers. "I can see …" in a report still counts as a proposal (A7's v1 rule); P4.1 tunes it.
- **D28, "stop at the first empty stage".** Read as "never fill": no stage pulls items in to replace one a cap or the byte limit skipped. The per-kind caps are A4 §5.1 step 8's. Soft limit 4 holds for every bullet; the hard limit 6 is for `Updated:` items, which do not exist yet (P1.1). Merging same-subject slot facts needs P3.3's slots; identical bullets are merged now. The old packer kept an oversized first copula whole past 900 B; D28's 900 B is a hard limit, so such a bullet is skipped.
- **D14, the header everywhere.** The header is the one packet mark (`MEMORY_MARK`), so every packet-recognizing check (echo protection, tests, the wrap) keeps working; the wrap's bullets keep their tags until P0.7 adopts the renderer. The scope parenthetical waits for P3.1; "earlier sessions" over-claims until P0.5's per-repo store, since today's store is per session.
- **D14, provenance.** The source a bullet names comes from the legacy row (`noteSource`, `user` unless tagged otherwise), as the old `[kind · age · user]` tag did. It is no truer than before: the end-to-end session shows a Write tool result worded "(you said)", and the `poison` arm's planted line now reads "Rule you set: …". P0.4 makes the source true by construction (D12). Ages appear only for rows with a wall-clock time; episodes persist none until P0.3.
- **The turn counter writes now**, in A4 §1's `windows/<win>/delivery.log`. With flags ignored until P0.8, every flagged arm's `off` state also fails `no-ledger` and its `shadow` state `no-live-ledger` (34 each); `arms.json` records that, with the run.
- **Readonly writes no window file** (turn records, crons), like every other write under readonly.
- **SessionStart** keeps its legacy selection (≤ 8 pins, 3 gists) but goes through the renderer, so it is now worded and within 900 B. D23's ≤ 3 pins is P2.5's.
- **The R6 replay protocol**: SessionStart, Stop and UserPromptSubmit only (tool events would take hours more, and Submit and Stop read the tool results from the transcript); human prompts as R6 §1.2 defines them; one shared Eden home in session order; a frozen copy, because Claude Code swept one of the 35 transcripts during this slice. A skill invocation is submitted as `/name args`.
- **`budget` (P1.1's arm) flipped green** at CI scale: 4,710 tokens per epoch over 100 human turns (base 8,595). At A5's 300 turns it still fails (14,882; base 29,749). `arms.json` records CI scale, and its `why` says so.
- **Hand-read packets come from the world replay**, not the R6 replay: the real sessions' packets would show the user's prompts to the agent, and X5 keeps real prompt text out of agent view.
- **#57:** "EDEN_MEMORY_CAP=40 clamps to 10 and packet bullets stay ≤10" passes now (the hook packet is ≤ 4 bullets), so its `test.failing` marker is removed. #57's other three tests still fail for reasons outside P0.2 (the first leg of the postgres test gets no packet at all from `inject`).
