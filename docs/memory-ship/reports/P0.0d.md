## What changed

- **`eden eval build-negatives` exists** (EXECUTION §8 steps 1–7, R9 §R5.3). It builds the user's private real-negative set from their own Claude Code transcripts into `~/.eden/eval/` (directory 0700, files 0600), and prints counts and paths only.
  1. **Select:** D12's user-typed entries of each project's main transcripts. Subagent files, task notifications, peer messages, compaction summaries, tool results, Claude Code's wrappers (`<command-…`, `<local-command…`, `<system-reminder>`, …) and headless `claude -p` prompts are skipped.
  2. **Strip:** D12's pasted spans: `<pasted_content>` blocks, fenced code, `>` quotes, spans of ≥ 200 characters that one of the last 10 tool results holds, runs of ≥ 3 lines without sentence-final punctuation.
  3. **Drop, never redact:** any secret-rule hit (D13, A6 §2.2), a JWT shape or an email address, checked on the raw prompt and again on what is kept.
  4. **Normalize:** `/Users/<name>/` and `/home/<name>/` become `…/USER/`, and this machine's host names `HOST`. Repo-relative paths stay.
  5. **Canary:** every build first screens 5 synthetic secrets of 5 shapes, with fresh random values. If one survives, the build aborts and writes nothing; the error names the shapes, never the values.
  - Candidates are keyed by the sha256 of their text. A rebuild keeps labels, adds new prompts, and keeps prompts whose transcripts Claude Code has since swept (30 days).
  - `--label` asks for each unlabelled prompt's label (`n`/`p`/`d`, `s` skip, `q` quit), one answer per line, saving after each. `--freeze` writes the `negative` rows to `real-negatives.vN.jsonl` with a `.sha256` in sha256sum's format.
- **D13's secret gate exists as a module** (`src/memory-secrets.ts`), on no hook path yet. It applies the vendored gitleaks v8.30.1 default rules the way gitleaks does (keyword prefilter, secret group, entropy floor, global and rule allowlists), with their Go regexes translated to JavaScript. It adds A6 §2.2 (b)–(d) and the provider shapes gitleaks lacks or gates on context. P0.4 builds `sanitizeForStore` on it.
- **D12's authority and paste stripping exist as a module** (`src/memory-authority.ts`: `userTyped`, `toolResultText`, `stripPastes`), on no hook path yet.
- **The harness loads and replays the silence set** (A5 §2 `silence` (c), §3.7):
  - `arms/negatives.ts` loads R1's 150 negatives, R8's 98 `nim-neg`, and the user's frozen set from `EDEN_EVAL_NEGATIVES`, checked against its `.sha256` by the product's reader. Without that variable, it reports `skipped: private set absent`; CI's test run prints that line.
  - `arms/silence.ts` plays a world scenario once to build a store, then asks every negative in a fresh session against that same store (Eden's files restored before each, so the samples are independent). It reports each source's false-inject rate with its Wilson 95% interval and the ids of the negatives that fired, never text. A control, the store's own prompts that need an item, shows whether the plugin can fire at all.
- **No hook behaviour changed:** no file under `plugins/` changed, and no hook entry point imports the new modules. The CLI loads `eval-negatives` only for `eden eval`.

## Decisions made

- **Where the D12 and D13 code lives.** EXECUTION §8 steps 1–3 need D12's selection and stripping and D13's rules, which P0.4 also needs. They are product modules in `src/`, so P0.4 builds on them instead of duplicating them; no hook calls them yet.
- **The rule set (D13, A6 §2.2).** gitleaks v8.30.1 is vendored verbatim and applied with gitleaks' own semantics, as far as text allows: path conditions never hold, and gitleaks' base64/hex segment decoding is not ported (P0.4 follow-up). Go syntax is translated: a leading `(?i)` becomes the `i` flag; an inner one becomes a modifier group closed and reopened around each later `|` of its group; `[[:alnum:]]`, `\z`, `\A`, `(?P<` are rewritten; any other POSIX class throws. All 221 regex rules compile.
- **Provider shapes beyond gitleaks (A6 §2.2 (a), "covers `cfat_` …").** gitleaks has no `cfat_` rule (R9 §R5.2 asked to add it), and it gates some shapes on context the `secrets` arm's synthetic values lack: OpenAI keys on the `T3BlbkFJ` marker, Mailgun and Telegram on the provider's name, AWS key ids on an entropy floor (one arm value ends in nine `Q`s). Bare-shape rules for these make the gate stricter, never looser; benign drops stayed at 2 of 1,224. A6 §2.2 (a) now says so.
- **D13's keyword rule is case-insensitive**, since env lines spell it `PASSWORD=`. It is otherwise verbatim, including its unanchored `is`.
- **Drop on the raw prompt.** A secret inside a paste is stripped anyway, but the drop rules run on the raw prompt too, so stripping that misses a paste cannot leak it. EXECUTION §8 orders strip before drop; checking both is stricter.
- **R9 §R5.3's extra drops** (a JWT shape, an email address) are in the command's drop rules, not in D13's module: they protect the negative set, not the store.
- **Headless prompts are skipped by the build, not by `userTyped`.** A real transcript showed `claude -p` prompts as `promptSource: "sdk"` with no origin; this machine's transcripts hold 28 such lines beside 153 typed. Scripts and agents (including slice e2e runs) send them, so they are not human prompts for the negative set (R6 §1.2). D12 still gives them the invoker's authority.
- **D12's spans, where A6 is terse.** "Spans ≥ 200 characters that also occur in a recent tool result" is read per paragraph, else per line, against the last 10 tool results before the prompt in its transcript. "Sentence-final punctuation" is `.`, `!` or `?`, optionally followed by a closing quote or bracket; a colon is not, and a blank line ends a run. Paste markers are matched anywhere in the text, with the same id, to the end when unclosed.
- **Normalization** is anchored to absolute paths, so a repo path like `app/home/page.tsx` stays; host names are this machine's full name and first label.
- **The canary** screens its 5 prompts with the same per-prompt function as real prompts, before reading any transcript, instead of writing them into a copy of the transcripts: the screen is the only stage that can drop a typed secret, and the prompts end in sentence punctuation so stripping cannot remove them.
- **The replay's store is a world scenario**, not the planted CueBench store P4.3's gate names: planting needs `eden memory remember`, which no slice has built. Each negative opens a fresh session against the same restored store, so each is an independent sample, as the Wilson interval assumes.
- **R9 calls the replay "the arm"**, but it is not in `arms.json`: a record there must reproduce in CI, and a private file cannot. CI runs its tests against the scripted plugin and prints the skip line.
- **This machine's transcripts were read once by the command**, into a temporary home deleted right after, printing counts only. The holdout rule concerns the frozen set and its text; no text reached this session.
