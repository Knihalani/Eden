# P2.5 — SessionStart + SubagentStart delivery

**Outcome:** merged. A subagent now gets a packet at SubagentStart (flag `deliver.subagent`, `shadow` by default): up to 3 bullets for the places its task names, plus the policies its task's and its type's classes fit. A fork is given nothing its parent already holds. A startup briefs at most 3 pins and no gists. `subagent` turns green, its new policy part included, and every other arm keeps its record.
**PR:** #137 (predicted before the single push) · **Merge commit:** the rebase merge of #137 onto `main` (shown on the PR page; this report is part of the merged tree) · **Date:** 2026-10-12

## What changed
- **The launch record (A4 §5.3, D23).**
  - A `PreToolUse` handler matched on `Agent` (`hook.ts spawn`, `memory-spawn-hook.ts`) appends `{k: "spawn", id, type, paths, classes, t}` to the session window's `spawn.log`. It prints nothing and opens no store.
  - `paths` are the places of the repo the task names: paths that exist, or a file name in a folder that exists. A relative path is read from the session's folder first. Prose with a slash ("and/or"), URLs and paths outside the repo are not places.
  - `classes` are the action classes the task names (A7 §5). The task's text is never kept (X11).
  - Nothing is recorded with the flag `off`.
- **SubagentStart (A4 §5.3, D23, D25, D27).**
  - **The claim.** SubagentStart takes the one unconsumed launch record of its type from the last 5 s, marked consumed under `flock`. With two open records, none is taken. With no record, or a task that names no place, the subagent gets the parent's recent paths: those of its last 3 human turns' tool batches. The scope is stored, and a resumed subagent reuses it.
  - **The packet.** Up to 3 bullets: first the policies and intents of the task's classes and the type's, then the rows the lexical path finds for the scope's paths. They pass validity, the gate, the child's shadow set and the child's ledger.
  - **Type classes.** A type's name is read as words, with its agentive ending as a verb ("code-reviewer" is review, "git-committer" commit). `memory-classes.json`'s `agents` map adds `integrate` to `review`, so a reviewer gets the merge policies.
  - **A fork** (`agent_type: "fork"`) copies its parent's current-epoch ledger at its first start, into its shadow ledger when the point is in shadow. It also reads the parent's whole conversation as its D26 residual.
  - **The child's shadow set** follows its type: a fork has the parent's whole set; a typed subagent has the parent's eagerly loaded files, the CLAUDE.md files and AGENTS.md; Explore and Plan have none.
  - **Distance.** A child window's deliveries, the guard's included, are measured on its own transcript (`subagents/agent-<id>.jsonl`).
- **SessionStart (A4 §5.2, D23).**
  - **Selection.** A startup or clear briefs at most 3, in order:
    - rules proposed for revocation;
    - the D11 proposal and the rules kept for all projects;
    - the repo's newest pins.
  - **No gists at startup.** A compaction keeps the 3 legacy gists and no pin (Decisions).
  - **CLAUDE.md from disk.** The project's CLAUDE.md files are read from disk before the shadow test, since Claude Code runs SessionStart(startup) before InstructionsLoaded.
  - **A rule-stripped row.** A row the rules kept for all projects leave with no rule of its own briefs its other text as a fact, not as "Rule you set".
- **A6 §2.5's revocation proposal.**
  - Declined asks go to the repo store's `declines.jsonl`.
  - A rule declined 3 times within 14 days is briefed as `Rule you set: … (you declined it 3× — say "that rule is gone" to remove it)`.
  - "that rule is gone" in the session's next 2 human turns ends it, unless the guard has asked since.
- **D11.** When "yes, everywhere" keeps a proposal shown in the previous session, the Submit says "Kept for all projects: …". It says nothing when `deliver.submit` is `off`.
- **`eden setup`** installs SubagentStart, and `eden hook` routes it. `eden doctor` expects 10 memory events.
- **SubagentStop** still does not encode the child's own transcript (decided here; see Decisions).
- **Key files:**
  - `src/memory-spawn.ts`: task paths, the record, the claim, the stored scope, parent paths, type classes.
  - `packages/cli/src/memory-spawn-hook.ts`: the `PreToolUse(Agent)` handler.
  - `packages/cli/src/memory-hook.ts`: `subagentStart`, `childScope`, `briefing`, `compactGists`, the Submit's acknowledgement, `endRules`.
  - `src/memory-revoke.ts`: decline log, count, shown record.
  - `src/memory-shadow.ts`: child sets by type, CLAUDE.md files on disk.
  - `src/memory-session.ts`: `childTranscript`.
  - `src/memory-ledger.ts`: `inheritLedger` (`off`, `into`).
  - `src/memory-residual.ts`: a fork's whole conversation.
  - `scripts/subagent-timing.ts`: targets 2 and 3.
- **Tests that asserted the old startup briefing** now state the new contract, each with an inline comment. Most move to SessionStart(compact), where gists remain, so they still guard gist validity and scrubbing: `src/sleep.test.ts`, `src/memory-identity.test.ts`, `src/memory-project.test.ts`, `src/memory-packet.test.ts`, `packages/cli/src/memory-hook-turns.test.ts`, `packages/cli/src/memory-hook-epochs.test.ts`. The `hooks.json` and setup/doctor event lists gain the new entries.

## Decisions made
- **Deviations from the prereg (disclosed):**
  - (a) The prereg says "no gists". A compaction's SessionStart still briefs the 3 legacy gists, and no pin:
    - With gists removed there too, `negation` went red. Its control need ("how should we cache sessions?") was met only by the compaction's gist, because the Submit's lexical recall misses "caching".
    - A green arm must stay green, and A4 §5.2 says only "re-arm" for a compaction. So the gists stay there until the cue path brings a dropped row back, filed for P4.2.
    - The red test "after a compaction, nothing" became "no pin, the legacy gists".
  - (b) The prereg's "by `tool_use_id`, else …": the meta file that names the call is written after SubagentStart returns (seen in the real session), so that path is removed, with its tests. A4's rule is read strictly: one open record of the type, else the parent's paths.
  - (c) "`shadow` only the shadow ledger" holds: a fork under shadow copies its parent's deliveries into its own shadow ledger, which the shadow point reads beside the live one.
  - (d) The red D11 test asserted the stripped row's fact is not briefed. P2.4's follow-up and P2.4's round-2 test want it briefed. A keyed row is no candidate of the lexical path, so dropping it would lose the fact everywhere. It is now briefed as a fact, not "Rule you set".
- **The record holds the task's classes, never its text** (X11). "Policies whose classes fit the task" need only the classes.
- **The parent's read set until P3.2** is the paths of its last 3 human turns' tool batches (D4's main-thread paths).
- **A type's classes** come from its name's words plus the `agents` map (`review` adds `integrate`), A4's reviewer example as data.
- **The revocation count is read at SessionStart** from the store's decline log. A6 has sleep propose it; the count is a read of the same records, so no proposal file is kept. The proposal counts in SessionStart's 3 whether or not the rule is a pin.
- **SessionStart's `Updated:` items are refiled to P3.3.** They need a lookup from a delivered cid to its current value, which keyed slots give, and nothing changes a value between sessions before P3.4's mining.
- **SubagentStop does not encode the child's own transcript** (the follow-up asked P2.5 to decide; P0.6 had deferred it at the user's request). The parent's Agent result carries what the child found, and rows made from the child's reads would come back to the parent as bullets it holds (P0.6: `redundant_rate` +4.42 pp).
- **"fork" is Claude Code's fork mode**: on by default in interactive sessions, off under `-p` unless `CLAUDE_CODE_FORK_SUBAGENT=1` (the sub-agents reference), which is why 2.1.285 headless rejected it. It was captured with the variable on 2.1.294.
- **`deliver.subagent` stays `shadow` by default** (X7). Stage S3 turns it on.
- **`eden setup`** installs SubagentStart only: its PreToolUse is the compile hook, so its subagents take the parent's paths (filed below).
