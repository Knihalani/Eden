# P3.1 — Scope catalog (R5 §9 rule)

**Outcome:** merged. Every repo store now holds a scope catalog derived by R5 §9.2's rule (D3) from the main checkout's `git ls-files -co --exclude-standard`. It is kept current after a manifest write and at sleep, and looked up by longest prefix without the filesystem. `r5-unit-rows` turns green (16/16), every other arm keeps its record, and the guards are identical to `main`'s. `eden memory scopes`, `eden memory forget --all-in <scope>`, a scope on each remembered row, and the doctor's catalog line now exist. No delivery point reads a scope yet (P3.2's read set).
**PR:** #138 (predicted before the single push) · **Merge commit:** the rebase merge of #138 onto `main` (shown on the PR page; this report is part of the merged tree) · **Date:** 2026-10-12

## What changed
- **The rule (R5 §9.2, D3), `src/memory-scopes.ts`.**
  - **Files (step 1):** `git ls-files -z -co --exclude-standard` in the main checkout. Git's own variables (`GIT_DIR`, …) are cleared, and git's untracked nested repo entry (`agent-x/`, trailing `/`) is dropped.
  - **Manifests (step 2):**
    - Name-only: Cargo.toml, go.mod, pyproject.toml, deno.json, setup.py, pom.xml, build.gradle(.kts), *.gemspec, *.csproj, *.fsproj, composer.json, mix.exs, Package.swift, pubspec.yaml.
    - Content: package.json with a non-empty string `name`; setup.cfg with a `[metadata]` `name =`; DESCRIPTION whose first field is `Package:`; CMakeLists.txt and meson.build with a `project(` line.
    - nx's project.json only with a root nx.json. Bazel BUILD never counts.
    - A listed file is read only when it is a regular file inside the checkout, ≤ 1 MB.
  - **Workspace members (step 3):** package.json `workspaces` (array or `.packages`), pnpm-workspace.yaml (`!` negation), Cargo and uv `members` minus `exclude`, go.work `use`.
    - Globs resolve from the declaring file's folder.
    - A match needs a manifest.
    - A declaration in an excluded folder is ignored unless that folder is itself a member.
  - **Exclusion and buckets (steps 4–5):** R5's VENDOR / TEST / EXAMPLE segments (case-insensitive), dot segments and single-`_` segments exclude a folder. A member is never excluded. An EXAMPLE tree becomes one bucket scope.
  - **Min-2 (step 7):** applied deepest first. The folders it drops are kept as `waiting`.
  - **Bazel/Buck/Pants fallback (step 8):** only at such a root, and only where `""` owns over half the files.
  - **`.eden/scopes` override (step 9):** applied in line order; `!` removes a scope, never `""`.
  - **Lookup (step 10):** longest prefix on a `/` boundary.
- **Paths (§9.1):** `repoPathOf` maps a path to its repo key (D1) and to a path relative to its own worktree's top, with links resolved and the filesystem's case. So an agent worktree's `packages/know/src/a.ts` is `packages/know`.
- **The catalog file**, `<store>/scopes.json`: `{built, checkout, scopes, waiting}` (Decisions).
- **When it is built (A4 §2):**
  - **At a turn's end,** when the store has none: the async Stop's last step, listing for ≤ 10 s. Not at SessionEnd.
  - **After a write that can change it:** a PostToolBatch (or, for hosts without batches, a PostToolUse) whose Write/Edit/MultiEdit/NotebookEdit wrote one of: a manifest, a workspace file, a build-system root file, `.eden/scopes`, or a file a waiting folder owns. Writes of another repo don't count. Listing is limited to 1 s, since the batch blocks the agent.
  - **At the idle sleep,** from the checkout the catalog recorded, while that checkout still keys to the store.
  - The wide event of an event that rebuilt it carries `catalog: <scope count>`.
- **Rows carry `scope` (A4 §1; absent is `""`).** `eden memory remember` stores the catalog scope owning the line's `scope` hint (a folder relative to the repo's top), else owning the folder it was said in.
- **Commands:**
  - `eden memory scopes [--json] [<path>…]`: the arm's contract. It builds the repo's catalog now, and stores it unless memory is off or read-only.
  - `eden memory forget --all-in <scope>` (A6 §3): sends the scope's keyed (D9 rule) rows to history. It takes a catalog scope, or one live keyed rows still carry after their folder went. It exits 2 on an unknown name and lists the scopes. It never reads a store of an unknown format.
  - `eden doctor --memory`: `scope catalog: N scopes · built <iso> from <checkout>`, `none built yet …`, or `outside git: one scope`.
- **Key files:**
  - `src/memory-scopes.ts`: the rule, paths, listing, build, read, triggers.
  - `packages/cli/src/memory-scopes.ts`: `scopes`, `forget --all-in`.
  - `packages/cli/src/memory-hook.ts`: `rebuildAfterWrites`, `buildMissingCatalog`.
  - `packages/cli/src/memory-sleep.ts`: the idle sleep's rebuild.
  - `packages/cli/src/memory-remember.ts`: row scopes.
  - `src/index.ts`: `MemoryRecord.scope`, and `forgetScope` sharing `toHistory` with `forget` and `abandon`.
  - `src/memory-batch.ts`: `writtenPaths`.
  - `packages/cli/src/doctor-memory.ts`: `scopeCatalogCheck`.
- **Spec notes:** DECISIONS D1 and D3 (built in P3.1), A4 §2.

## Decisions made
- **`scopes.json` is `{built, checkout, scopes, waiting}`, not R5 §9.2 step 10's bare sorted list.** `built` gives the doctor its time. `checkout` lets the idle sleeper, which knows only its store, rebuild. `waiting` closes R5 §10's lag: a new package becomes a scope when its second file is written, not at the next sleep. `scopes` is the sorted list.
- **Files come from the main checkout** (R5 §9.2 step 1, "in the main worktree"). A package created in a linked worktree joins the catalog once the main checkout has it (follow-up).
- **Rows the hook encodes stay at `""`.** A slot fact is written at the working scope (A4 §2.3 via R3 F10, D7's `default_scope`), and the working scope comes from P3.2's read set. Only `remember` rows, whose folder is explicit, get a scope now.
- **"Keyed rows" (A6 §3) are rows stating D9 rules.** Slot keys are P3.3's.
- **`forget --all-in` takes an exact scope.** A nested scope inside it is another product (R5 P9). It also takes a scope that live keyed rows still carry, so rows of a removed or renamed package can still be forgotten.
- **A missing catalog is built only at the Stop, not by a batch.** A batch blocks the agent, and a first listing of a large repo takes 1–5 s cold (R5 §8). SessionEnd shares a 1.5 s budget (R0), so it builds none.
- **A manifest over 1 MB, a non-regular file, or a link leaving the checkout is not read**, and so is no manifest. Git lists a link as a file, and a device would never finish reading (round 1's major).
- **Timeouts:** git may list for 1 s in a batch, 10 s at a Stop, and 30 s at sleep or from the CLI. A listing that times out leaves the catalog as it was (fail open).
- **`.eden/scopes`:**
  - lines apply in order;
  - an add matches any folder of the files;
  - `!` removes a matching scope, never `""`;
  - `#` lines and blank lines are skipped;
  - min-2 does not apply to override scopes (the override is applied last, as step 9 says).
- **Deleted red test:** the red commit had a pure-function test that git's trailing-`/` entry is no file. The filter moved into `repoFiles`, where git's output is read, and its git test covers it. The drop is named in f21d3279d's message.

## Not done / follow-ups
- **P3.2:**
  - The replay worlds (`harness/fixtures/demo-world.ts`) give `apps/web` and `packages/cli` only a `package.json`. Min-2 leaves both waiting, so the guard worlds have one scope. P3.2's place checks need a source file per package there (a `fixture:` change, with a `harness_sha` amendment).
  - Rows the hook encodes (typed rules, facts) are stored at `""` until a working scope exists. So `forget --all-in <package>` does not reach a rule typed while working in that package.
  - A package created in a linked worktree is not a scope until the main checkout has it. Each manifest write there lists the main checkout for no change, at most 1 s.
  - A write a waiting folder owns that never lands in `git ls-files` (ignored output, a failed write, the replay worlds' writes) rebuilds the catalog on every batch (Evidence: 7.8% and 6.8% of the worlds' batches). Fix: rebuild only when the written file exists and git lists it.
- **P3.3:** `forget --all-in` should also take keyed slot facts.
- **P4.2:** a repo git cannot list within the Stop's 10 s never gets a catalog. The idle sleeper has no recorded checkout to build from, so every scope reads as `""`. A sleep-built snapshot with the checkout passed in would cover it.
- **No owning slice (stays here):** `packages/cli/src/memory-hook-recur.test.ts` runs `forget --secret` without `CLAUDE_CONFIG_DIR`, so the purge lists real `~/.claude/projects` transcript paths in the test output. It reads only and changes nothing, but the test is not isolated. This slice's own test sets `CLAUDE_CONFIG_DIR`.
