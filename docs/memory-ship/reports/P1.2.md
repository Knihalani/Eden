# P1.2 — Epochs

**Outcome:** merged. A compaction now re-arms only what its summary dropped. SessionStart(compact) starts an epoch; PostCompact then holds each delivery of the closed epoch whose value tokens `compact_summary` still names, so a fact the summary keeps is not delivered again while a rule it dropped comes back on its cue. `clear` starts an epoch. A forked session brings nothing at its SessionStart and copies its parent's ledger after its first turn. The internal compaction agent's SubagentStop writes nothing. `compaction` is green; `resume` and `rewind` stay green; every guard is identical to `main`.
**PR:** https://github.com/Knihalani/Eden/pull/130 · **Merge commit:** printed in the slice's final message (this report is part of the merged PR, and no commit follows the merge) · **Date:** 2026-10-10

## What changed
- **Value tokens (A4 §4, R0 F14).** Each `deliver` record carries its value tokens, each hashed (`vt`, X11):
  - a slot: its value's words ("postgres", "node 22");
  - a rule: its class verb and object, from the first clause that names an A7 §5 action class. "Don't merge PRs yourself" gives `integrate` and "pr". The object is the words after the verb; when the verb ends its clause ("Run the tests before you commit"), it is the clause's other words, without rule markers or words that only link clauses ("before", "without"). A clause naming only its class ("Never deploy", "Before you deploy, ask me") gives none. A rule with no class verb keeps its object words;
  - episodes, gotchas and procedures: none.

  A summary names a class with any of its verbs in any inflection ("merging", "committed"), and an object in either number ("PRs", "PR").
- **PostCompact.** Claude Code runs SessionStart(compact) just before PostCompact (R0 F32). SessionStart(compact) starts an epoch in every ledger the window has, which re-arms everything, as before. PostCompact then appends one `held` record per ledger: the deliveries of the epoch the compaction closed whose value tokens the summary names in full. The fold moves those to the new epoch, at the summary's offset and on every branch (`att` ""). Everything without value tokens is always re-armed. PostCompact reads no store, and its wide event logs `held` (cids) and `rearmed` (a count). A host without PostCompact re-arms everything, as before.
- **`clear`** starts an epoch, as `compact` does. Claude Code gives `/clear` a new session, so this matters for a host that keeps the id.
- **Fork (D25, D2).** On Claude Code 2.1.294 a fork's SessionStart (`source: "fork"`) names no parent, no environment variable does, and its transcript is written only after its first turn, as the parent's lines with their `uuid`s kept and each `promptId` replaced. So:
  - SessionStart(fork) brings nothing, like `resume`, and marks the window in `ctx.log` with when the parent last answered;
  - the fork's first `stop-sleep` (or SessionEnd) finds the parent. Candidates are the windows of the transcripts beside its own, at most 32, nearest the parent's last answer first. The parent is the one whose turn map (`hwm.json`) holds the newest of the fork's lines, and a window that is itself a fork loses a tie;
  - it copies the parent's current-epoch deliveries on its branch, except those made at the parent's prompts after the fork point (`inheritLedger`). The parent's `tokens_epoch` is copied whole, an upper bound. The mark is resolved either way, and the wide event logs `forked_from` and `copied`.
- **The internal compaction agent** (`agent_type: ""`, R0 F32): its SubagentStop returns before any store is opened. Its last message is the summary, which the main transcript's compact-summary line already carries to the delta encoder.
- **Registration.** The plugin's `hooks.json` and `eden setup` register PostCompact, `eden hook` routes it, and `eden doctor` checks for it: 8 memory events, so an older `eden setup` install shows "missing PostCompact".
- Key files:
  - `src/memory-value-tokens.ts` (new): value tokens and the summary's token set.
  - `src/memory-ledger.ts`: `vt` on keys and records, the `held` record, `holdSummarized`, `inheritLedger`.
  - `src/memory-fork.ts` (new): `markFork`, `inheritFork`.
  - `src/memory-window.ts`: `fork` records in `ctx.log`. `src/memory-delta.ts`: `turnMap`.
  - `src/memory-validity.ts`: exports `ACTION_VERBS` and `objectWords`.
  - `packages/cli/src/memory-hook.ts`: PostCompact, SessionStart `clear`/`fork`, `stop-sleep`'s fork copy, the compaction agent's skip.
  - `packages/cli/src/{hook,setup,doctor}.ts`, `plugins/eden-memory/hooks/hooks.json` and `README.md`: PostCompact.
  - `docs/memory-ship/DECISIONS.md` (D2, D25) and `A4-DELIVERY-CONTRACT.md` §4: what P1.2 built and its narrow readings.

## Decisions made
- **Value tokens** (A4 §4 names them for slots, policies and intents only): episodes, gotchas and procedures have none, so a compaction always re-arms them. A rule whose clause names only its class has none either: any summary mentioning a deploy would otherwise hold "Never deploy" (review round 1). A class's default object is not widened ("pull requests" does not name "PR"): filed to P2.1.
- **Which deliveries a summary can hold:** those of the epoch the compaction closed. A held delivery counts its re-eligibility distance from the summary (its `off`), and is on every branch (`att` ""): the summary, not the old prompt, now carries it.
- **SessionStart(clear) and SessionStart(compact) start the epoch; PostCompact holds.** R0 F32's order puts SessionStart(compact) first, so a host without PostCompact keeps P0.2's re-arm-everything.
- **SessionStart(fork) brings nothing,** as `resume` (D25 groups them; the fork holds its parent's context, packets included; before v2.1.214 a fork reported `resume`).
- **The fork copy waits for the fork's first `stop-sleep`:** no payload names the parent and the transcript appears only after the first turn (captured), so the fork's first turn runs on an empty ledger. A heuristic match at SessionStart (the parent's last answer time) could copy the wrong ledger; I chose the exact match by line uuids.
- **The fork's `tokens_epoch` is the parent's whole epoch,** an upper bound: a snapshot keeps it as one sum. It is exact for an idle parent (`--resume --fork-session`), and the overcount errs toward fewer packets under the 6k cap.
- **Only the parent's current epoch is copied:** if the parent compacted after the fork point, what it delivered before that compaction comes once more in the fork (one repeat each).
- **The internal compaction agent's SubagentStop is skipped** before the store is opened (R0 F32 names P1.2).
- **`rewind`:** already built by P0.2/P0.6 (deliveries on an abandoned branch do not count, read from the delta encoder's abandoned prompts); P1.2 changes nothing there and the arm stays green.
