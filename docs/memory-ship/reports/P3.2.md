# P3.2 — Place signal + read set

**Outcome:** merged. Every window now has a read set: the ≤ 2 scopes holding ≥ 30% of D4's path weight, from what its prompts named and its batches touched. Rows the hook encodes are stored at their scope, Submit and SubagentStart deliver only what A4 §2 makes visible from the read set (never a sibling folder's row), and a turn on two folders gets one bullet per slot (`auth provider — apps/web: Clerk · packages/cli: has no auth`). `fan-out` turns green, `scoped`'s `no-leak` (accepted red since P0.5) passes at CI scale, `single-package` stays green, every other arm keeps its record, and no guard gets worse.
**PR:** #139 (predicted before the single push) · **Merge commit:** the rebase merge of #139 onto `main` (shown on the PR page; this report is part of the merged tree) · **Date:** 2026-10-13

## What changed
- **Place signal (`src/memory-place.ts`, D2, D4, A4 §2).**
  - **Paths by source.** A human Submit appends a `prompt` record to the window's `ctx.log` with the places of the repo its prompt names (paths only, never text, X11), and reads them directly. A PostToolBatch records its tool paths and, apart, its Bash paths: a `cd` target that is a place of the repo, and path arguments read from there. A command that moves out of the repo records none. A subagent's batch is also appended to its session's window as `sub`.
  - **Weights.** Each distinct path gains the weight of every source it is in: prompt 3; a tool path of the newest batch 2, of the last 3 human turns 1; a Bash path 1. Subagent paths weigh 0.5 and count only while the main-thread paths carry < 30% of all the weight.
  - **Recent.** The last 3 human turns are the records from the third-newest `prompt` record on, the current Submit's included. Each source reads its 64 newest distinct paths. `stop-sleep`'s compaction keeps exactly these.
  - **Read set.** Every scope holding ≥ 30% of the weight, at most 2, heaviest first (ties: the scope met first). With none at 30%, the catalog scope owning the paths' common folder; with no path, `""`. Another repo's paths are ignored.
  - **Unknown place.** With no readable catalog (a repo's first moment, a broken `scopes.json`, outside git) nothing is filtered and rows are stored without a scope, as before P3.2.
- **Rows carry a scope.**
  - Each row the hook encodes gets the one catalog scope its text names. A relative path is read from the top, else from the session's folder; a file path in the root's own folders names `""`; URLs and prose slashes name nothing.
  - With several named scopes: the working scope (the read set's first) if it is among them, else their common ancestor.
  - Naming none: the working scope, or `""` for a rule and for a fact of one of D7's root slots (`default_scope: root`).
  - `scope: ""` is written explicitly, so a row with no `scope` means "written where the place was unknown"; such a row stays visible everywhere. `eden memory remember` now writes `""` at the root too.
- **Visibility (A4 §2).**
  - A legacy fact (until P3.3, a slot fact), a policy or an intent is visible at its scope and below. Any other row only at its scope, and from an ancestor only when the prompt names that scope. Nothing at a sibling.
  - Submit filters the lexical path, the narrative and ICL lanes' own indexes (by each hit's row), the how-to lane and the compiled triggers, before their caps. SubagentStart filters by the child's read set.
- **Two-scope bullet (A4 §2, D4), at the shape step.**
  - A one-clause legacy copula row at one read-set scope takes the other scope's value from the packet's candidates, else from that scope's newest live row the user typed that states the slot's subject words. "has no auth" and "… is …" state them; a question, an instruction, a state (D7's status lexicon, "a mess") and any row of the prompt being answered do not.
  - The ledger records both rows (`parts`). A later candidate saying only a value the bullet gives is dropped. Other candidates at either scope are labelled `<scope>: …` after their packet label, unless they name their scope.
- **Ledger:** a legacy slot's cid is `s:<scope>|<subject hash>` for a folder scope (A4 §4); the root keeps `s:<hash>`.
- **Supersession stays within a scope (A4 §3.2):**
  - at write;
  - at the idle sleeper's assembly, which runs per scope group, with rows of unknown scope in every group and only those giving the unscoped semantic store's tombstones;
  - in `validity.jsonl`: a supersession's `retract` keeps the superseded row's scope (`in`), and `validText` applies it only to rows at that scope or of unknown scope;
  - on the overwrite route (`sf-assemble`), assembled per scope and without the semantic store's unscoped values where a place is known.
- **SubagentStart (A4 §5.3):** the child's `scope.json` holds its read set: its task's paths read as a prompt's, or the parent's read set (P2.5's follow-up), with the parent's recent paths as the cue.
- **Catalog (D3):** a repo's first SessionStart builds its catalog (≤ 1 s) so its first prompt is placed. A write into a waiting folder rebuilds only for a regular file git lists (`listedFile`). A write in a linked worktree rebuilds nothing.
- **Wide events:** Submit and SubagentStart carry `read`, the read set's size (no folder names, X11).
- **Key files:**
  - `src/memory-place.ts` (new): paths, weights, read set, visibility, rows' scope, two-scope bullet; `taskPaths` moved here from `memory-spawn.ts`.
  - `packages/cli/src/memory-hook.ts`: place per event, prompt records, Submit and SubagentStart filtering, two-scope delivery, SessionStart catalog, rebuild rules.
  - `src/index.ts`: rows' scope, `RowFilter` through retrieval, per-scope supersession and assembly.
  - `src/sleep.ts`: per-scope assembly.
  - `src/memory-validity.ts`: scoped retracts.
  - `src/memory-batch.ts`: Bash paths.
  - `src/memory-window.ts`: compaction by prompt record.
  - `src/memory-ledger.ts`: scoped slot cids.
  - `src/memory-scopes.ts`: `listedFile`.
  - `src/memory-spawn.ts`: the child's read set.
- **Fixture** (`fixture:` 0fb4a3b59, P3.1's follow-up): the replay worlds' `apps/web` and `packages/cli` each get a source file, so the guard worlds have three scopes.
- **Spec notes:** DECISIONS D2, D3, D4; A4 §2, §4, §5.3.

## Decisions made
- **D4's weights add up per source:** a path in the newest batch is also a path of the last 3 turns (2 + 1). R6 §9.4 asks that main-thread and most recent paths outrank older ones, and summing does that. "The last 3 human turns" are counted by `prompt` record position, the current Submit's included (in read-only consent, which records nothing, the three earlier ones).
- **D2's tie-breaker read literally:** subagent paths count only while the main-thread paths carry < 30% of (main + 0.5 × subagent) weight.
- **Rows' scope (A4 §3.2, D7):**
  - A rule is stored at `""` unless it names a folder (A4 §2: policies are mostly `""`), so the P3.1 follow-up about `forget --all-in` and rules typed in a package stays open (refiled to P3.3).
  - A fact of a D7 root slot goes to `""`. Until P3.3's slot table this is a heuristic: the copula's subject, or D7's patterns.
- **Unknown place:** with no catalog, rows are stored without a scope and nothing is filtered, rather than collapsing every reader to `""`, which would hide every placed row. A row without `scope` therefore means "unknown", and P3.2 writes `""` explicitly.
- **Until P3.3, legacy kinds map to A4 §2's table:** `fact`/`preference` read as slot facts (own scope and below, without P3.5's override); rules as policies; every other row as an episode (exact scope).
- **The two-scope bullet before slot keys:** the slot is a one-clause copula row's subject words (P1.1's and D26's convention); the other value is a typed row stating them. A4 §4's `s:<scope>|<slot>` is kept for folder scopes; root slot cids are unchanged so existing ledgers stay valid.
- **A repo's first catalog at SessionStart (≤ 1 s):** P3.1 built it only at a turn's end, which left a repo's first prompt unplaced.
