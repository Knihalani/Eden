## Decisions made

- **Deviation: literal text may exceed 120.**
  - **The conflict.** EXECUTION R-5 asks for "no line exceeds the limit", and for a diff that is "formatting only", verified by an identical test run; PROGRESS's gate says "AST-equal or identical test results". For literals the two requirements conflict:
    - Prettier never breaks a literal.
    - Splitting a string (`"ab"` → `"a" + "b"`) or rewriting a regex changes the program, so the result is not AST-equal.
  - **The side effects of splitting.** It would also:
    - re-indent whole test bodies, because Prettier keeps `test("title", () => {` on one line only when the title is a single literal;
    - make test titles and error messages unsearchable.
  - **What I chose.** I kept the diff formatting-only. The check lets a line past 120 only by literal text, which matches ESLint's `max-len` options (`ignoreStrings`, `ignoreTemplateLiterals`, `ignoreRegExpLiterals`). The code in a template's `${…}` still counts.
  - **When it was chosen.** After the probe, not before (see the disclosure above).
  - The reviewer agreed with the choice on the merits.
  - The rule is stated in `CLAUDE.md` and in the checker's header, and EXECUTION's R-5 row records it.
- **Width 120.** Measured with `widths.sh` (session scratchpad):
  - **Method.** 60 files that no `whatever:` commit touched (12,735 lines), each formatted from the base tree with CLI flags only. The metric is lines removed per `git diff --no-index --numstat --diff-algorithm=myers`, summed.
  - **Results.** 120 rewrites the fewest existing lines: 235, against 667 at 80, 295 at 100, 249 at 110, 286 at 130 and 378 at 140.
  - **Defaults.** At 120 Prettier's defaults win: trailing commas `es5` gives 320 and `none` gives 463; `arrowParens: avoid` gives 364.
  - **Reproducibility.** These are the prereg's numbers, and they reproduce exactly with `widths.sh`. The reviewer reproduced them independently from base (`rev-runs/widths2.sh`). Its different round-1 values came from sampling the already-reformatted tree, which held 2 of the 60 sample files.
- **Scope.**
  - Whole directories for the loop's scope and `scripts/`, so new files there are covered automatically.
  - Only the four pack-touched files in `packages/know/src`, because its generated data tables have lines up to 38,175 characters, which Prettier would explode.
- **CI enforcement is part of the slice.** A max line length that nothing checks would not keep "every later diff in those files reviewable", EXECUTION R-5's reason. EXECUTION §6 already anticipates "a formatter/max-line-length check".
- **The checker's test lives in `scripts/`.** `test.sh` did not discover `scripts/*.test.ts`. It now passes them as files, because a bare `scripts` argument would match any path containing it. The test that pins `test.sh`'s last line was updated in its own `fixture:` commit.
- **History rebuilt after review round 1** (the branch was not yet pushed).
  - The fixture now comes first and accepts both forms of the line, so no commit on `main` is red.
  - `scripts/` is formatted.
  - The checker counts template code.

  The round-1 branch is kept locally as `mem/R-5-format-v1`.
- **Worktrees in the scratchpad.** The slice worktree and the base and head verification trees sit outside the main checkout. That way no ancestor `node_modules` leaks into tsc or Bun resolution, which was P0.−1's lesson.
