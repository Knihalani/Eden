# P2.3 — PreToolUse policy guard

**Outcome:** merged. Before a command breaks a rule the user typed, Eden now asks: `gh pr merge` after "Don't merge PRs yourself" asks "Eden: rule you set (1 day ago): pull requests are merged by you, not by the agent", and Claude gets the same rule next to the tool result. It asks only for a prohibition on an irreversible class or a live intent, only in `default`, `acceptEdits`, `plan` and `auto`, and never denies. The four gate arms are green, the 48-case fixture table scores recall 24/24 and precision 24/24, and the guard's p99 is 63.9 ms (n 1,000). As shipped (`guard.context` shadow, `guard.ask` off, X7), the guard prints nothing and logs `would_ask`; stages 5 and 6 turn it on.
**PR:** https://github.com/Knihalani/Eden/pull/135 · **Merge commit:** printed in the slice's final message (this report is part of the merged PR, and no commit follows the merge) · **Date:** 2026-10-11

## What changed
- **One handler per command, re-checked before the guard loads.**
  - `hooks.json` registers 16 Bash handlers: one per command A7 §5's patterns start with (`Bash(git *)`, `Bash(gh *)`, `Bash(rm *)`, …) and the three wildcard-led patterns as written (`*deploy*`, `*migrate reset*`, `*db drop*`). It also registers the `mcp__.*__merge.*` matcher. Each runs `hook.ts guard <n>` in shell form, ending `2>/dev/null || true`.
  - Why not A7's one handler per `(class, pattern)`: in code review, its 29 narrower rules all fired on any `$()` line. In a real session that cost ~1.3 s per call.
  - `hook.ts` reads the payload and checks it against every class (`src/memory-guard-match.ts`) before loading the guard. A call no class is (`git status`, `bun test`, `gh pr view`) costs a process start and logs nothing.
- **The answer** (`src/memory-guard.ts`):
  - Commands are read as Claude Code reads an `if` rule: subcommands, `$()` and backticks, leading assignments.
  - A command named by a variable names no class, and neither does `--help` or `--dry-run` outside quotes.
  - A rule of the call's class applies when the call names its object (`*` always does; "don't delete the fixtures" applies to `rm -rf tests/fixtures`, not to `rm -rf node_modules`). For history-rewrite it must also name the rule's action ("never force-push" is not "never rebase").
  - Rules are read through validity as at every delivery point: revoked, overturned, ended, and intents over 7 days old are gone.
  - The most severe class with a rule that applies answers, with ≤ 2 rows.
  - An ask is due for a prohibition on an irreversible class or for a live intent. In `dontAsk` and `bypassPermissions` the guard tells only and logs `guard_bypassed`.
  - Wording: each rule is its own clause of what the user typed, "Rule you set (<age>): …". A prohibition on the agent alone ("… yourself") of a class's default object is said as who does it (D14).
- **The hook** (`packages/cli/src/memory-guard-hook.ts`):
  - Flags (X7): `guard.context` gives the context; `guard.ask` gives the ask, which carries its context unless context is `off`; `shadow` logs `would_ask` and writes the shadow ledger.
  - `EDEN_POLICY_GUARD=off` silences the whole guard.
  - One answer per call: the first handler to record the call in the window's `guard.log` (under `flock`) answers.
  - The ledger records what it tells, outside the refractory rule and the budget.
  - Read-only consent answers nothing.
- **The rule index** (`src/memory-rule-index.ts`): A4 §1's `policies.jsonl` and `intents.jsonl`, written beside a repo store at each persist when they change, so the guard never loads the store.
- **After the call** (`src/memory-guard-log.ts`, `packages/cli/src/memory-hook.ts`):
  - PostToolBatch labels each ask `approved`, `declined` or `denied`. Sleep labels any ask still pending from the transcript.
  - An intent ends when its ask was approved and the call ran (validity `end` records).
  - "Open it now." releases the intent whose own verb, or class verb, it names.
  - "That rule is gone", as a whole sentence in the human turn after the ask, ends the rule asked about.
- **Elsewhere:**
  - A repo's `.eden/flags.json` may lower `guard.ask`, never raise it (`src/memory-flags.ts`).
  - `eden doctor --memory` prints the guard's two flags, `EDEN_POLICY_GUARD` and the indexed rule rows.
  - Shared hook helpers moved to `packages/cli/src/memory-hook-io.ts`, and session names to `src/memory-session.ts`, so the guard loads less of Eden.
  - `scripts/guard-timing.ts` measures the guard as Claude Code spawns it.
- **Harness** (`fixture:` commits):
  - The simulator evaluates handler `if` rules (`harness/permission-rule.ts`). A `$VAR` outside the command name runs nothing, as a real session showed.
  - An arm's `on` state writes every point `on`.
  - `fail-open`'s script runs a guarded command.
- **Spec notes:** D19, A4 §5.4, A7 §5 and EXECUTION X7 record what was built.

## Decisions made
- **Registration (D19, A7 §5).** One handler per command, not per `(class, pattern)`, because the narrower rules fire on any `$()` line (~1.3 s per call in a real session).
  - The cost moves: every `git`, `gh`, `bun`, `npm`, `pnpm`, `yarn`, `pip`, `cargo`, `rm`, `psql`, `vercel`, `fly` and `kubectl` command now starts one guard process, which exits before loading the guard: 40.6 ms p50 in the run of record.
  - Shell form, not A7's exec form: every hook ends in `2>/dev/null || true` to fail open (P0.8).
- **Asks for prohibitions only.** A positive rule ("always run the tests before you push") tells, never asks: it says how to do the action, not to stop it (D19's "ask … for an irreversible class or any live intent", read with A6 §2.5).
- **Object and action matching** (A6 §2.5, "no blanket asks"). A rule applies only when the call names its object, so "Never push to main" stays silent on a bare `git push` made while on `main`. This is a recall gap, filed below.
- **Flags (X7).**
  - An ask carries its context unless `guard.context` is `off`, since A6 §2.5 says the guard sends both.
  - `EDEN_POLICY_GUARD=off` silences the whole guard, as D19 says, not only `guard.ask`.
  - A repo file may lower `guard.ask` but not raise it. A cloned repo is untrusted, and the ask is the one control-flow path (PROGRESS follow-up, `/security-review`).
- **Read-only consent:** the guard says nothing, since it cannot keep one answer per call without writing `guard.log`.
- **Intents end only from an approved ask whose call ran.** A call nobody was asked about (`bypassPermissions`, or `guard.ask` off as shipped) leaves the intent until a release or 7 days (D9; review round 1).
- **"That rule is gone" ends a rule only when:**
  - the sentence is nothing but that;
  - it comes in the human turn after the guard asked about the rule in the same window;
  - the turn count is read from the ledgers. With `deliver.submit` `off` no turn is recorded, so the phrase never matches: it fails toward keeping the rule.
- **Wording (D14 vs A6 §2.3).** Surface clause by default. The "… by you, not by the agent" rewrite applies only where it is exactly right: a prohibition on the agent alone ("yourself") of a class's default object.
- **Labels.** `denied` is separate from `declined`: under `claude -p`, Claude Code 2.1.294 denies an ask and returns its reason as the error, so the reason reaches Claude there. A result that cannot be read stays unlabelled.
