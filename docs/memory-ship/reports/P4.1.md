# P4.1 — Situation cue + turn mode

**Outcome:** merged. A human turn is now cued by its situation, not its prompt alone (A7 §3), and every human mode but chatter is answered (A7 §2). "yes do it" after a proposal naming a file now gets that file's memory (A5 `continuation` green); "yes do it" after "Shall I merge the PR?" now gets the merge rule. CueBench ctx recall is 9/22 counted in context, 7/22 in the cue's own packet. Under R1's own definition (the cue's packet) the ≥ 0.40 gate is unmet; you accepted the in-context definition before the guards ran. Two other results are reported plainly below: the guard `false_rate` rose +1.13 pp pooled, which A5's paired rule does not count as a regression and you accepted; the full-scale counter-target (Target 3) missed by 1 negative, exactly as on `main`.

## What changed
- **A7 §2's turn modes** (`src/memory-turn.ts`).
  - New modes: `debug` (error-shaped text, or a word of failure: fail/broken/error and their word families), `how-to` ("how do I", "how to", "run the tests", the verb "set up") and `question` (a trailing `?`, or a WH-word first). The first match wins, after `nonhuman`, `ack` and `continuation`.
  - "I can see / confirm / tell / reproduce …" is a report, not a proposal.
  - `proposalSentences` gives the sentences that offer an action or ask a question.
  - `isAnswered`: every mode but `ack` and `nonhuman` retrieves. Before P4.1 only `imperative` did.
- **A7 §3's situation cue** (`src/memory-cue.ts`; `relevant`/`recall` in `src/index.ts`).
  - Four parts, each scored separately against a row's needles and summed with the mode's weights: default 0.55/0.15/0.15/0.15, `continuation` 0.15/0.15/0.20/0.50, `debug` 0.45/0.10/0.20/0.25.
    - `q_prompt`: the prompt.
    - `q_turn`: the previous typed prompt.
    - `q_path`: the basename and non-generic folders of the newest 8 paths of the window's recent tool calls in `ctx.log`. The wrap has no repo top, so it uses the request's path basenames.
    - `q_prev`: the agent's last message, without every token of the packets Eden gave the turn it answers (transcript `hook_additional_context` attachments since the previous typed prompt; the wrap's previous tail). Only its rare words (df ≤ 50) and identifiers are read.
  - A context part adds at most 2 matched words to a row (R2 §5.2's mass limit).
  - Until P4.3's τ, the context parts rank the rows the prompt admits and never admit a row alone.
  - A continuation admits only on STRONG evidence: an identifier its agent's last message shares with the row (the same token, or a bare filename and a path ending in it), or a class or slot of the proposing sentences.
  - On this situated path, the scorer also uses R1's plural stemming (with lazy per-stem postings) and D17's kind prior, cut to a thousandth so it never exceeds one matched word. The legacy callers keep the old scorer, and gave identical output to `main` in the reviewer's 600-query probe.
- **The episode gate** (`src/memory-gate.ts`): `q_path` is a MEDIUM part; a continuation's identifiers are STRONG. Identifiers match by `sharesIdentifier`: two paths match only whole, so `packages/cli/src/server.ts` is no evidence for `packages/wrap/src/server.ts`.
- **The hook** (`packages/cli/src/memory-hook.ts`):
  - it builds the cue for every answered human Submit, and falls back to the prompt alone if that throws;
  - one `ctx.log` read serves both the place and `q_path`;
  - `turn_mode` in the wide event now names `question`, `debug` and `how-to`.
- **The wrap** (`src/memory-wrap.ts`):
  - it answers turns with the same cue;
  - a restarted wrap's turn reads D12's split for its triggers (P2.2's follow-up);
  - a wrap-only session keeps and ends rules for all projects in a repo's store. `answerUserGlobal`, shared with the hook, closes P2.4's follow-up.
- **Follow-ups closed:** all 5 P4.1 rows:
  - P0.6: q_prev's rare words and own-delivery stripping;
  - P0.2: continuation STRONG injections, the "I can see" marker, `q_path` in the episode gate;
  - P2.2: "yes, ship it"-style replies reach the trigger;
  - P2.4: wrap-only D11;
  - P2.2: the wrap restart's D12 split.
- **Harness:**
  - the new arm `cuebench-ctx` (`arms/bench.ts`, `arms/cuebench.ts` `recallInContext`, `arms.json`, `groups.ts` facts, `reference.ts`, `registry.test.ts` 46 arms);
  - two `fixture:` commits: `continuation`'s setup turn, and `cuebench-ctx`'s separate stores;
  - `scripts/test-times.txt` facts rows.
- **Tests:**
  - `src/memory-cue.test.ts` and `src/memory-cue-review.test.ts` (new; the reviewer's round-1 probes);
  - additions to `memory-turn`, `memory-gate`, `memory-residual`, `memory-wrap`, `memory-hook-turns` and `arms/kit`.

## Decisions made
- **The ctx gate counts recall in context** (`recallInContext`). The harness asks a ctx cue's previous turn as a real turn, and on base and new alike that turn's own packet delivers 2 of the 22 gold rows (q178, q186). The ledger rightly withholds them at the cue (A4 §4). The cue's-packet number is reported beside it. This definition was chosen after seeing per-cue results, which the prereg discloses. You accepted it: "Accept in-context, report both".
- **The context parts never admit a row alone** (non-continuation turns). A7 §4 gives `q_turn`, `q_path` and `q_prev` MEDIUM evidence, and τ (P4.3) is not built. So the prompt still admits, as before, and the context ranks. A busy context therefore cannot add packets (A7 §3's "per-part mass limits").
- **`q_prompt` is not identifier-split** (A7 §3 says it is). Splitting "Node.js" into "node" admitted a mined node-version fact on R1's hard negative "who created the Node.js runtime?" in `restate-learn`'s silence replay, a check that had been passing. The context parts are split. Filed to P4.3.
- **R1's plural stemming and D17's capped kind prior, on the situated path only.**
  - They are pieces of P4.2's BM25F that the weighted sum needs in order to rank at all: with the +25/+40/+50 prior, ctx stayed at 5–6/22. You chose to keep stemming.
  - The kind prior is a thousandth of the legacy one, under the least a matched word adds (debug's `q_turn`, 0.18).
- **q_prev's selection runs at Submit, not in `stop-fast`** (A4 §5.7). The turn mode's proposal check reads the text, and the Submit has the store's df and the transcript's packets. `qprev.json` keeps the text.
- **A continuation's classes and slots are read from its proposing sentences only.** What the agent reports having done ("I merged the docs PR") is not what "yes" accepts. Its identifiers are read from the whole message.
- **The reply's own identifiers are no continuation evidence** ("yes but in vitest.workspace.ts"). This follows A7 §2's "STRONG evidence from `q_prev`"; it is kept as a test.
- **STRONG identifier matching:** the same token, or a bare filename and a path ending in it. Two paths match only whole (A7 §4).
- **The wrap's `q_path`** is the request's path basenames: it has no repo top to read folders against.
- **`cuebench-ctx` sits in the `facts` test group.** Every group's gate file exceeds a minute locally once the arm's ~33 s is added. `test-times.txt` gets the local times scaled by each file's local/CI ratio (Actions is off).
