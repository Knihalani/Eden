# P1.1 — Ledger core

**Outcome:** merged. The window ledger now has its D25 snapshot. A Stop rotates `delivery.log` and folds it into `delivery.json`, so a Submit reads a bounded ledger: 17,319 B after 300 soak turns, against 52,216 B on `main`. cids carry `<repo8>/`, overflow evicts above 256 entries, a changed value comes back as one `Updated:` item, and past 6k tokens in an epoch only `Updated:` items go out. The Submit's wide event logs the transcript's bytes beside `message.usage`'s context tokens, and `hook.log.d/` keeps 90 days, then daily aggregates. ## What changed
- **Snapshot and rotation (D25, A4 §4).** `stop-sleep` and SubagentStop fold each ledger file under `delivery.lock`. Each fold:
  1. renames the log to `delivery.log.<n>`;
  2. folds the snapshot with every rotated log past its `through`;
  3. writes `delivery.json` by rename (`delivery.shadow.json` for the shadow ledger);
  4. removes the rotated logs.

  Readers fold snapshot + rotated logs + live log. A line appended to a rotated log after the fold read it goes back to the live log, and a rotated log the snapshot already holds is never folded twice. The fold keeps each cid's latest delivery (a union keeping max(`off`) within an epoch), the epoch, `tokens_epoch`, and the human turns: their count plus the last 16 `prompt_id`s.
- **Overflow:** above 256 entries a fold evicts older epochs first, then the least recent episodes.
- **cid / ver:** `cid = <repo8>/<kind letter>:<key>`. Slot keys also keep their subject words, each hashed (`sw`). The ledger stays text-free (X11).
- **`Updated:` items (A4 §4 re-arm; D28's hard limit 6).** A candidate is an `Updated:` item when either:
  - its slot cid is live at another `ver`; or
  - its text retracts or switches away from a live slot's value, naming only subject words of that slot (D7).

  The replaced value is named from `validity.jsonl` or the switch's own text. Delivering the item also records the slot at its new value (`deliveredKeys`), so the change is given once, in this packet or a later one. `Updated:` items count toward neither the soft limit of 4 nor a kind's limit, up to 6 bullets. They render as "Updated: … (was V; you said, …)".
- **Budget:** past 6k tokens in the epoch only `Updated:` items pass. There is one `packet` record per packet, holding a quarter of its characters, as A5 counts tokens. A new `budget` drop stage is logged.
- **Wide events and retention (X11):** a human Submit's event now has `off`, `ctx_tokens` (the last `message.usage`: input + cache creation + cache read), `ids` and `tokens_epoch`. At `stop-sleep`, day files older than 90 days become `hook.log.d/daily/<day>.json`, holding counts and times only.
- **The wrap (P0.7's follow-up):**
  - `deliver.submit` governs it: `off` encodes and answers nothing; `shadow` answers without attaching, and its refractory rule reads attached and would-be packets; `on` attaches.
  - Each conversation is a window, `windows/wrap-<key>/`, with its ledger (folded past 32 KB) and an `ev: "wrap"` wide event. The breaker's reader skips these events.
  - Turn tails persist in `tails.jsonl` until they have gone an hour unused, so a restart puts every earlier packet back. Each write fails open on its own.
- **`eden memory dump`** lists a folded ledger as a `{"k": "snapshot", …}` summary, then the records after it.
- Key files:
  - `src/memory-ledger.ts`: fold, snapshot, overflow, novelty, `Updated:` items, budget.
  - `src/memory-window.ts`: `existingLedgers` sees snapshots and rotated logs; `appendRecords`.
  - `src/memory-hook-packet.ts`: `Updated:` shape and wording.
  - `src/memory-events.ts`: fields, `retainEvents`.
  - `src/memory-residual.ts`: `contextTokens`.
  - `src/memory-validity.ts`: `subjectWords`; a switch keeps its new value, `n`.
  - `src/memory-wrap.ts`: flag, window ledger, tails.
  - `packages/cli/src/memory-hook.ts`: wiring.
  - `packages/cli/src/memory-dump.ts`.
  - `benchmarks/wrap-cache/prefix.ts`: the `inject-restart` path.

## Decisions made
- **`hturn` in the snapshot (A4 §4: "`hturn` is not stored in the snapshot").** The snapshot keeps a fold of `turn` records: the count of distinct `prompt_id`s plus the last 16. It is not a counter a Submit increments. A repeated Submit's id is within the last 16, or still in the log, so it counts once. That is the race A4 guards against, and it keeps the read bounded (the P0.6 follow-up). A4 §4 records this.
- **The ledger stays text-free (X11; P0.2's test that `delivery.log` holds no value).** "(was …)" takes the value from `validity.jsonl`'s retraction records (P0.3's supersession, D7's switch), or from the switch's own text. Slot subjects are kept as per-word hashes. I changed the first red commit's design (a `val` on keys) in a second, disclosed red commit (746fbe154).
- **`Updated:` detection on the legacy store.** Until P3.3's keyed slots, "`ver` changed" also covers a row whose D7 switch or retraction names only the live slot's subject words. Delivering it records the slot at the switch's new value, which validity's one switch parser captures (`n`). An item comes on the cue that retrieves the new value. Non-human submits and SessionStart get none: that needs a cid → current-value lookup (P2.5, P3.3).
- **The budget counts every packet** in the epoch, SessionStart's included. Only `Updated:` items pass it; there are no guard deliveries yet.
- **Overflow runs at the fold only.** A reader's in-memory fold may exceed 256 entries between Stops. The spec's overflow is a storage bound.
- **The wrap:**
  - `deliver.submit` governs it (decided as the P0.7 follow-up asked, before stage 2).
  - Its ledger is for measures: what the request carries stays the truth for its refractory rule and budget.
  - The flag files are read with `process.cwd()`, the directory the wrap runs in, which is the repo whose store it uses (`processMemory`).
  - The wrap's exceptions stay out of the breaker (filed to S2).
- **Child-window distance** (A4 §4: measured on the child's own transcript) waits for a child delivery point (P2.5). No child window delivers today.
- **The dump's ledger contract** (an A5 entry point) lists a folded ledger as a snapshot summary. `spawn-writers` is revised in a `fixture:` commit (CLAUDE.md step 4).
