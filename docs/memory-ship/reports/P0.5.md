# P0.5 — Repo identity (git-common-dir), window keys, migration

**Outcome:** merged. Memory is one store per repo (D1): a repo's sessions, linked worktrees, subagents and wrap share it, other repos never do, and `eden memory migrate` moves the per-session stores written before as sanitized legacy episodes.
**PR:** PENDING · **Merge commit:** PENDING · **Date:** 2026-10-09

## What changed
- **One store per repo (D1).** The hook, the wrap (`processMemory`) and `eden memory import` write to `<root>/repos/<key>/`. The key is 16 hex characters of `sha256(realpath(git common dir))`. It is read from the files git reads (a `.git` directory with a `HEAD`; a `.git` file's `gitdir:`, then its `commondir`), with no git process. Tests check it against `git rev-parse --path-format=absolute --git-common-dir`.
  - Linked worktrees, nested or outside the checkout, share their main checkout's key; a submodule has its own.
  - Outside git, the key is the folder the session started in. SessionStart records that folder in the window's `ctx.log`, and every later event of the session uses it, its subagents' included.
  - A session no longer gets its own store directory. It still labels its rows (`ep`), and its gist states only those rows.
- **Window keys (D2).** A subagent's events run in the window `session_id--agent_id`, and its rows go to the repo store.
- **Format (EXECUTION §9).** A per-repo store gets `format.json` (`{"major":2}`) when it is opened. A store whose major is unknown or unparseable is neither read nor written, by the hook, the wrap's `AgentMemory` (checked at every use), sleep or the wrap's tool-trace observer.
- **`eden memory migrate`** (`--dry-run` by default, `--apply`, `--rollback`, `--contract --yes`).
  - **Mapping:** R-7's snapshot first, then the transcript's first `cwd`.
  - **Rows:** each becomes an episode tagged `src:legacy`, with the id `legacy:<hash>`. It passes `scrubMemoryText` and loses its instructions; superseded rows, corrupt lines and rows left empty are not migrated. Where one repo's legacy rows disagree on a subject, the older value is logged `stale_for`.
  - **Apply:** backup, stage, verify, swap. The tar backup is 0600; the old tree stays read-only as `memory.legacy-v1/`. A hook writes nothing between the two renames, and the next `--apply` finishes an interrupted swap.
  - **Rollback:** restores the old tree, keeping what was written since, less the migration's rows and records.
  - **Contract:** after 30 days and `--yes`.
- `eden memory dump` lists repo stores; `eden doctor --memory`'s `repo key` line names the key and store for the current folder, and how many per-session stores still wait for `migrate`.
- **The `cross-repo` arm** (P0.0c's follow-up): repo A says postgres, repo B sqlite; each repo's next session gets its own value and never the other's.
- **Key files:**
  - `src/memory-repo.ts`: identity, store paths, the format rule, the migration's paths, `storeFor`.
  - `packages/cli/src/memory-migrate.ts`: the migration.
  - `packages/cli/src/memory-hook.ts`: the per-repo store, D2 windows, the swap and format guards.
  - `src/index.ts`: `perRepo`, the store's seal, the wrap's store.
  - `src/sleep.ts`: a gist states its own session's rows.
  - `packages/cli/src/memory-import.ts`, `memory-dump.ts`, `doctor-memory.ts`, `packages/wrap/src/tool-observe.ts`.
- **Tests:**
  - test seeding moved to the repo store, with every behavioural assertion kept;
  - tests that named the old layout now assert D1/D2's;
  - two quarantined tests pass now and run as plain tests (#63 `memory-ship`, #58 `memory-project`);
  - the nine #64 `test.failing` tests in `src/memory-subagent.test.ts` are deleted, as P0.1 decided, with the user's go-ahead.

## Decisions made
- **No `dirmap.json`** (D1 caches `dir → (repo, top)` because the git call costs 20–40 ms). The key is read from git's own files with a few `stat` calls (Submit p99 unchanged within the A/A noise), so there is no call to cache and no cache to go stale (DECISIONS D1 note).
- **Legacy rows are gated episodes.** They are `src:legacy` (A6 §2.1, §4), so A7 §4's episode rule applies: one STRONG match, or MEDIUM from two cue parts.
  - The `migrate` arm's `mapped` cues were one part each, so a spec-exact plugin could never pass them. The `fixture:` commit d331f95c1 puts an agent message about each subject before its cue, and adds a store check through `eden memory dump`.
  - The previous typed prompt could not serve as the second part (see the `typedPrompt` follow-up).
- **Session gists are not migrated.** Only SessionStart reads one, and the rows it summarises are migrated. They stay in the legacy tree with sleep's other derived files (EXECUTION §9 note).
- **Mapping order** (A6 §4 vs EXECUTION §9): R-7's snapshot first, then the transcript's first `cwd`. Both sources are read; A6 §4 now says so.
- **"50-cue old-vs-new read comparison"** is read as a row-level read-back through the store's reader: the first 50 rows, same text, `src:legacy`, no pin, no secret. A cue-level comparison cannot match by design, since legacy rows are episodes the gate holds back.
- **Conflicting legacy values** within one repo log the older ones `stale_for` from the newest one's time. When the values cannot be ordered, all of them are logged (G2 before G1).
- **A session's gist states its own rows (`ep`)**, as it did when each session had a store. Without this, every session's gist restated every repo fact (seen in the development run).
- **The wrap and `eden memory import` write per repo** (D1 covers all long-term memory): the wrap by the folder it runs in, import by each record's `cwd`. P0.7 still owns the wrap's delivery semantics.
- **Hook writes during a migration.** A hook writing between the staging copy and the swap writes into the tree that becomes legacy. Rows a transcript holds come back at that session's next event; a ledger record does not. Accepted and documented (EXECUTION §9 note).
- **The locked 2k bench's seeding** (`fixture:` 8ba35aec4). It seeded the root store and then checked the wrap and the hook, which now read the repo store; it now seeds that store. No check changed. n 2000 and 252,822 bytes, as on `main`.
