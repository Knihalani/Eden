# P2.2 — Compiled triggers

**Outcome:** merged. An action word in what the user types now fires its class, and the class delivers up to 2 of the rules keyed on it: "looks done, can you land it?" gets "Don't merge PRs yourself" with no word in common. Keyed rules no longer arrive by word overlap (D18). On R1's test policy cues, recall@4 is 17/32 (`main` 8/32), and the trigger's rules reach 0/80 negatives. The gate arm `policy-trigger` stays red on `fir` and `policy-on-positives`, which count the lexical path; the user accepted that until P4.3.

## What changed
- **One action-class lexicon, shipped as data** (`src/memory-classes.json`, read by `src/memory-classes.ts`):
  - A7 §5's classes, with D18's `stash` and D9 fix 4's `protected-path`, in R8's order of specificity.
  - Every reader takes it from there:
    - D9's extraction (`memory-policy.ts`, which no longer holds `CLASS_WORDS`/`DEFAULT_OBJECT`);
    - revocation verbs and default objects (`memory-validity.ts`, which no longer holds `ACTION_VERBS`/`DEFAULT_OBJECTS`);
    - compaction value tokens (`memory-value-tokens.ts`);
    - the cue.
  - Word edits against `main`'s regexes:
    - `dependency` allows determiners and up to 3 other words before "package/library", but not a preposition ("Ask before adding a new dependency" is now a rule; "add tests to the package" and "add a section about packages" are not);
    - `destructive-db` also matches a db/table/schema before the verb (A7: "drop/truncate/reset/wipe + db/table/schema"), with each gap bounded to 60 characters;
    - the phrasal forms "close it out", "wrap it up", "roll it out" count;
    - a cue's `main`/`master` is a branch only in a branch context ("push to main", "the main branch"), so "refactor the main function" fires nothing.
- **Prompt-side class firing** (`src/memory-triggers.ts`, A7 §1 layer 3, A4 §5.1 step 4b):
  - A class fires on its word in the user's own words, as D12 splits them: marked pastes, fences, quotes and spans copied from a recent tool result are left out.
  - A clause that asks for information fires a class only where its word is the verb of the user or the agent:
    - such clauses are a WH-question, "remind/tell/show me …", "need help with", or "(can you) explain";
    - so "where do prod credentials live?" fires nothing, while "what should I run before I push?" fires `push-upstream`.
  - Each fired class gives at most 2 rows keyed on it, the ones the user stated first, then the newest. Every class's first row comes before any class's second, and each row once.
  - The classes are computed once per Submit (a one-entry cache).
- **D18 in the store** (`src/index.ts`):
  - A live rule row with D9 keys is kept out of the lexical postings (`ruleRows`), so a policy or an intent comes only by its class's trigger.
  - `recall` puts the triggered rules first (A7 §4: a trigger hit is STRONG and admits alone), then the lexical notes.
  - The rest of the Submit path (validity, gate, residual, shadow set, ledger, budget, shape) is unchanged, so an expired intent, an overturned rule or a rule already delivered in the window is still dropped.
- **`eden memory remember "<text>" | --jsonl -`** (`packages/cli/src/memory-remember.ts`, D11's command):
  - Each statement becomes one row in the user's words (`src:user`), in its `cwd`'s repo store: a rule row with D9 keys when it states a rule, else of the `kind` given.
  - It prints `{"remembered": N}`, or 0 when memory is off.
  - It is the entry point the `policy-trigger`, `cuebench-code`, `alias-batch` and scale arms plant through. Its contract is confirmed in `cuebench.ts`'s header (`fixture:` 4bcedccfa).
- **Wide events:** a human Submit's event names the classes its own words fired (`classes`), for stage-1 shadow reads.
- **Tests:**
  - new: `src/memory-classes.test.ts`, `src/memory-triggers.test.ts`, `src/memory-triggers-store.test.ts`, `packages/cli/src/memory-remember.test.ts`, `packages/cli/src/memory-hook-triggers.test.ts`;
  - changed: three assertions in `src/memory-packet.test.ts` moved from `notesFor` (the lexical path) to `recall`, because keyed rules are no longer lexical.

## Decisions made
- **Pre-registered red, accepted by the user.**
  - `policy-trigger`'s `fir` (any packet on a negative) and `policy-on-positives` (any fixture-policy bullet) count the lexical path, whose gate is P4.3's (BM25F, τ_repo). On `main` plus `remember`, the lexical path alone put a packet on 52/80 test negatives.
  - The prereg read A5's "FIR ≤ 5 %" and "≤ 10 %" as R1 Addendum A measured them, the trigger's own (Target 2), and predicted the two checks red.
  - Asked in this session (2026-10-11) whether P2.2 may merge with them red, owned by P4.3, the user answered "Accept until P4.3 (Recommended)". `arms.json` (caa2e7a95) and PROGRESS record it.
- **D18 read strictly** (DECISIONS D18: "Policies are delivered by compiled triggers, not similarity"; A4 §2's policy row).
  - Every row with D9 keys leaves the lexical path, including one D9 keys on an incidental class word ("Never console.log in production" is `deploy`).
  - This conflicts with A4 §5.1 step 6 and A7 §4, which admit a policy on an identifier-shaped STRONG match. The reviewer's three cases got their rule on `main` and not since: "add console.log calls to debug the auth flow", "fix the flaky test on release-2.x", "add a db:check step for the users table migration".
  - On the fixture, strict D18 raised recall: `test` all-positive recall@4 116 → 129 of 253. The guards' `need_miss_rate` is unchanged (paired 0/0).
  - Filed to P5.4: D9 precision and identifier-shaped admission of keyed rows.
- **A clause that asks for information fires only on the user's or the agent's verb** (A7 §1: "an action word in the cue fires it"; R1 Addendum A: topical words overfire; the P2.1 row asked for the lexicon's precision).
  - Two readings were measured on `dev`: no exception (V1) and the I/we/you exception (V2, shipped). V2 has the same recall (12/28 policy, 127/263 all positives) and +1 negative and +2 positives with a keyed bullet.
  - V2 keeps "What should I run before I push?", which `main` answered lexically and V1 would have lost (an existing hook test).
- **A reply to a proposal gets no trigger.**
  - The hook and the wrap recall only on `imperative` turns, and A7 §2 lets a continuation inject only on STRONG `q_prev` evidence. Turn modes are P4.1's.
  - So "yes, ship it" after "Shall I merge the PR?" gets no rule from the trigger; the P2.3 guard is the backstop.
  - The arms and the end-to-end ask fresh sessions or typed requests: they do not cover replies to proposals. Filed to P4.1.
- **A trigger fires on a lexical no-op cue** ("ship it" is on `isNoopCue`'s list): a trigger hit is STRONG and admits alone (A7 §4). The lexical path still answers nothing to it.
- **Ranking within a class:**
  - "user-stated" means a row whose `src` is the user;
  - "most recently stated" is the store's order (`compareRecency`: `seq`, then time);
  - "narrowest scope" ranks nothing until rows carry a scope (P3.1).
- **The lexicon's word edits** (dependency modifiers, destructive-db in either order, phrasal "it/this/that" forms) follow A7 §5's table. Disclosed: the dependency and phrasal edits were made after the in-process prototype had shown `test` cues q440 ("add a nice date picker package") and q418 ("close this out"); A7's "add dep/package/library" names the generalization. `extraction` is unchanged (0/217, 16/18).
- **`remember` rows:**
  - they ignore `scope`, since rows have none until P3.1;
  - their kind follows D9 first (a stated rule is a rule row whatever `kind` says), as the hook's `observe` does;
  - `--global` waits for P2.4's user-global store.
