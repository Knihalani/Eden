# P2.1 — Policy & intent extraction

**Outcome:** merged. A rule the user types is now keyed `(class, polarity, object)` at write time (D9 with R8's four fixes). A qualified rule is an intent that expires after 7 days and never pins; `never`/`always` pins a policy. A rule stated outright of the opposite polarity, or a revocation, moves the older rule to history and takes it out of every packet, gists included. `eden memory extract` answers the `extraction` arm: 0/217 false durables (R8's regex: 3/217) and batch-B rule recall 16/18 (R8: 13/18).
**PR:** https://github.com/Knihalani/Eden/pull/133 · **Merge commit:** printed in the slice's final message (this report is part of the merged PR, and no commit follows the merge) · **Date:** 2026-10-11

## What changed
- **D9 extraction** (`src/memory-policy.ts`), over the user's own words only (A4 §3.0):
  - **Triggers and classes.** An imperative trigger (`don't`, `never`, `always`, `without asking`, `ask before`, `only … after`) and fix 2's added triggers (`hold off`, `no <verb>ing`, `leave … unmerged / as a draft / alone`, `wait before/for`, `without checking with me`) must be followed by a word from A7 §5's lexicon, D18's `stash` or fix 4's `protected-path` class (`.env` and its secret variants, `infra/`, lockfiles). The class is the one whose word comes first; a tie goes by R8's order.
  - **Exclusions** (fix 2): `don't forget to`, `never mind`, `don't worry/bother/hesitate`, questions (a ", ok?" tag aside), and descriptive clauses (a subject other than "you").
  - **Intents** (fix 1): a qualifier binds to its own clause. `before`/`after` make an intent only before a time or an event; a precondition keeps a standing policy.
  - **Objects** (fix 3): synonyms are named one way. A class's default object alone keys as `*`; named with other words it is dropped ("the main branch" is `main`). Command flags are no object.
- **Rule rows** (`src/index.ts`):
  - A typed rule row (kind `constraint`) carries `rules: [{k, q?, c?, v?}]`:
    - `q`: the qualifier that makes it an intent;
    - `c`: the rule is narrowed;
    - `v`: history-rewrite's action (squash ≠ force-push).
  - An all-intent row has `valid_until` = t + 7 days and never pins. An explicit `never`/`always` pins a policy, and an episode is never a pin.
  - A rule row of an earlier prompt goes to history when every rule it states is overturned (L8).
  - A rule typed again after it was overturned is learned again (`restatementKey`).
- **Overturning, at every delivery point** (`src/memory-validity.ts`):
  - Each policy stated outright, and each revocation ("you can open the PR now", keyed by D9's classes), appends an `oppose` record to `validity.jsonl`.
  - Older text stating the overturned rule loses that sentence at Submit, SessionStart and in session gists. Each key's newest record is read, and readings are cached per text.
  - An intent's clause leaves every delivered text 7 days after it was said (`withoutExpiredIntents`), so a mixed row ("Never force-push, and don't open the PR yet") keeps its policy. `forget` does not read through this.
- **Ledger and compaction** (`src/memory-ledger.ts`, `src/memory-value-tokens.ts`):
  - A keyed rule row's cid and ver are a hash of its rules, so two rows saying one rule share a cid.
  - Its compaction value tokens come from its keys: the class token, plus the object or the class's default object. A summary names the default object by any synonym ("pull requests").
- **Session gist** (`src/sleep.ts`) and **SessionStart briefing** (`packages/cli/src/memory-hook.ts`): only live rows, no intent rows, and expired intent clauses dropped.
- **`eden memory extract --jsonl -`** (`packages/cli/src/memory-extract.ts`): the `extraction` arm's entry point; pasted spans are stripped first (D12). No slot records (P3.3).
- **Tests:**
  - `src/memory-policy.test.ts`, `src/memory-policy-store.test.ts`;
  - `packages/cli/src/memory-hook-policy.test.ts`, `memory-extract.test.ts`;
  - `memory-hook-policy-review.test.ts`: the reviewer's probes from rounds 1–3.

## Decisions made
- **Recurrence → pin waits for P2.4.** ROADMAP's P2.1 row lists recurrence in ≥ 2 sessions → pin, but A4 §6–§7 place promotion at sleep with `policy_recur`, and the `policy-recur` arm is P2.4's. P2.1 stores each rule's key and session (`ep`), so P2.4's detection is a key comparison.
- **Left to P2.3:** an intent's expiry when its action completes (`gh pr create` ran), and the per-class declarative rewrite ("PRs are merged by you, not by the agent"). Both are the guard's wording and timing, which `policy-guard` and `intent-expiry` check.
- **Keys live on the legacy row** (`rules` on a `constraint` row), not in A4 §1's `policies.jsonl`/`intents.jsonl`, so that purge and forget keep covering one store. A compact guard index is filed to P2.3.
- **The class is the one whose word comes first after the trigger**, with ties broken by R8's order. R8's pure order keys "don't touch main until the release is out" as deploy (A236).
- **D9's "same key" is read as the same rule.** For history-rewrite, whose words name distinct actions, the rule also keeps its action (`v`), so "never force-push" neither overturns "always squash when merging" nor shares its cid. Other classes' words stay synonyms of one rule (delete/remove, deploy/release, add/install).
- **The overturning asymmetry (A4 §3.1, L8):**
  - Only a policy stated outright (its own verb, nothing narrowing it) overturns.
  - It overturns a prohibition only one stated outright. So "never squash" overturns "always squash when merging", while "you can merge now" leaves "never merge PRs without a review" (P0.2's validity test). "Don't install packages without asking" + "You can install packages now" leaves the prohibition live.
  - A narrowed positive typed after an outright negative leaves both live, newest first.
  - No row is overturned by its own prompt ("Don't merge PRs. Always merge PRs from dependabot.").
- **Revocations are logged twice:** as `oppose` records keyed by D9's classes (so "you can open the PR now" reaches review and protected-path), beside P0.2's `revoke` record, which text-level `forbids` still reads.
- **An intent supersedes no policy**: "don't squash yet" leaves "always squash".
- **Intent expiry is a delivery step** (`withoutExpiredIntents`), because a mixed row has no `valid_until` of its own. A text without a wall-clock time counts as older than 7 days. `forget` reads the stored text, not the delivered one.
- **An episode is never a pin** (D6: pins are rules). Before, a prompt's whole-text episode was pinned by the legacy "always" reading and briefed rules its rule row no longer held.
- **D9's exclusions apply to the legacy rule words too** ("Don't forget to delete the debug logs" is no rule). A rule on no action class ("always explain plainly") keeps the legacy reading, unkeyed.
- **Object labels depart from R8's gold in two places, invisible to the arm:**
  - "shared branches" keys as `shared` (gold `branch|*`, A212, B3): the default object is dropped only when named with other words, which keeps "the main branch" (`main`) apart from "the feature branch" (`feature`). So "you can force-push now" does not revoke "never force-push on shared branches".
  - "before you merge, wait for my ok" (B16), "wait before you deploy" (A241) and "don't release before QA signs off" (A234) are gold intents with `q=before`, but are read as policies under fix 1 (a precondition clause).
  - The gold's A207 class `other` predates fix 4's `protected-path`.
- **Batch B was not unseen** (prereg): it was printed once while orienting. No rule was added for a batch-B phrasing that neither D9 nor A7 §5 names. B4 ("terraform apply") and B5 ("no new npm packages") stay misses.
