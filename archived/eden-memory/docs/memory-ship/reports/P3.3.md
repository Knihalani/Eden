# P3.3 — Slot table + live/history + retraction

**Outcome:** merged. A statement of one of D7's 15 slots is now a keyed row. A newer value at the same scope, `use A not B` and a retraction send the old value to history by key, and D31's `stale_for` keeps the old value out of episodes and gists at that scope and below. The ledger, D26's residual and the two-scope bullet read slots by key, and `eden memory extract` answers slot records. Two pre-registered results missed and are reported as such: held-out E3 batch-B slot recall was **8/16** (target ≥ 12/16; 15/16 after one disclosed look at its misses), and the `stale_rate` guard is **9/609 vs 0/537** (accepted by the user until P3.4).

## What changed
- **D7's slot table** (`src/memory-slots.ts`):
  - **The table.** The 15 slots, each with its aliases, its value class (canonical values and their other names: `postgres` for "PostgreSQL", `next.js`, `fly.io`, `k8s`, …, or a version number), its default scope, and D7's status lexicon.
  - **The reader.** What the user typed is read clause by clause, and the first of D7's forms that states something wins:
    - D7's base and additional forms, and A4 §3.1's retractions;
    - `S is not V`;
    - the same forms in other words (`V is our S`, `our tests use V`, `we replaced B with A`, `we use pnpm and vitest`, `it's V` after a slot's clause);
    - after the disclosed look, R8's `everything is V now`, `use A for X, not B` where X is the slot's job, a switch of the whole app or one side of it whose values share a class, and time phrases.
  - **Read narrowly**, because a false slot supersedes a true one. These state nothing:
    - a question, a conditional or a reminder;
    - an instruction other than D7's own `use` forms ("install the dependencies with npm");
    - a value followed by a noun ("the jest config");
    - a qualified subject ("the staging database", "end-to-end tests", "the docs site");
    - a value said for one environment ("sqlite for local dev");
    - a placeholder, a day or a colour;
    - "my <alias>", except for the GitHub account;
    - an everyday-word value ("main", "next", "render") whose slot the sentence does not name.
  - A slot takes one value per sentence. A word-set test (`mayStateSlot`) runs before the reader, so each hook process does not re-read every stored row.
- **Keyed slot rows** (`src/index.ts`):
  - **Keys.** A typed row stating slots carries `slots: [{k, v?, x?}]`.
  - **Supersession.** The same `(scope, slot)` with another value, `use A not B` and a retraction send an older row to history (`invalid_at`) once every value it sets is gone. A row stating two slots keeps the one still true. A same-scope supersession marks the new row `corrected: 1`.
  - **Equal write.** An equal visible value writes no row; the visible row counts it (`reps`).
  - **Default scopes.** A root slot is written at `""` unless the text names a scope or the working scope has its own row. A statement of a root and a working slot that go to two scopes is two rows of one text.
  - **The legacy copula reader** (`objectAsserted`) keys a slot statement by its slot's label, so the semantic store, sleep's assembly and the session gist key by slot, not by `(stack, uses)` (R3 E8). Rows whose place is known no longer write into the unscoped semantic store.
  - **Dedupe.** `observe` dedupes identical text per scope, and a pure retraction is a slot fact, not a rule row briefed at SessionStart.
- **`stale_for` by key** (`src/memory-validity.ts`, `recordSlotChanges`):
  - **The record.** Each value a statement ends is logged with its slot, its scope (`in`) and the descendants that hold their own value (`except`).
  - **What carries it.** A clause carries the value by one of its names, beside the slot's alias when the name is an everyday word or a version.
  - **What keeps it.** A clause giving another subject the value ("the cache is postgres"), a clause stating the change, and a clause opening with another folder ("In apps/web the …") keep it.
  - **Read set.** A row visible at the reader's folder is read against the records held there (Submit and SubagentStart pass the read set).
  - The prompt's legacy reading no longer logs a D7 value at every scope.
- **Ledger** (`src/memory-ledger.ts`):
  - Slot cids are `s:<scope>|<slot>` (the root's `s:<slot>`), with the canonical value's hash as `ver`, and a row stating two slots records both.
  - `Updated:` is a key comparison. A typed episode's switch is read by the slot table. A retraction renews the slot at the empty value.
  - The `sw` switch reading is retired.
- **Residual** (`src/memory-residual.ts`): D26's slot rule reads aliases and value names.
- **Place** (`src/memory-place.ts`): the root-slot heuristic (`ROOT_SUBJECT`, `ROOT_STATEMENT`) is replaced by the table, and the two-scope bullet reads one-clause rows by key.
- **Sleep** (`src/sleep.ts`): the session gist states slot values by scope ("In packages/cli the database is sqlite"), each read at its own scope, and fast-memorize skips placed rows.
- **Encode** (`src/assemble.ts`, `src/index.ts`): a heading's numbered list ends each item at its line break, and indented lines continue the item.
- **`eden memory extract`** (`packages/cli/src/memory-extract.ts`) answers slot records.
- **Tests:**
  - `src/memory-slots.test.ts`: the phrasing table, 124 tests, R3 E8's rows included;
  - `src/memory-slot-store.test.ts`, `src/memory-slot-delivery.test.ts`, `packages/cli/src/memory-hook-slots.test.ts`;
  - `src/memory-slot-review.test.ts` and table rows: every review round's probes;
  - `packages/cli/src/memory-extract.test.ts`, extended.
  - Legacy tests that pinned the `(stack, uses)` or `(auth, is)` subjects, or the prompt-time logging of D7 values, moved to the keyed path; each change is commented.

## Decisions made
- **Keys live on the row** (`slots`), as P2.1's `rules` do, so purge and forget keep covering one store. A4 §1's `live.jsonl`/`history.jsonl` are not split out; a superseded row is history by its `invalid_at`. `validity.jsonl` stays as the clause log for text with no key (episodes, gists, other sessions' rows).
- **The legacy copula reader keys a slot statement by its slot's label.** Without this, sleep's assembly and the semantic store would supersede "we use pnpm" with "we use postgres for the db" (both `(stack, uses)`, R3 E8). Legacy tests that pinned the old subject keys now use the slot labels.
- **D7's reading is narrower than its text where the text would let a false slot supersede a true one.** The narrowings cover:
  - retraction verbs, kept to D7's and A4 §3.1's;
  - a class value ending its clause;
  - qualified subjects as other instances;
  - environment values;
  - D7's deploy form with "we" only;
  - placeholders;
  - "my".
  - Cost, after rounds 4–5: "The database is postgres in production" and "we switched the web app from next to remix" read nothing (the whole-app subjects are single words), and "The web app deploys on Vercel" reads nothing. The batch numbers did not change (A 47/48; B 15/16 post-look).
- **A statement of a root and a working slot is two rows of one text** (D7: a root slot at `""`; A4 §3.2). The packet never shows one text twice. The root row's text still shows the working value at a sibling's cue, as `main`'s one row at `""` did (filed to P3.5).
- **A retraction typed at the root does not end a descendant's own value.** Supersession is per scope (A4 §3.2), and D31 spares overriding descendants.
- **Rules stay at `""` unless they name a folder.** This answers P3.1's and P3.2's follow-up (A4 §2: policies are mostly `""`), and is recorded in DECISIONS D3.
- **Root slot cids changed** from a subject hash to the slot's id (`s:pkg.manager`), so a window open across the upgrade may be given a root slot once more.
- **The equal write** (A4 §3.2) returns the visible row in place of a new one, and counts `reps`. D30's `restate`/`confirm` events are P5.1's.
- **One value per slot per sentence.** A sentence giving two folders' values keeps the first, because a row has one scope.
- **Batch B's remaining miss** ("our db is sqlite for local dev and postgres in prod", gold postgres) is R8's own judgement call. It reads no value: a value said for one environment is that environment's.
